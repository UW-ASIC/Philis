Performance-driven Wire Sizing for Analog Integrated Circuits

Yaguang Li, Yishuang Lin, Meghna Madhusudan, Arvind Sharma, Sachin S. Sapatnekar, Ramesh Harjani and Jiang Hu · supplied manuscript (PDF metadata dated 2022)

Graph-based prediction and discrete wire sizing with detailed evaluation; manuscript-specific evidence.

Open supplied PDF · 27 physical pages · File identity and coverage

The supplied file todaes22yl.pdf is “Performance-driven Wire Sizing for Analog Integrated Circuits,” by Li and coauthors. Its central contribution is to make wire width a circuit-performance design variable after placement and global routing, rather than choosing it only from minimum design rules or current limits.

Where the teaching treatment lives

Read wire sizing for the RC tradeoff and implementation procedure, performance feedback for surrogate validation, and electromigration for reliability limits that width optimization must respect. This source is a 27-page supplied manuscript; the file does not justify inventing a final journal DOI, volume, or issue.

Why width is a performance variable

Changing width changes resistance and capacitance differently. Series source resistance can reduce effective transconductance, while added capacitance at a sensitive node can reduce bandwidth or phase margin. Thus “wider everywhere” and “minimum total C” are both incomplete policies. The paper demonstrates this using OTAs, comparators, VCOs, and switched-capacitor filters in advanced processes. Motivation and examples, PDF pp. 2–4

Table 7 provides a useful counterexample: uniformly increasing wire width from 1× to 3× improves the example current-mirror OTA's UGF from 451.0 to 511.4 MHz while its gain falls from 33.1 to 31.1 dB and its aggregate FOM falls from 0.92 to 0.90. The lesson is competing sensitivities, not a SKY130 prediction. Table 7, PDF p. 19

Decision variables and objective

The paper assigns discrete width choices per net after global routing and before detailed routing. Symmetric nets receive the same width. Its FOM combines bounded, normalized performance scores: for a positive larger-is-better metric z with target φ, use min(z/φ,1); for a positive smaller-is-better metric, use min(φ/z,1). Weighted averaging then creates a maximization objective. §2–3, PDF pp. 5–6

Limit. These ratios assume meaningful positive quantities and do not handle zero, sign changes, or logarithmic metrics generically. A high aggregate FOM can still hide an unmet specification. Even a printed FOM of 1.00 should not be treated as a proof: rounding, normalization, and metric selection matter. Philis should retain the individual values and explicit pass/fail margins.

What the WAGN model actually sees

The graph represents device pins, I/O pins, and routing Steiner points. Node features include device type, functional role, dimensions, and location. Edge features include horizontal/vertical span, via count, width choices, pin dimensions, and terminal types. This is substantially richer than a netlist-only or wirelength-only feature set. §4.2, PDF p. 8

The Wire Attention Graph Network combines node and edge information through attention and pooling. Its distinguishing attention kernels capture feature distance, similarity, and additional learned relations. The manuscript denotes the final soft classification output P(FOM<T) for one user-specified threshold. It estimates class membership; the reported classification experiments do not establish probability calibration, a full performance distribution or manufacturing yield. It is not a prediction of gain in dB or delay in seconds. The classifier's useful ranking range can saturate far from its threshold. §4.3–4.5, PDF pp. 9–11

Adoption reason. The feature design teaches Philis what information a physically relevant fast evaluator may need. It does not establish that a GNN should be the first implementation. Extracted terminal RC and finite-difference sensitivities provide an interpretable baseline against which a learned model must earn its complexity.

The optimization procedure, with the safeguards preserved

  1. Train the classifier on extracted, simulated layouts, including width changes. Reason: schematic-only labels omit the mechanism being optimized.
  2. Relax the width variables temporarily and search cheaply using the fixed learned model. One method uses Bayesian optimization; another differentiates through the model while treating widths as the optimized parameters.
  3. Use multiple starts to reduce sensitivity to local optima. This improves exploration but does not certify a global optimum.
  4. Discretize candidate widths. The paper rounds near-integer values and partly enumerates floor/ceiling combinations for ambiguous values. Enumeration can grow exponentially; a production implementation needs an explicit limit.
  5. Realize the candidate in detailed routing, preserving legal dimensions and symmetric width assignments. The physical result, including fallbacks, is the candidate that must be evaluated.
  6. Simulate a shortlist (ten by default in the experiments), then choose using simulated performance. This last step prevents the surrogate's favorite false positive from becoming the final answer.

§5 and Algorithm 1, PDF pp. 12–14

The paper reports widths realized as multiple parallel routes on its gridded technology. Those are not electrically identical to replacing them with one continuous wide rectangle: access vias, current sharing, lengths, coupling, and neighboring clearances differ. Keep the realized topology in Philis's route model. Width realization, PDF pp. 15–16

Evidence, baselines, and limits

The experiments use 12 circuit cases, ASAP7 and GF12, 2,000 generated layouts per schematic, and held-out test samples. They compare uniform widths, conventional simulation-guided BO, WAGN-guided BO, TensorFlow-based optimization, and transfer variants. Transfer is examined between topologies within the same circuit family; the authors explicitly identify transfer across families, regression, large circuits, and process variation as unresolved limitations. §6 setup, PDF pp. 14–17 Limitations, PDF p. 23

The headline 11% improvement or 8.7× speedup is relative to particular BO budgets and hardware. The timings include a distinction between training cost included and excluded; parallel label generation and sequential BO also use resources differently. Count data generation, training, detailed-route retries, extraction, and simulation in a Philis comparison. Runtime discussion and Table 6, PDF pp. 18–19

Reported 99% routability and limited die-area increase describe the tested layouts. Congested analog blocks, guard-ring obstacles, wide spacing rules, or pin access can make width changes much harder. A fallback to the original width must trigger reevaluation; otherwise the score describes geometry that was never built.

Concrete Philis integration

DetailedCfg currently has base widths, signal/supply fattening, width-dependent spacing, and current-based trunk widening. Add legal per-net or per-segment width options as candidates, with corresponding contact/via strategies. Keep EM minima as feasibility conditions and circuit performance as the separate optimization target. Share width choices across electrically matched routes where justified.

The current total-C winner selection can favor thinner wires even where source resistance dominates. First establish an RC-aware circuit evaluator; then run a small discrete search on critical nets using real extraction/simulation. Only after this baseline exists should model-guided search be compared at equal total cost. Log which net or segment changed, predicted metric effect, realized geometry, measured effect, and any model error.

Reading coverage and limits

Read PDF pp. 1–27: motivation, formulation, graph construction, attention/pooling, training, both optimization algorithms, experiment setup and results, parameter analysis, manual annotation comparison, limitations, references, and detailed appendix tables. Visually checked PDF p. 19 for runtime and performance table interpretation. These are source results; no WAGN model was trained and no circuit speedup was measured in this documentation session.
