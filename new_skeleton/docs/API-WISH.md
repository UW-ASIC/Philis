# API-WISH — the consumer-first conformance pass to PLAN.md

Working method: **write the call site first, then make the library conform.** We
design in reverse dependency order so every signature is shaped by its consumer
rather than by what was convenient to implement. The workspace does **not
compile** until the last step lands. That is expected and accepted.

Design order (reverse of dependency order):

| # | Crate | Status |
|---|-------|--------|
| 1 | `backend/gr`, `backend/dr` | **interface landed**, impl delegated |
| 2 | `backend/gp`, `backend/dp` | **interface landed**, impl delegated |
| 3 | `frontend/library` | **interface landed**, impl delegated |
| 4 | `backend/annotator` | **interface landed**, impl delegated |
| 5 | `kernel/analog` | **landed** — `Mode::Budget`, `Requirements::budget`, `Rule::residual` overrides, `DtiBand::branch` |

`frontend/library` precedes `backend/annotator` because `library` is `Problem`'s
only consumer, and `annotator` is its producer.

`backend/dr`'s pin-access gap is a **prerequisite for validating any of this**, not
a step-5 concern: with every net open, each device extracts onto its own island,
LVS can never match, and any oracle-priced variant decision is scoring a layout
that is unroutable by construction. It is bundled into step 1 for that reason.

---

## Frozen decisions

These are settled. Do not relitigate them per-crate; divergence between the four
P&R stages is the specific failure this file exists to prevent.

### D1 — Flat parameters, no context bundle

Stage signatures stay flat even at 8 parameters. No `RouteCtx`/`PlaceCtx`/`Env`
struct. Rationale: every input stays visible at the call site, and a bundle would
have to either hide mutable loop state inside a "context" or fork into two
parallel bundles for the placement and routing tiers that then drift apart.

### D2 — `Report` carries the lex tuple at the type level

`pnr_core::Report` grew a third field. The three tiers of PLAN §3b are now
structural, not conventional:

```rust
pub struct Report {
    pub hard_violations:   Vec<Violation>,  // V   strict legality
    pub budget_violations: Vec<Violation>,  // Θ   budgets, live residual in .margin
    pub cost:              f32,             // PEX objective
}
impl Report {
    pub fn lex(&self) -> (usize, f64, f32);  // comparison key, summed across stages
    pub fn feasible(&self) -> bool;          // V = 0 AND Θ = 0
}
```

Θ is a **summed residual**, not a count: a budget missed by 1 nm and one missed by
1 µm are not equally bad, and a count-based Θ lets the search sit on a large
violation indefinitely as long as it does not add a new one.

This retires the string-match every consumer currently uses to recover a number
from prose (`v.rule == "routing overuse"` in `frontend/library`).

### D3 — Negotiation state is owned by the orchestrator

`gr::Negotiation` holds the PathFinder history cost `h_n` and is passed
`&mut` through both routers. Two reasons it is not `&mut self` on the router:

1. **Permanence is the convergence guarantee.** `c_n = (b_n + h_n)·p_n` converges
   only because `h_n` permanently increases the cost of contested resources
   (PLAN §4e). A router constructed fresh per epoch — which is what
   `frontend/library` does today — throws `h_n` away exactly when it starts to pay.
2. **The terminator must read it.** PLAN §5 terminates on prices being stationary,
   which is a statement about `h_n`. Not observable through `&dyn GlobalRouter`.

Determinism is therefore over `(inputs, seed, neg)`. Same inputs with different
incoming history route differently, by design.

### D4 — No oracle handle on any stage trait

PLAN treats DRC/PEX/LVS as callable per candidate move. **We do not buy that
API.** Instead: `verify` measures, `frontend/library` bakes the measured value into
a freshly-constructed `RuleBatch`, and the stage consumes it as an ordinary `reqs`
entry. This is the mechanism `verify::drc_feedback` already uses.

Consequence, stated so nobody "fixes" it later: parasitic and coupling gradients
are **per-epoch, not per-move**. Accepted, because PLAN's free-oracle premise does
not hold in this repo — gdsverify is 99.86% of measured runtime, and the GPU lane
was already measured net-negative. Revisit only if the extraction rewrites land.

The alternative — threading a `ctx: &Ctx` with a PDK + oracle handle through
`Rule::cost`/`satisfied` — would rewrite every rule in `kernel/analog` to buy a
granularity we cannot afford to use.

### D5 — Guard rings are `&[Macro]`, as a separate parameter

`post_cell::guard_rings` already returns `Vec<Macro>`; pins carry `NetId`
(target), shapes carry `LayerId` (obstacle). No newtype. Separate from `macros`
because macro indices are device indices everywhere else in the flow.

Rings are **placement-derived state**, recomputed every epoch (PLAN §4e: a
constraint generated by the decision it constrains). They are already in absolute
coordinates — never run them through `place_macros`.

This retires the trailing-absolute-coord-macro hack in `frontend/library`, where
rings reach signoff but the router never sees them, so every ring is an
unconnected island.

### D6 — Variant pricing is a free function, not a trait method

`gr::price_group(macros, layers, cfg) -> GroupPrice`. Not on `GlobalRouter`: it is
not an algorithm swap point, and putting it there forces boilerplate on every impl.

`GroupPrice::reachable` is load-bearing beyond cost. A variant whose pin faces
cannot be reached is **infeasible**, not merely expensive — and no placement of it
helps. That is what lets the outer loop distinguish a position-space local minimum
from a variant-space binding (PLAN §5).

### D7 — Variant choice is search state on `Layout`, and the space is pre-drawn data

`Layout::variant: Vec<u16>` indexes into
`gp::VariantSpace { alternatives: Vec<Macro>, lock: Option<u16> }` per cell. Invariant:
whoever writes `variant[i]` writes `hw[i]`/`hh[i]` from the new footprint **in the same
breath** — the same rule `orient` already obeys.

`lock` is the **matching lock**, and it is the one piece of the collapse below that
reaches a placer today: cells sharing a lock id must hold the *same* variant index, and
`dp` reshapes them **jointly**. It exists because the collapse does *not*: with one cell
per device a differential pair is two independent cells with two independent indices, and
a uniform per-cell reshape move will refinger one half of a matched pair and leave the
other alone — different fingering, footprint and pin faces on devices whose whole purpose
is to be identical. DRC cannot see it and LVS cannot see it, so nothing downstream reports
it. `dp` receives `Requirements<Layout>`, not `analog::Constraints`, so it cannot read
`Unitization::same_variant_required` itself; the producer resolves that constraint into
dense ids (`library::cellgen::variant_locks`).

Producer contract: cells sharing a lock id must have **index-compatible** spaces — at
minimum the same count, with index `v` naming the same construction in each. A consumer
may assume nothing beyond the count and must not index past the shortest member's space.
*Refusing* to reshape a locked cell was rejected as the alternative: it disables the
feature exactly where matching matters most, while the joint move *is* the same-variant
case's correct behaviour and is a step toward the real collapse rather than a stub to
delete.

Pre-drawn `Vec<Macro>`, **not** a `&dyn Reshaper` redraw callback. `(group, variant)
-> Macro` is pure and byte-deterministic, so it is drawn once per run and reused for
every trial move in every epoch; a callback would redraw per proposal, and a placer
able to redraw would need a dependency on `cells`. The variant-pricing pass has to
draw them all anyway (PLAN §2 step 2 prices a variant by drawing and routing it), so
the table is a by-product, not an extra cost.

The space arrives **already collapsed** by the same-variant and integer-ratio
constraints (PLAN §2), which is what shrinks `|Var|^|g|` to a handful of legal joint
assignments. Stages consume survivors and must never recombine them per-device.

Enumeration order is **not** a similarity ordering, so `variant ± 1` is not a "small"
reshape. Sample uniformly.

### D8 — `gp` proposes, `dp` searches

`gp` writes a starting `Layout::variant` and sizes extents from it; it does not
search. A coarse spread has no routability or parasitic signal to choose a variant
on, and PLAN §2 is explicit that pricing one means actually routing it. Reshape is a
`dp` move.

### D9 — λ/ρ carried in `gp::Prices`, orchestrator-owned

Symmetric with D3. `mechanics::analog_cost` currently derives each batch's weight
from live budget headroom, rebuilt from nothing per call — so a budget binding for
fifty epochs prices identically to one that just became binding, it never escalates,
and margin gets traded for parasitics. `Prices::drift()` is PLAN §5's
`‖λ_{k+1} − λ_k‖ < δ` stationarity probe.

### D10 — Φ and lex are different measures for different jobs

`Report::lex() -> (|V|, Θ, PEX)` ranks **solutions**.
`Report::phi() -> (|V|, Σ margin)` gates **repairs** — accept only Φ-non-increasing
moves, which makes the repair-dependency graph acyclic and stops "fix A, break B"
cycling (PLAN §3a). Metropolis still applies, but only *within* the PEX tier: uphill
moves explore parasitics and can never spend legality.

Both sum margins, so **`margin` must be a measured quantity, never a violation
count**. `format!("analog hard batch {bi}")` with `margin: count` is exactly what the
tiers replace — it makes "one batch, three violations" indistinguishable from "a 3 nm
shortfall".

### D11 — Two explicit loops, not three

PLAN §1 describes three nested tiers. `library::run` has **two**: outer over the
variant assignment, middle over feasibility epochs. The inner PEX-refinement tier is
`dp`'s own move loop and does not appear here.

That is the separation-of-timescales argument taken literally: variant choices are
discrete and rare, position feasibility is medium-frequency, parasitic polishing is
high-frequency and local. A third loop in the orchestrator would call `dp` once per
parasitic step, which is inverted — `dp` already *is* that loop.

### D12 — The outer tier fires on a diagnosis, not a schedule

The middle tier's stall counter used to `break` the run. It now feeds a decision:

- **feasible + prices stationary** ⇒ terminate. Feasibility alone is explicitly not
  termination (PLAN §5) — a run can be legal while still re-negotiating, and stopping
  there banks a solution that was mid-trade.
- **stalled + still infeasible** ⇒ *variant-space binding*. No arrangement of the
  chosen variants satisfies the constraints, so further placement effort is wasted.
  Escalate the assignment.

The stall **is** the certificate that no local position move helps, which is what
makes the two cases distinguishable at all. `RunStats::variant_escalations` exposes
the count, because "hit a variant binding" and "placement local minimum" are
otherwise indistinguishable from outside the run.

`cellgen::escalate` returning `None` (collapsed space exhausted) is a real answer —
this circuit cannot be laid out under these constraints — and terminates rather than
spinning.

### D13 — The annotator runs once per run, not once per epoch

`Problem` is a pure function of the netlist. It was re-derived every epoch only
because DRC feedback was *appended* into `problem.placement.hard` and `Requirements`
cannot be cloned (boxed trait objects). The loop now `truncate`s the feedback batches
back off at the top of each epoch, so the base rule-set is reused untouched.

Same for `fixed`, the injected-block flags, and the single-kind `abutment_groups`
filter: all pure functions of the netlist + DAG, all hoisted out.

The final `metadata::build` must truncate too — leaving measured DRC findings in
would attribute them to a declared rule family in the budget table.

### D14 — `metadata::build` moved into the loop as Θ

It ran once, after the loop, on the winner — a *report*, not a search signal. Inside
the loop it becomes the middle tier of the objective.

`BudgetStatus::criticality` is **not** the residual. It is the promotion signal (how
close to binding) and belongs in the ρ ratchet. Folding it into Θ would make a
satisfied-but-tight budget read as a violation and the run would never terminate.

### D15 — Double-registration identifies a budget, but only after judgement

`Enforce` grows a third arm (`Hard` / `Budget` / `Cost`), and every batch lands in
**exactly one**. A batch in two partitions is counted twice by `Report::lex`, priced
twice by `gp::Prices`, and makes the tier ordering meaningless — the same constraint
sits both above and below the feasibility frontier.

The existing two-arm code simulates the missing middle tier by registering a batch in
**both** `hard` and `cost` via `clone`. That pattern locates the budgets:
`CrosstalkExclusion`, `ParasiticBudget`, `CouplingBudget` in `extract.rs`.

**It is not a mechanical sweep.** `emit.rs` double-registers `SymmetryGroup` too, and
symmetry must stay `Hard`. A budget is *tradeable* — priced, with a multiplier saying
how binding it is, allowed to sit at a positive residual while converging. An exact
equality is not tradeable at any price. Demoting symmetry to a budget would make PLAN
§4a's one-grid-unit-off parking permanent and report it as convergence.

Classify by what the constraint **is**, not by the shape of its registration:
- `Hard` — legality and exact equalities (DRC, LVS structure, symmetry axes, integer
  ratios, disjunctive branches). Construction / projection / branching, never priced.
- `Budget` — accumulating set-level allowances with a spec *and* a margin (coupling
  sums, parasitic R/C, thermal gradient, matching voltage). Priced, ramped toward hard.
- `Cost` — shaping terms with no spec to violate.

Useful consequence: `ParasiticBudget` and `CouplingBudget` already carry both a spec
(`max_r_mohm` / `max_c_af` / `max_coupling_af`) **and** `margin_pct`. They can report a
real normalised residual *today*, without waiting on the `RuleBatch` margin debt — so
they are the two batches that should stop reporting counts first.

### D16 — `groups` and `abutment` are two tables, and `Problem` owns both

`Problem::groups` is the **recognition** table (composites included) so `Target::Group`
rules can score a composite like a device. `Problem::abutment` is **diffusion-sharing
permission** — the same-polarity subset.

They were conflated, and `library::run` was deriving the second by filtering the first.
That is recognition semantics in the orchestrator: only the annotator knows what a
group means. Worse, the loop applied the *filtered* table to `coarse.groups` and the
*unfiltered* one to `layout.groups` after `dp` — so the same field meant two different
things on either side of one call.

Granting abutment on the composite table lets an NMOS and a PMOS abut, their opposite
implants merge, and extraction reports a channel that "ambiguously matches MOS rules
[nmos, pmos]" — DRC-clean and LVS-fatal, unrepairable downstream because nothing is
illegal.

**Not yet consumed:** `library::run` still derives `abutment_groups` locally. Wiring it
to `Problem::abutment` is a follow-up, deliberately not done while the library step was
in flight.

### D17 — Accepted corrections from implementation (do not re-decide)

Two of the frozen decisions were wrong in detail and are amended here rather than
silently patched:

- **D2's Θ sums incommensurable units.** Routing overflow is a dimensionless node-use
  count; a DRC margin is nm. Summed into one `f64`, a 1-node overflow weighs the same
  as a 1 nm shortfall — the same defect D2 correctly rejects one level up. A residual
  is only comparable **normalised by its own budget**, so Θ wants `residual / budget`
  per entry. `Violation` needs a `budget` alongside `margin` to make that expressible.
  Folded into the margin debt below; do not add a second scaling hack in the meantime.
- **D3's `pressure()` is a level, not a delta.** PLAN §5 terminates on
  `‖λ_{k+1} − λ_k‖ < δ`. Σ`h_n` is monotone non-decreasing by construction, so it never
  goes flat while anything is contested and cannot be compared to δ. The orchestrator
  must difference it across epochs (it owns the loop, so this is its job), or
  `Negotiation` should expose the epoch increment. Currently used only for
  `RunStats::route_pressure`, so nothing is broken — but it must not become a
  termination input in its present form.

Still open, not yet accepted: `GroupPrice::reachable` is a `bool` where PLAN §5 wants a
diagnosis — it cannot say *which* pin face is unreachable, which is the actionable half.

## Debt accumulated for `kernel/analog` (step 5)

Append to this list as each consumer step invents something.

- **`Requirements` needs a third arm.** Today `hard` / `cost`. PLAN's lex-min needs
  `hard` (V) / `budget` (Θ, carrying the augmented-Lagrangian λ and ρ per batch) /
  `objective` (PEX). Budgets and the parasitic objective currently share `cost`, so
  the middle tier cannot be formed at all. Blocks: `gr::score` and `dr::score` can
  only populate `budget_violations` from *built-in* mechanics (overflow, overuse)
  until this lands.
- **λ/ρ must be carried, not recomputed.** `gp::mechanics::analog_cost` weights each
  batch by its live budget headroom — an adaptive penalty rebuilt from scratch every
  call. PLAN §6 needs the weight ratcheted up for batches whose residual is *not*
  shrinking, which requires per-batch state that survives the epoch.
- **`DtiBand` cannot be enforced by cost.** Its `cost` is penetration depth into the
  forbidden band, which is exactly the failure PLAN §4b names: a gradient on a
  disjunctive set parks in the illegal gap. Needs a per-pair Boolean
  `b ∈ {share, isolate}` as *search state*, with each branch a clean interval
  constraint. Same shape for injector-exclusion and the implant-merge/LVS guard.
- **Set-level budgets need a set, not a pair.** PLAN §4c: no pairwise rule can
  express "Σ over all aggressors ≤ budget". A victim flanked by five
  minimum-spaced aggressors passes every pairwise check and blows the budget 5×.
- ~~**A batch cannot report a real margin.**~~ **Closed** (Θ-realness step).
  `RuleBatch::residual` landed (Σ per-rule overshoot, normalised by each rule's own
  budget), every stage fills `Violation::margin` through `Violation::from_residual`,
  and the downstream symptom is fixed too: `metadata::BudgetStatus` now carries a
  measured `residual` (summed on family merge) plus an `arm` tag, `build()` scans the
  hard **and** budget arms of both tiers, and `MetadataReport::theta()` sums
  budget-arm residuals in milli-budgets rather than counting unmet rules. As
  predicted, the call site (`library::lex_key`) did not change — only `theta()`'s
  body did. Known leftover, documented at `theta()`: the stage reports already carry
  the same budget residuals, so `lex_key`'s `pt + rt + theta()` double-weighs the
  budget arm ~×2 — monotone-safe, cleanup deferred.
- **Exact equalities: the projection operator already exists and is already wired.**
  This one was mis-scoped in earlier entries and the correction matters, because it
  moves PLAN's highest-leverage item from "not built" to "built, applied at the wrong
  moment".

  `Rule::project` — "move `state` onto this rule's feasible set, **exactly**" — is
  declared with the PLAN §4a argument in its own doc comment, `SymmetryGroup`
  implements it, it has seven unit tests in `placement/symmetry.rs`, and
  `dp/src/lib.rs` calls `batch.project(&mut l, cfg.grid)` over every hard batch.

  So symmetry is *not* penalty-only. The gap is **when** projection runs: `dp` applies
  it once, terminally, after `legalize::separate_overlaps`, as a final re-snap. PLAN's
  feasibility pump wants the opposite — alternate projection with the relaxation step
  so the search never leaves the feasible manifold. A terminal snap can only move
  devices *after* legality was established, which is why the call site already has to
  measure `before_proj` and roll back, and why injected macros have to be restored by
  hand afterwards.

  Revised assessment: the representational change (symmetric-feasible sequence pair /
  ASF-B\*-tree / TCG-S) is still the strongest form, and still deferred — the trait
  contract survives it, since a representation still decodes to a `Layout`. But the
  cheap intervening win is to move the existing `project` call **inside** the SA loop
  as a per-move (or per-epoch) projection rather than a terminal snap. That is a `dp`
  change of a few lines against machinery that is already written and tested, and it
  is a strictly better use of effort than a new representation.

- **Θ's unit is now real, and one fudge factor should die with it.**
  `Rule::residual` returns overshoot **normalised by the rule's own budget**, which is
  what makes Θ summable across incommensurable rules (D17). `CouplingBudget::cost`
  currently multiplies by `1e-3` with the comment "so it is commensurate with the other
  routing costs rather than dwarfing them" — a hand-tuned scale that exists only
  because the quantity was never normalised. Normalising removes the need for it;
  delete the factor when `residual` is implemented there, and check the other rules for
  the same pattern.

## Debt accumulated in `frontend/library` (step 3)

The loop and its four `cellgen` bodies are landed. What they deliberately do not do:

- **Group collapse and merged macros are not in `enumerate`.** It emits one
  `VariantSpace` per *device*, so PLAN §2's collapse — the thing that shrinks
  `|Var|^|g|` to a handful of legal joint assignments — has nowhere to apply: there is
  no group whose variant *vector* `same_variant_required` / `target_ratio` could
  constrain, and `Problem::reuse` / `Problem::parallel` remain consumed by nobody.
  Landing it needs, in this order: (1) a device→cell map owned by `cellgen`, because
  `library::run` still indexes `device_power`, `fixed`, and `abutment_groups` by device
  and every one of those becomes wrong the moment a cell holds two devices; (2) the
  joint enumeration itself, which is where `Unitization` finally bites; (3) `cells`'
  already-written merged interdigitated path (`mosfet`'s `n_dev > 1` ABBA
  `finger_sequence`), currently unreachable because nothing asks for a multi-device
  group. (3) is also what restores legitimate diffusion abutment — a merged group is one
  macro, so the legalizer needs no same-group overlap exemption, and that exemption was
  removed precisely because it froze non-merged devices on top of each other.
- **Seeded pricing's routability half is near-vacuous until (1) lands.** `gr::price_group`
  on a one-device cell finds no net with two distinct terminals inside the group, so it
  always answers `reachable: true, overflow: 0` and only the DRC/ERC half discriminates.
  D6's load-bearing `reachable == false` therefore cannot fire yet. The call is wired
  anyway so collapse does not also have to invent the pricing path.
- **`escalate` does not sample uniformly, contra D7.** It is a mixed-radix *successor*
  ordered by pin-arrangement spread. That is forced, not preferred: the function is
  memoryless (the caller keeps no tried-set) and "never return an already-tried
  assignment" is a hard requirement, so only a successor on a total order satisfies it.
  It is also handed a different `seed` each outer iteration (`cfg.seed ^ outer`), so it
  could not index a stable permutation even if one existed. Uniform-without-repeats
  needs either a tried-set on the caller's side or a seeded bijection over the joint
  index space (cycle-walking Feistel — `Π n_i` is not a power of two).
- **Variant DRC/ERC pricing is duplicated in spirit with `macroMaster::variant_signoff`.**
  That module is the same sweep, but it is `#[cfg(all(test, feature = "gpurify"))]` and
  its `verify` dependency is optional specifically so `macro_master` builds with no
  GPurify checkout. Calling it from `library` would force `verify` (and `gdsverify`)
  into `macro_master`'s default dependency set to share eight lines `library` can call
  directly. Unify them only if they ever need to agree on more than "count the findings".
- **Per-alternative pricing adds `n_cells × |Var|` oracle calls, once per run.** Measured
  on sky130: a MOSFET enumerates 6 alternatives and each hypothesis costs ~13 ms, all of
  it inside `gdsverify` (99.86% of measured runtime). ~0.4 s for a 5T OTA, ~1 min at the
  benchmark's 800-cell ceiling. This is the one place in the flow where oracle calls were
  *added*, so it is named rather than discovered later. First cut if it bites: price
  DRC/ERC only for the alternatives that survive the routability half — which needs group
  collapse first, since that half does not discriminate on a one-device cell.
- ~~**D16's `Problem::abutment` is still derived in the loop.**~~ **Closed** (DTI
  branch step, D1) — see the annotator debt list below for the resolution.

### Appended by step 2 (`backend/gp`, `backend/dp` implementation)

Three of the entries above landed *while* this step was being implemented and are now
consumed rather than worked around: `Requirements`' `budget` arm, `RuleBatch::residual`,
and `Layout::branch`. `gp`/`dp` fill all three tiers of `Report` from real normalised
residuals, and `gp::Prices` prices `reqs.budget` with λ/ρ instead of live headroom. What
is left is genuinely new:

- ~~**The disjunctive branch move is state without a mover.**~~ **Closed** (DTI branch
  step). The missing seam landed as `Rule::branch(self) -> Option<(BranchId, bool)>`
  (the seed is the recognised-structure starting commitment, `true` = isolate) plus
  `RuleBatch::branches`, so a batch finally names which ids it owns. `dp::try_branch`
  is the predicted five-liner — flip, gate on the same `accept`, revert — carved out
  of the rotate band's roll range the way `can_reshape` was, so a run with no
  disjunctions consumes a byte-identical RNG stream. The flip is priced by `DtiBand`'s
  branch-aware `cost` copy on the PEX tier (`satisfied`/`residual` stay branch-blind
  by design). Remaining, deliberately: the branch table resets per epoch (`gp` hands a
  fresh all-`false` table and `dp` re-seeds); cross-epoch persistence is a one-liner
  in `library::run`, deferred until a circuit is seen re-discovering the same flip
  every epoch.

- ~~**`dp` cannot see the pin relocation that justifies the reshape move.**~~ **Closed.**
  `DetailedPlacer::place` now takes `macros: &[Macro]`, `Nets` carries a pin offset per
  (net, device) entry, and HPWL is a bbox over *pins* rather than device centres — so a
  reshape is priced on where its pins land (PLAN §2) and detailed placement has a
  wirelength signal at all for the first time. Confirmed empty before the fix:
  `Nets::from_macros(&[])` yields `count() == 0`, so `hpwl` returned `0.0` for every
  layout and `hpwl_delta` `0.0` for every move; dp's objective was overlap + analog cost
  only. Membership is hoisted (an alternative is drawn for the same terminals, so a
  reshape cannot change which nets a cell is on) and only the offsets of the reshaped
  cell's rows are patched — measured 30.5 µs to rebuild the CSR vs 0.018 µs to patch, on
  a 430-device/1290-pin/500-net block. Side effect, deliberate: the rotate move is no
  longer HPWL-neutral, because `Nets::pin` turns each offset by the device's `orient`.

- **Φ-monotone acceptance has no neighbourhood escalation.** `dp` accepts only
  Φ-non-increasing moves (D10), which is what makes the repair graph acyclic — but PLAN
  §3a pairs that with "when no single-move repair decreases Φ, escalate to a larger
  neighbourhood (rip up a whole group)". There is no escalation, so a device that would
  have to cross a neighbour to reach a better basin cannot get there by displacement; the
  swap move is the only escape hatch, and `legalize::separate_overlaps` is what still
  guarantees terminal legality. Not `kernel/analog`'s problem — it is `dp`'s, and it goes
  away with the sequence-pair representation, which makes the crossing unrepresentable
  rather than merely rejected.

- **λ has a cap, not a multiplier reset.** `gp::Prices` clamps `|λ|` so one physically
  unsatisfiable budget cannot swamp every other term. A batch that reaches the cap stops
  moving, which `Prices::drift()` then reads as "settled" when it is really "saturated" —
  the textbook fix is to reset λ and restart ρ when the residual stalls at a positive
  floor, which is also PLAN §5's variant-space-binding diagnostic and therefore wants to

### The `project` audit — the actual remaining correctness gap

Every batch that reaches a `hard` arm today, and whether it can restore its own
feasibility:

| batch (as registered) | feasible set | `project`? | verdict |
|---|---|---|---|

| `Symmetry` (per-rule, via the batch) | same | **yes** | correct |
| `Vec<ThermalGradient>` (`hard_and_cost`, one per block) | inequality `ΔT ≤ max_delta_mc` | no | **fine** — an inequality with a live gradient; the optimiser is the right tool, and a projection would have to solve the thermal PDE backwards |
| `Vec<Isolation>` (`hard_and_cost`, BiasGen) | inequality `gap ≥ min_distance_nm` | no | **fine** — continuous gap hinge, gradient walks to the set |

| `Vec<Differential>` (`extract::routing`) | length delta inequality **∪ a set equality on layer assignment** | no | **GAP** — the layer half is exact, is *not scored by `cost` at all*, and has no projection. - **`CentroidGroup` is penalty-only, and `violations` returns a constant `0`.** PLAN §4c
  states the two-sided common centroid as a group-level *linear equality*
  (`Σ_A a_i·(x_i − c) = Σ_B a_j·(x_j − c) = 0`, area-weighted) and rejects pairwise
  enforcement as "provably weaker". `separation()` measures it correctly; squaring it and
  registering it in `cost` only is PLAN §4a's parking failure with nothing above the
  feasibility frontier to notice. A `project` here would be *wrong*, not merely missing:
  the legal corrections are the interleavings (ABBA / checkerboard), a permutation of the
  array, and a projection that shifted coordinates would satisfy the equation while
  destroying the pattern that makes it mean anything. Same answer as symmetry —
  representation, not penalty. Commented at the call site in `placement/cc.rs`.
- **`MatchingPair::w_ratio` is read by nothing** — not `cost`, not `satisfied`, not

  enforced only by `cell::Unitization` (`target_ratio` / `dev_nf`), which is the right
  home, but nothing checks the two agree, so a contradicting `w_ratio` is silent.

**Restating the `SymmetryGroup` timing gap, since it is the one item that is built and
mis-scheduled rather than absent:** `dp` calls `batch.project(&mut l, cfg.grid)` once,
terminally, after `legalize::separate_overlaps`. PLAN's feasibility pump wants projection
*alternated* with the relaxation step so the search never leaves the manifold. The
existing call site already pays for the mistake — it measures `before_proj`, rolls back,
and hand-restores pinned macros. Moving that call inside the SA loop is a few lines in
`dp` against tested machinery and is strictly better value than a new representation.
`dp` is another agent's crate and was not touched.

### Normalisation and fudge factors

- **`CouplingBudget::cost`'s `× 1e-3` is deleted.** `cost` and `residual` are now the same
  normalised overshoot (`total_af / max_coupling_af − 1`, floored at 0). Safe in place
  because the batch is registered in the **budget** arm only and neither `gr::score` nor
  `dr::score` reads a budget-arm `cost`.
- **`ParasiticBudget::cost`'s `× 1e-6` is the same species and was left alone.** It is a
  hand-tuned scale on `len²` in nm², existing only because the quantity is not divided by
  `max_len_nm²`. Unlike the coupling one it *is* read — `gr::score` sums `reqs.cost`
  costs and `dr::score` blends them — so rescaling silently re-weights a sibling stage's
  PEX tier. Marked `ponytail:` in place; the upgrade is `(len/max_len)²` plus a
  re-baseline of the routing cost fixtures in one commit.
- **The `1e-3` / `4e-3` family on the placement pull terms** (`Symmetry`, `MatchingPair`,
  `CommonCentroid`, `CentroidGroup`, `Proximity`, `ThermalGradient`, `Isolation`) are
  *not* in the same category and were not touched. They are relative weights **within**
  the PEX tier, which PLAN §3b explicitly says is the one place a scalar weighting is
  appropriate. They are only a problem if one of those terms is ever promoted to Θ.
- **`Isolation::cost` squares its shortfall; `Isolation::residual` does not.** Squaring is
  not summable across rules — two rules 10% over would contribute `0.01` each while one
  rule 20% over contributes `0.04`, making Θ depend on how a violation is *partitioned*.
  Every `residual` in the crate is linear in the overshoot for that reason.

### Set-level budgets (PLAN §4c) — verified, nothing rewritten

  other net's same-layer shapes), and `residual` is measured on that sum. Confirmed by
  test: four aggressors at identical legal spacing give 4× the coupling of one.
- `CentroidGroup` is genuinely set-level (`a_side` / `b_side`, area-weighted). The

  by nobody, which is correct, but it is also not deprecated.
- Nothing else that should be set-level is secretly pairwise. `CrosstalkExclusion` is

  the floor cannot express; they are two constraints, not one done twice.
- Not yet set-level, and arguably should be: `Antenna` uses a constant
  `NOMINAL_GATE_AREA` denominator instead of the summed area of the gates the net drives,
  which is the same "sum over the set" shape one level down. Blocked on a net→gate-area
  map that `Routes` does not carry.

### `DtiBand` — what the annotator must now do

`cost` is branch-aware (measures against the committed component only), `satisfied` stays
the full disjunction (a pair that drifted into the *other* component is legal — making
this branch-aware would report a false violation whenever a flip is pending and
Φ-monotone acceptance in `dp` would reject the very move resolving it), and `residual` is
band penetration normalised by band width.

**Landed** (DTI branch step): `annotator::emit::placement` is the producer — one
`DtiBand` per recognised pair (DiffPair, each CurrentMirror leg, Cascode, Load →
`share`; BiasGen pair → `isolate`), accumulated across the whole call and registered
as ONE batch via `hard_and_cost` (the cost copy is what prices the flip). The
contract it satisfies, kept for the next disjunctive rule:

1. Allocate one `BranchId` per emitted pair, densely from `0`, and size `Layout::branch`
   to that count (`gp::mechanics` already writes the table). Two pairs must never share an
   id — sharing couples two independent disjunctions into one flip.
2. Seed the commitment from the **recognised structure**, not from geometry: `share` for
   pairs the recogniser puts in one trench (same well, same matched group,
   diffusion-shareable), `isolate` for a noisy/sensitive pair or an injector on a `<1 kΩ`
   path from a pad. Seeding from the current gap would re-derive the accident the branch
   exists to eliminate, since coarse placement has not run.
3. Keep the id stable across epochs. `Requirements` order is already a contract for
   `gp::Prices`; `BranchId` is the same kind of contract for search state, and a
   renumbering silently transfers one pair's commitment to another.

Injector-exclusion and the implant-merge/LVS guard are the same disjunctive shape and want
the same treatment. The flip move landed with the producer (`dp::try_branch` — see the
closed "state without a mover" entry above); the injector-on-pad-path *seed* did not,
because nothing models a pad or a path resistance (ledgered in the annotator debt list).

### Frozen decisions this step disagrees with

Mechanically: `gr::analog_tiers(routes, reqs) -> (V, Θ)` is the single routing-side
implementation and `dr::score` calls it, so the two stages cannot report the same batch on
two scales. The factor is **milli-budgets with `ceil`**, identical to `gp::mechanics::report`'s
private `milli`, and `gr::milli_budget`'s doc names `gp` as the authority.

- ~~**The scale factor now exists twice and is load-bearing in both copies.**~~
  **Closed** (Θ-realness step). `Violation::from_residual(rule, residual)` landed in
  `pnr_core::report`, exactly as prescribed — a constructor rather than a bare
  factor, with the `ceil` rationale in one home. `gp::mechanics`' private `milli` and
  `gr::milli_budget` are both deleted; every stage's margin goes through the
  constructor.
- ~~**Θ still mixes units by exactly one factor of 1000, and it is now inside a single
  stage.**~~ **Closed** (Θ-realness step). `gr::score` and `dr::score` both take a
  `cap_total` denominator (per-node capacity × node count) and report the built-in

  `Σ(usage − cap) / Σcap` in milli-budgets, in the same commit for both because
  `library::lex_key` sums the two stages' Θ. `Report::cost` deliberately keeps the
  **raw** overflow/overuse: the PEX tier's terms are relative weights within one
  stage, and rescaling one silently re-weights that tier.
- **A hard batch with no `residual` override now reports `1000 × violations`, not
  `violations`.** `Rule::residual`'s default is `1.0` when unsatisfied, so the count
  behaviour survives scaled up by the same factor `gp` uses. Harmless today — Φ is only

  violated while reporting no residual (the default override). A batch registered in the
  wrong arm therefore fails differently in each direction, which is a feature — a `Hard`
  batch in `budget` would vanish from Θ, and that is a louder failure than a silent 1.0.
