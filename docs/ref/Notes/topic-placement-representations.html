Placement representations and symmetry

Use sequence pairs, trees and shape functions while understanding the feasible space they encode.

Choose a representation for the constraints that must survive every move

A placement representation is more than a way to store coordinates. It determines which layouts can be reached, which constraints are true by construction, the cost of generating coordinates, and what a search move means. Coordinates offer freedom but admit overlap. A sequence pair encodes a relative ordering that can be packed without overlap. A symmetry-aware tree can make reflected pairs inseparable during search. A hierarchy can reduce the search dramatically while excluding useful global arrangements. The correct choice follows from required invariants and available computation, not from a universally superior tree.

Separate three objects. Electrical devices belong to the netlist. Physical modules are generated shapes containing one device, several fingers, or multiple electrically related devices. Placement states select a module variant, orientation and location while preserving the device-to-terminal mapping. Confusing those objects makes a geometric swap change electrical identity or makes a common-centroid equation count a merged macro as one unit when it represents several. The distinction is explicit in the topological volume's hierarchical synthesis chapter. Topological Approaches, PDF pp. 111–115.

This chapter derives small examples and then proposes an incremental path for Philis. Geometry is illustrative and is not a PDK rule set. Before comparing algorithms, read the optimality contract: a representation cannot make an omitted electrical or manufacturing constraint true.

Coordinates: flexible state, explicit legality burden

For each rectangle i, let its lower-left corner be (xi, yi), width wi and height hi. Two rectangles do not overlap if at least one relation holds: i left of j, j left of i, i below j, or j below i. With required horizontal and vertical clearances, these are inequalities such as xi + wi + sij ≤ xj. Their logical or is what makes unconstrained placement difficult: the optimizer must select a separating relation before ordinary continuous compaction can enforce it.

Philis stores device centers and oriented half-extents in Layout (line 11), together with orientation, variant, group, symmetry-axis and discrete-branch state. The equivalent left edge is x − hw. This is a useful general state representation: topology packers can emit the same coordinates, so an experimental sequence-pair or hierarchical packer need not replace the physical database. However, a bounding box does not describe terminal access, well spacing, internal diffusion, or a nonrectangular halo.

Action and reason: define a canonical placement candidate with stable physical-module identity, generated geometry revision, terminal map and exact coordinate transform. Let each search representation produce a candidate through an adapter. A single downstream legality evaluator then makes comparisons meaningful. Otherwise one algorithm can appear better because its packer ignored a halo or used device-center wirelength while another used actual pins.

Maintain variant and orientation invariants atomically. A rotation that changes the footprint must update extents and pin transforms in the same transaction. This is already stated as an invariant in Layout. Add independent checks for transformed polygons and accesses, because equal rectangle dimensions do not imply equal terminal geometry.

Sequence pairs: decode orders into separation constraints

A sequence pair consists of two permutations α and β of the same modules. Use the convention in the source: if i precedes j in both sequences, i is left of j. If i precedes j in α but follows j in β, i is above j. Every pair therefore receives one horizontal or vertical separation relation. Implementations using the opposite vertical convention are equally possible, but packer, moves and tests must share one definition. Topological Approaches, PDF pp. 48–51.

Take α = (A, B, C), β = (B, A, C), with A of size 4×2, B of size 3×3 and C of size 2×4. A is above B because their order reverses. A and B are both left of C because each precedes C in both sequences. Set the source coordinate to zero. Horizontal constraints give xA = xB = 0 and xC = max(4, 3) = 4. Vertical constraints give yB = yC = 0 and yA = 3. The resulting bounding rectangle is 6×5. This packing is minimal for those separation relations and dimensions; it is not a proof that 6×5 is globally optimal over all sequence pairs.

A straightforward implementation builds directed horizontal and vertical graphs and computes longest paths. Faster weighted longest-common-subsequence algorithms avoid explicitly storing every pairwise relation. The surveyed contour and priority structures improve decoding cost, but do not change the electrical meaning of a placement. Benchmark both decode time and feasible useful candidates per second. A faster decoder that generates mostly constraint violations can be slower at reaching a usable layout. PDF pp. 25–47.

decode(alpha, beta, dimensions, required_gaps):
    verify both permutations contain the same unique module IDs
    classify every pair using the documented order convention
    add directed separation edges with dimension + required gap
    check the resulting coordinate systems for consistency
    obtain x and y by longest paths or an equivalent decoder
    emit a candidate and verify the constraints outside the encoding

Same-axis symmetry is not automatic. The source derives a sufficient ordering condition for symmetry-feasible sequence pairs involving each module's reflected partner. It explicitly states that the condition is sufficient, not necessary. Searching only this subset exchanges coverage for efficiency. Record that restriction in experiment reports; an excluded feasible layout is not evidence that the circuit itself is infeasible. Multiple symmetry groups also require care because interleaved repair passes can obstruct each other; nested embedding or controlled group ordering avoids that failure mode. PDF pp. 49–50, pp. 60–64.

B* trees and symmetry islands: encode constructive structure

In the conventional B* interpretation presented in the symmetry-island chapter, a left child is placed to the right of its parent and a right child has the parent's x coordinate. A contour records the lowest legal y position above previously packed blocks. The contour is essential: a tree edge alone does not completely determine y when intervening blocks occupy space. Check conventions when combining chapters, because the hierarchical LP chapter uses a related tree with its own construction details. PDF pp. 79–85.

An automatically symmetric representation stores one representative of each mirrored pair and reconstructs its partner. Self-symmetric blocks lie on the axis. The island requirement additionally keeps group members connected by abutment. This is useful when close matching and local routing are essential, but it is stronger than symmetry itself: a symmetric solution need not be one connected island. Later extensions permit nested groups and otherwise unused spaces. The restriction should be selected because it serves an identified design purpose, not applied to every recognized pair automatically. PDF pp. 100–106.

Action: add a rigid or parametrically deformable group move before replacing the whole placer. Move the shared axis and legal representatives, regenerate partners and then check external constraints. This preserves equalities by construction and reduces repeated repair. The cost is a restricted move family, so retain occasional group restructuring or alternative templates to avoid freezing an initially poor internal arrangement.

The hierarchical B* work supports rectilinear island boundaries and contour-aware placement. A parent that sees only a bounding rectangle may waste reusable cavities; a parent that sees only active rectangles may illegally place another block in required well or guard-ring space. Offer a deliberate interface with occupied geometry, exclusive regions and permitted routing regions. Each region answers a different physical question.

Constraint graphs, linear equations and hierarchy

Once topology selects a relation, many spacing requirements become difference constraints xj − xi ≥ dij. A directed acyclic graph can compact these by longest paths. General linear equalities such as xA + xB = 2a for a symmetry axis a, or weighted centroid relations, need a richer linear system. Pretending a four-variable relation is an ordinary two-node spacing edge loses information. The retargeting chapter develops generalized coefficient graphs for this reason. PDF pp. 215–232.

Use a constraint graph or LP as a legality and compaction stage after a topology move. The rationale is separation of duties: search chooses combinatorial ordering and variants; a solver obtains the best coordinates for those choices. A feasible LP certifies only its encoded linear constraints. It does not prove diffusion sharing, orientation-dependent effects or post-route performance unless those models are actually included and valid.

Hierarchy should reflect electrical relationships while permitting overlap between relationship types. A device can belong to a matched pair, a current path and a proximity set simultaneously. The source's multi-level symmetry/matching/proximity graph gives one priority ordering, but also recognizes simulation-dependent priorities. Collapsing all intent into a single disjoint tree can erase those simultaneous requirements. Keep the semantic constraint graph even when a tree is chosen as the search decomposition. PDF pp. 119–129.

Bottom-up shape curves enumerate several child arrangements and retain width/height alternatives. For an ordinary horizontal composition, width is the sum of child widths and gaps while height is their maximum; vertical composition exchanges those operations. Enhanced shapes can exploit contours. Pruning a shape because another is narrower and shorter is safe only for the objectives and contexts represented by that dominance relation. A slightly larger child may expose the sensitive output on the correct side and reduce parent-level parasitics. Retain pin-interface or electrical equivalence classes when pruning. PDF pp. 137–147.

Philis already recognizes blocks in recognize (line 175), emits stage axes in placement (line 53), and applies projected moves in Sa::trial (line 140). Build a comparison around that boundary: current coordinate search; group-preserving coordinate moves; then an optional topological initializer or packer. This sequence lets each added representation justify itself through better feasible search rather than architectural fashion.

Verify a tiny sequence-pair case by enumerating both permutations and comparing decoded nonoverlap with a direct rectangle check. Verify group moves with unequal widths and self-symmetric blocks, then with nested axes and fixed devices. Check that round-tripping a topology through coordinates preserves electrical identity, orientation and pin geometry. Finally compare complete routed results with identical model fidelity, random-seed budgets and hardware time. Area alone cannot tell whether a representation helped analog layout.

A useful report records both solution quality and representation coverage: fixed hierarchy, permitted variants, symmetry restrictions, ordering convention and unresolved failures. Search failure inside a restricted family is evidence about that family and runtime budget. It should trigger a broader representation or a clear incomplete result, never an unsupported statement that no valid layout exists.
