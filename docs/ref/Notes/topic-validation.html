Chapter 30 / 30

Experiments that demonstrate better layouts

Validate mechanisms, compare fairly, expose counterexamples and measure circuit-level improvement.

To show that a new constraint improves layout quality, test the physical failure it is intended to prevent and the tradeoffs it creates. A lower internal penalty alone is not evidence of a better analog circuit.

Write a falsifiable claim for every improvement

Turn “common centroid is better” into a conditional statement: “for equal electrical unit weights in a linear spatial parameter field, the generated layout equalizes the first moments and reduces that field's ratio-error contribution.” Then test a quadratic field, unequal edge environments and routed parasitics, where the same certificate is insufficient. This structure distinguishes a valid technique from a universal claim the sources do not make. Gradient-cancellation motivation, PDF pp. 1–3 Limits and tradeoffs, PDF pp. 6–7

Similarly, “wider routes improve performance” needs a circuit, metric and operating domain. Widening reduces geometric resistance but can add capacitance or force detours. The wire-sizing paper provides explicit cases where uniform width changes improve some metrics and worsen others. Test the actual constraint and its competing effects. Uniform-width comparison, PDF p. 19

A useful experiment record states the mechanism, expected direction under its assumptions, intervention, unchanged comparison conditions, measured outcomes, possible confounders and acceptance threshold. Thresholds should follow a specification or model accuracy requirement, not be chosen after observing the result.

These are proposed discriminating experiments, not claims that the current engine passes them or that they were run during handbook writing. The detailed chapters supply the equations, scope and expected failure modes behind each row.

Use a validation ladder from arithmetic to complete circuits

Level 1: mathematical and semantic checks. Verify moment algebra, units, covariance transformations, terminal identities and graph equivalence on small examples with known answers. These can expose an incorrect implementation before an expensive layout run. For the higher-order pattern, explicitly test every monomial of total degree up to the claimed order; do not test only one convenient gradient direction.

Level 2: isolated physical structures. Use device arrays, line/via structures, coupled routes, guard rings or resistor/capacitor cells with controlled geometry. Compare analytic limits and an independent qualified extraction/model source. Sweep the parameter that activates the mechanism, including boundary conditions where the approximation should break down.

Level 3: circuit blocks. Use mirrors, differential pairs, OTAs, resistor ratios, references and capacitor DACs with fixed testbenches. Evaluate the metrics that motivated the constraint. A mirror may need current-ratio error over output voltage; an OTA needs more than gain; a reference may be limited by temperature coefficient or thermoelectric offset.

Level 4: complete flow. Run annotation, cell generation, placement, routing, physical checks, extraction and simulation. Include legal-route success rate and model coverage, not just the best successful circuit. This reveals interface failures that isolated rule tests miss.

Level 5: process/manufacturing evidence. Compare to foundry-qualified decks, characterized models and measurements where available. Textbook equations and simulations do not independently establish silicon yield. This stage is a required external evidence source for manufacturing claims, not work completed by these notes.

Make comparisons fair and reproducible

Hold the schematic, authorized sizing space, process data, legal geometry policy, testbenches and metric definitions constant unless the experiment intentionally studies one of them. If a new method uses larger devices or a looser outline, disclose that as a changed design space. Compare at equal compute/evaluation budgets as well as, where useful, equal final quality.

Use several seeds for stochastic search. Report the distribution of feasible quality, feasibility rate, runtime and failure reasons. The best of many runs can overstate typical performance; an average over only successful runs hides inability to route difficult examples. For timing, distinguish wall time from total CPU/GPU work and number of expensive extraction/simulation calls.

Cache keys should include schematic, emitted geometry, PDK/deck/model versions, extraction settings, stimulus and measurement script. Store unrounded raw metrics and derived scores so a changed weighting policy does not require pretending old measurements were different. Keep versioned candidate records; source hashes in coverage serve a similar purpose for this handbook.

For layout-aware ML, split datasets at the level matching the claim. Random variants from the same topology support interpolation claims. Transfer to new circuits, sizes, processes or test modes needs corresponding held-out groups. Check repeated or near-identical geometries across splits; leakage can make a model appear predictive while it is memorizing layouts. Metric-dependent transfer, PDF p. 4

Use ablations to learn which constraint helped

Compare the full method to variants removing one new constraint or model at a time, while preserving feasibility requirements. For example, compare route-length matching alone to route-length plus per-layer/via matching, then to extracted terminal RC matching. Measure both runtime and electrical results. If a new geometric rule improves its own score but does not improve any intended metric, it may still be useful as a conservative screen, but that is a narrower claim.

When mechanisms interact, a one-at-a-time ablation is insufficient. A guard ring's benefit depends on return impedance; common centroid's value depends on the gradient model; wire widening depends on node sensitivity and channel congestion. Add a small factorial or structured sweep for these interacting variables. Report the domain where the effect changes sign rather than forcing one universal ranking.

Also include counterexamples. A no-gradient scenario should not reward costly gradient cancellation merely because the pattern looks disciplined. A low-impedance route may tolerate added capacitance that would be fatal on a high-impedance node. A dummy or shield lacking the connection or environment required by its qualification should not receive the corresponding credit; some qualified dummy/fill structures are intentionally floating. These cases check the evaluator's reasons for taking an action.

Quantify uncertainty in yield and small improvements

If n independent Monte Carlo samples contain no failures, that does not prove zero failure probability. Under a binomial model, a one-sided confidence bound at level 1−α gives pfail ≤ 1−α1/n, approximately −ln(α)/n for a small bound. At 95% confidence this is about 3/n. Thus 1,000 passing samples support a bound near 0.3%, not parts-per-billion reliability. The derivation follows P(no failures) = (1−p)n; independence and representative sampling are assumptions.

For paired layout comparisons, use common characterized random samples when appropriate to reduce comparison noise, while still evaluating the joint pass event for each layout. Do not independently push every correlated parameter to its worst marginal quantile and call that a statistically meaningful sample. Importance sampling or worst-case distance methods need their own assumptions and estimator checks, as discussed in robust design.

A tiny nominal metric improvement below extraction or simulation uncertainty is not convincing evidence. Estimate solver tolerance, model approximation and run-to-run variation where relevant. Report a practical effect size and margin to required limits. A repeatable increase in feasibility or margin can matter more than a small best-case objective gain.

Reuse independent checks already present in the repository

The repository includes DRC cross-check tooling, LVS cross-check tooling, and PEX cross-check tooling. Build validation around these independent comparisons where their PDK/device scope is appropriate. Their existence is not proof that every new device or effect is covered. In particular, xcheck_pex.py independently recomputes the same per-rectangle ground-capacitance formula from GDS and checks a heuristic total/ground-capacitance band; it does not independently validate resistance, coupling, field accuracy or reduced-network poles. The DRC comparison uses the same local deck, so agreement does not prove foundry-rule completeness. Inspect the actual invocation, model and reference setup for each experiment.

Separate the reusable validator from the optimizer being evaluated. A moment checker that simply reads the optimizer's reported score cannot independently verify its internal-unit mapping. Recompute from emitted unit identities and coordinates. Likewise, extract the final routed geometry when testing a width change; do not validate it using only the width value requested before legalization.

Report improvement in the language of the design contract

A useful result says which required metrics passed, how their worst-case margins changed, how many candidate runs were feasible, and what area/power/runtime costs accompanied the change. Show the nondominated alternatives when tradeoffs remain. Do not aggregate unrelated circuits into a single percentage without explaining normalization and weighting.

Keep the conclusion bounded by evidence: “reduced simulated offset variance under the characterized model,” “improved worst-bit settling at equal capacitance,” or “detected terminal-index failures that the previous test hid.” Those claims directly support better engine decisions. A source paper's reported speedup, matching improvement or yield number becomes a hypothesis to reproduce under Philis's conditions, not a default expectation.
