# 2.4 The Hierarchical Framework

> **Chapter 2**: Hierarchical Placement with Layout Constraints (Lin & Chang)
> **Part**: Part I: Placement

## Key Concepts

The hierarchical framework builds on top of the [[2.3 Placement of a Symmetry Group|ASF-B*-tree]] (which handles a single symmetry group) to address the full placement problem: simultaneously placing **symmetric modules inside symmetry islands** alongside **nonsymmetric modules**. The key data structure is the **Hierarchical B*-tree (HB\*-tree)**.

### 2.4.1 Hierarchical HB\*-Tree

- The **HB\*-tree** extends the ordinary B\*-tree by introducing **hierarchy nodes** that encapsulate entire symmetry groups.
- Each symmetry group $S_i$ is represented by a single **hierarchy node** $n_{S_i}$ in the top-level B\*-tree.
- Inside each hierarchy node, an **ASF-B\*-tree** (Augmented Symmetry-Feasible B\*-tree, see [[2.3 Placement of a Symmetry Group]]) stores the placement of that symmetry group's modules. The ASF-B\*-tree produces a **symmetry island** -- the rectilinear region occupied by the symmetric placement.
- **Non-hierarchy nodes** represent ordinary (nonsymmetric) modules and are placed in the top-level B\*-tree alongside hierarchy nodes.
- This two-level structure allows the placer to **simultaneously optimize** the placement within each symmetry group and the global arrangement of all modules.

**Example (Fig. 2.12):** For a placement with two symmetry groups $S_1$ and $S_2$, the HB\*-tree has two hierarchy nodes $n_{S_1}$ and $n_{S_2}$, each containing an ASF-B\*-tree, plus regular nodes for nonsymmetric modules.

### 2.4.2 HB\*-Tree with Rectilinear Symmetry Islands

Symmetry islands are generally **not rectangular** but **rectilinear** (staircase-shaped). The basic HB\*-tree must be augmented to represent these irregular outlines accurately.

**Prior approach (Wu et al. [33]):** Slice a rectilinear module into rectangular sub-modules along vertical boundaries. This is problematic because maintaining sub-module relationships during B\*-tree perturbations is complicated.

**The contour-node approach (used here):** Instead of slicing, introduce **contour nodes** into the HB\*-tree to represent the top horizontal contour segments of each symmetry island.

- For a symmetry island with contour segments $c_{00}, c_{01}, c_{02}$ (left to right), three contour nodes $n_{00}, n_{01}, n_{02}$ are added.
- Each contour node stores the coordinates of its corresponding horizontal contour segment.

#### Property 2.2: Structural Rules for the HB\*-Tree

Six properties govern the relationship between hierarchy nodes, contour nodes, and regular module nodes:

1. The **left child** of a hierarchy node, if any, must be a **noncontour node** (it represents the lowest adjacent module to the right of the symmetry island).
2. The **right child** of a hierarchy node must be the **contour node** representing the **leftmost** top horizontal contour segment (modules are placed above the symmetry island).
3. The **left child** of a contour node, if any, must be the contour node representing the **next contour segment to the right**.
4. Children of a **regular module node** must be **noncontour nodes**.
5. The **right child** of a contour node, if any, must be a **noncontour node** (otherwise contour segments would overlap).
6. The **parent** of a contour node must be either a contour node or a hierarchy node (never a regular module node).

These properties ensure a consistent tree structure where contour nodes form a left-linked chain hanging off the right child of the hierarchy node, and regular modules attach only at valid positions.

**Example (Fig. 2.13):** For symmetry group $S_0 = \{(b_0, b_0'), (b_1, b_1'), (b_2, b_2')\}$:
- (a) The ASF-B\*-tree of $S_0$
- (b) Horizontal and vertical contours from packing
- (c) The rectilinear symmetry island with effective contours $c_{00}, c_{01}, c_{02}$
- (d) The augmented HB\*-tree with hierarchy node $n_{S_0}$ and three contour nodes

### 2.4.3 HB\*-Tree Packing

The packing algorithm determines the physical coordinates of all modules from the HB\*-tree representation.

**Packing Procedure:**

1. **Traverse the HB\*-tree in preorder (DFS).**
2. When a **hierarchy node** is encountered:
   - **Pack its internal ASF-B\*-tree first** to obtain the symmetry island's contours (both top horizontal contours and bottom contour from [[2.3 Placement of a Symmetry Group|Section 2.3]]).
   - Store the contours in the hierarchy node.
   - Calculate the **best y-coordinate** for the bottom boundary of the symmetry island using the bottom contour (from Fig. 2.11), minimizing dead space between previously packed modules and the symmetry island.
   - Pack the **left child** (and all its descendants) of the hierarchy node.
   - Then pack the **contour nodes** of the symmetry island sequentially ($n_{00}, n_{01}, n_{02}, \ldots$), updating their coordinates.
   - Replace the hierarchy node with its contour information in the global contour data structure.
3. **Device-type awareness:** When packing a node, compare the device type (NMOS/PMOS) with previously packed modules in the contour list. If types differ, snap the module to reserve white space for surrounding **wells or guard rings**.

**Example (Fig. 2.14):** An HB\*-tree with 20 modules and two symmetry groups $S_0, S_1$:
- First, the ASF-B\*-trees inside $n_{S_0}$ and $n_{S_1}$ are packed to obtain rectilinear outlines.
- Then nodes $n_5, n_6, n_7, n_8, n_9$ are packed in DFS order.
- The temporal contour list starts as $\langle n_5, n_6, n_7, n_9 \rangle$.
- After placing $S_0$'s symmetry island, the contour list updates to $\langle n_{S_0}, n_7, n_9 \rangle$, minimizing dead space.

#### Theorem 2.4: Linear-Time Packing

> **The packing for an ASF-B\*-tree or an HB\*-tree takes linear time**, i.e., $O(n)$.

**Proof sketch:** Given $n$ total modules, $m$ symmetry groups, $\hat{n}$ nonsymmetric modules, and $n(S_i)$ modules per symmetry group:

$$n = \hat{n} + \sum_{i=1}^{m} n(S_i)$$

- **ASF-B\*-tree packing** for group $S_i$: Two steps, each $O(n(S_i))$.
  - Step 1: Pack all representative modules (B\*-tree packing is linear).
  - Step 2: Compute coordinates of each symmetric module in constant time per module.
- **HB\*-tree packing**: If all symmetry islands are rectangular, $O(m + \hat{n})$ time (ignore contour nodes). If rectilinear, the bottom contour of $S_i$ has $O(n(S_i))$ segments; comparing packing contour segments with bottom contour segments takes $O(n(S_i))$.
- **Total**: $O(m + \sum_{i=1}^{m} n(S_i) + \hat{n}) = O(m + n)$. Since $m \leq n$, the packing time is $O(n)$.

## Algorithms & Methods

### HB\*-Tree Packing Algorithm (Pseudocode)

```
function PACK_HB_TREE(node):
    if node is NULL:
        return

    if node is a HIERARCHY NODE:
        // Step 1: Pack internal symmetry group
        pack ASF-B*-tree inside node
        compute top contours and bottom contour of symmetry island
        store contours in node

        // Step 2: Calculate y-coordinate for symmetry island
        y = best_y from bottom contour vs. current packing contour

        // Step 3: Pack left subtree (modules to the right)
        PACK_HB_TREE(node.left_child)

        // Step 4: Pack contour nodes (modules above symmetry island)
        for each contour_node in node's contour chain:
            update contour_node coordinates
            replace hierarchy node in global contour structure
            PACK_HB_TREE(contour_node.right_child)  // modules above this segment

    else if node is a REGULAR MODULE NODE:
        // Standard B*-tree packing
        compute (x, y) from parent relationship and contour
        snap position if device type differs (well/guard ring spacing)
        update contour structure
        PACK_HB_TREE(node.left_child)
        PACK_HB_TREE(node.right_child)
```

### Key Data Structures

| Structure | Role |
|-----------|------|
| **B\*-tree** | Base tree encoding relative placement (left child = lowest adjacent right; right child = first module above) |
| **ASF-B\*-tree** | Augmented Symmetry-Feasible B\*-tree for a single symmetry group (see [[2.3 Placement of a Symmetry Group]]) |
| **HB\*-tree** | Hierarchical B\*-tree -- top-level B\*-tree with hierarchy nodes containing ASF-B\*-trees |
| **Hierarchy node** | Represents an entire symmetry group; contains an ASF-B\*-tree |
| **Contour node** | Represents a horizontal contour segment of a rectilinear symmetry island |

## Connections to Bigger Picture

Section 2.4 bridges the gap between single-symmetry-group placement ([[2.3 Placement of a Symmetry Group]]) and the full placement algorithm ([[2.5 The HB-Tree Algorithm]]). While Section 2.3 introduced the ASF-B\*-tree to handle one symmetry group, the HB\*-tree embeds multiple ASF-B\*-trees into a unified hierarchical structure that can be optimized via simulated annealing (covered in Section 2.5). The contour-node augmentation for rectilinear symmetry islands is a critical contribution -- without it, the framework would be limited to rectangular symmetry islands, which rarely occur in practice. The linear-time packing guarantee (Theorem 2.4) is essential for making the simulated annealing loop practical, since packing is called thousands of times during optimization. This hierarchical approach contrasts with the flat placement methods of [[1 Device-Level Topological Placement|Chapter 1]] (Balasa), which handle symmetry at the device level without explicit hierarchy, and sets the stage for the deterministic hierarchical approach in [[3 Deterministic Analog Placement|Chapter 3]] (Strasser et al.).
