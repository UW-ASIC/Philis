# 5.1 Introduction to Layout Retargeting

> **Chapter 5**: Analog Layout Retargeting (Said, Dessouky, El-Adawi, Abbas, Shahein)
> **Part**: Part III: Layout in the Design Flow

## Key Concepts

### 5.1 Introduction -- Why Retargeting Matters

- **Process migration** is a constant pressure in the semiconductor industry: fabrication houses continuously push toward smaller feature sizes, forcing mixed-signal teams to migrate legacy IP blocks to newer processes.
- Unlike digital designs, where migration is largely automated (re-run the flow after migrating the standard-cell library), **analog migration is still mostly manual**. Device characteristics change with the process, so circuits are redesigned even when targeting the same performance.
- **Layout retargeting** aims to automate this: given a source layout in process A, produce a functionally equivalent layout in process B that preserves the original placement, routing, and design heuristics.
- Key motivation: the source layout already embeds years of expert knowledge -- verified through fabrication and silicon testing. Designers prefer to keep this knowledge rather than accept a tool-generated "optimized" layout that has never been taped out.
- Retargeting is distinct from automatic placement and routing: it **starts from an existing layout** rather than a netlist, and its goal is to **conserve physical intelligence** while adapting to new design rules.

### 5.2 Previous Work

- The need to migrate hard IPs was first investigated for **digital cells** [1], then extended to digital library IPs with constraints like port matching and power/ground sizing [2].
- **Analog IPs** impose additional constraints: **matching, symmetry**, and the tight coupling between physical design and circuit behavior [3, 4].
- Early optimization-based retargeting tools were rejected by designers because they "reinvent the wheel" -- producing new layouts rather than preserving the original design intent [5].
- One of the first analog cell migration approaches [6] reused only relative block positions and aspect ratios; device-level fidelity was not guaranteed.
- **Compaction-based migration** [7, 8] emerged as the preferred approach because the target layout closely resembles the source, preserving floorplan, placement, and routing. This is the approach developed in this chapter.
- The framework in [8] comprises both **device resizing** (netlist migration) and **layout migration**, both based on a design extraction methodology.

### 5.3 Analog Layout Retargeting Flow

The retargeting tool takes four inputs:
1. **Source design netlist and layout** (in the original process)
2. **Target netlist** with new device dimensions (from a separate netlist migration engine [10])
3. **Target process technology parameters and design rules**
4. **Optional user-defined constraints**

The flow consists of three **design extraction modules** followed by a **compaction step**:

```
Layer Mapping --> Constraint Generation --> Device Recognition --> Layout Compaction
```

A key architectural choice is the heavy reuse of the industry-standard **Calibre** physical verification suite [9], which provides:
- Handling of all process information files (no re-implementation needed)
- Automatic access to updated process file formats
- High-performance, feature-rich verification engines

#### 5.3.1 Layer Mapping

- Copies all source-process layout layers to corresponding target-process layers using **Calibre DESIGNrev** with a mapping file.
- Mapping can be **one-to-many or many-to-one**, depending on layer definition differences between source and target.
- Adjacent contacts and vias are **merged** to facilitate subsequent compaction (see [[5.6 Constraint Optimization]]).
- In some cases, entire devices must be **replaced** (no one-to-one correspondence exists); see Sect. 5.7.4.
- The mapping rule file is prepared **once per source-target technology pair**.
- Output: a layout that looks like the source but uses target process layers.

#### 5.3.2 Device Recognition

- The target netlist (produced by a separate netlist migration engine) contains **new device dimensions** for the target process.
- The retargeting tool must **identify each physical device** in the source layout and **link it to the corresponding netlist element** -- essentially a layout-versus-schematic (LVS) check.
- Performed using **Calibre nmLVS** with a special rule file.
- Capable of identifying complex structures: **finger transistors, matched transistor pairs**, and linking them to single devices.

#### 5.3.3 Constraint Generation

- Source layout design rules must be **translated** to target process rules and formulated as **layout constraints** for the compaction engine.
- This is **not a one-to-one translation**: design rules change considerably between processes.
- Uses **Calibre nmDRC** in a special internal mode that transforms design rules into layout constraints via a modified rule file. This masks constraint complexity and leverages industrial DRC technology.
- **Constraint count** has a huge impact on compaction efficiency and accuracy; redundancy must be minimized (see [[5.6 Constraint Optimization]]).
- In addition to design-rule constraints, **updated device dimension constraints** (new transistor $W$ and $L$) from the netlist migration engine are also imposed on physical device dimensions.
- Layout migration = design-rule constraints + device dimension constraints applied to the layer-mapped layout via compaction.

### 5.4 Layout Compaction Methodologies: Background

**Compaction** minimizes total layout area while satisfying all design-rule constraints. The two foundational approaches:

#### 5.4.1 The Constraint-Graph Approach

A **one-dimensional compaction technique** using a directed graph to capture design-rule constraints [13].

**Formulation.** During horizontal compaction, each element is represented by the $x$-coordinates of its edges. A minimum-distance design rule between two elements is expressed as:

$$x_j - x_i \geq d_{ij} \quad \text{where } i, j \in \{1 \ldots k\}$$

where $d_{ij}$ is the minimum-distance spacing between elements at $x_j$ and $x_i$.

**Graph construction** from the constraint set $G(V, E)$:
- **Vertices**: one vertex $v_i$ per variable $x_i$
- **Edges**: a directed edge from $x_i$ to $x_j$ for each inequality $x_j - x_i \geq d_{ij}$, with edge weight $w(i, j) = d_{ij}$
- **Source vertex** $v_0$ at $x = 0$, connected to all vertices with no left-side constraints
- **End vertex** $v_n$ after the last layout edge, connected from all vertices with no right-side constraints
- All layout elements are assumed to have positive $x$-coordinates
- A constraint-graph with only minimum-distance constraints is a **directed acyclic graph (DAG)**

**Solving: Longest-path algorithm** [14]:
- Starting from $v_0$, find the **longest path** to each vertex $v_i$
- Sum all path weights and assign the result to $x_i$
- This guarantees all inequalities involving $x_i$ are satisfied
- The longest-path value gives the **minimal possible coordinate** for vertex $v_i$

**Advantages:**
- Computationally simple and efficient

**Drawbacks:**
1. **Long wire problem**: all elements are pushed as close as possible to the left boundary. Gate contacts and enclosing metal migrate to the leftmost edge, creating unnecessarily long wires. This damages layout shape, increases parasitics, and negatively affects subsequent compaction in the orthogonal direction. Addressed in [15, 16].
2. **Only two-variable constraints**: the graph structure inherently supports only inequalities of the form $x_j - x_i \geq d_{ij}$. However, **matching and symmetry constraints** require multi-variable constraints of the form:

$$x_b - x_a = x_d - x_c \quad \text{where } a, b, c, d \in \{1 \ldots k\}$$

And hierarchical layouts further increase the variable count per constraint [17].

#### 5.4.2 Linear Programming: The Simplex Method

One-dimensional compaction can be formulated as two **separate LP problems** (one per dimension). Decision variables are all element coordinates $x_1, x_2, \ldots, x_k$.

**General LP formulation:**

$$\text{Minimize } f(x_1, x_2, \ldots, x_k)$$
$$\text{subject to } f_i(x_1, x_2, \ldots, x_k) \leq d_{f_i}, \quad i = 1 \ldots m$$
$$x_1, x_2, \ldots, x_k \geq 0$$

Constraints beyond two variables are called **multivariable** or **nondistance constraints**. All constraints are reformulated as $\leq$ via algebraic manipulation [18].

**Slack variables.** Each inequality is converted to an equality by adding a slack variable $x_{k+i}$:

$$x_{k+i} = d_{f_i} - f_i(x_1, x_2, \ldots, x_k)$$

**Matrix form:**

$$\text{Minimize } f = \mathbf{c}^T \mathbf{x}$$
$$\text{subject to } \mathbf{A}\mathbf{x} = \mathbf{d}, \quad \mathbf{x} \geq 0$$

where:
- $\mathbf{x}$: $(n \times 1)$ vector of all variables (location + slack), $n = k + m$
- $\mathbf{c}$: $(n \times 1)$ coefficient vector for the objective function
- $\mathbf{A}$: $(m \times n)$ constraint coefficient matrix
- $\mathbf{d}$: $(m \times 1)$ constant term vector

**Basic Feasible Solution (BFS)** (Definition 5.1): A solution with $m$ constraints and $n$ variables that:
- Satisfies all $m$ constraints
- Has $m$ **basic variables** with values $\geq 0$
- Has $k = n - m$ **nonbasic variables** with value zero

**Simplex iteration.** Separate basic ($\mathbf{x}_B$) and nonbasic ($\mathbf{x}_N$) variables. The problem becomes:

$$\text{Minimize } f = \mathbf{c}_B^T \mathbf{x}_B + \mathbf{c}_N^T \mathbf{x}_N$$
$$\text{subject to } \mathbf{B}\mathbf{x}_B + \mathbf{N}\mathbf{x}_N = \mathbf{d}, \quad \mathbf{x}_B, \mathbf{x}_N \geq 0$$

Key derived quantities:
- **Basic variable values**: $\mathbf{x}_B = \mathbf{B}^{-1}\mathbf{d}$
- **Cost rate vector** (relative cost of each nonbasic variable):

$$\mathbf{z} = \mathbf{c}_N - (\mathbf{B}^{-1}\mathbf{N})^T \mathbf{c}_B$$

- **Objective function**: $f = \mathbf{z}^T \mathbf{x}_N + \mathbf{c}_B^T \mathbf{B}^{-1}\mathbf{d}$

**Simplex algorithm steps:**
1. Obtain an initial BFS
2. Construct the simplex problem in matrix form
3. Calculate basic variable values via $\mathbf{x}_B = \mathbf{B}^{-1}\mathbf{d}$
4. Calculate cost rate vector $\mathbf{z}$
5. **Entering variable** $x_e$: the nonbasic variable with the most negative value in $\mathbf{z}$. If all $z_i > 0$, the current solution is optimal -- stop.
6. **Leaving variable** $x_l$: determined by the **minimum ratio test**:

$$\frac{x_l}{\Delta x_l} = \min\left(\frac{x_i}{\Delta x_i} \;\middle|\; \Delta x_i > 0, \; 1 \leq i \leq m\right)$$

   where $\Delta \mathbf{x}_B = \mathbf{B}^{-1}\mathbf{N}\mathbf{a}_e$ is the step vector and $\mathbf{a}_e$ is a unit vector at the entering variable position.
7. Update $\mathbf{B}$ and $\mathbf{N}$ matrices to reflect the swap
8. Go to step 3; repeat until optimal

**Performance note:** The simplex method is efficient when variables and constraints are limited. The main bottleneck is computing $\mathbf{B}^{-1}$, needed in steps 3, 4, and 6. **LU factorization** [18] helps when $\mathbf{B}$ is sparse (most elements zero), which tends to be the case when minimum-distance constraints dominate. However, for complex industrial layouts, the pure simplex method is **very time-inefficient** compared to graph-based techniques.

#### 5.4.3 Graph-Based Simplex Methods

Several hybrid methodologies combine graph efficiency with LP generality [16, 19-21]:

- **Marple et al.** [16]: graph-based simplex supporting only minimum-distance constraints plus a special objective that minimizes long wiring lengths.
- **Onozawa** [19]: efficient graph-based algorithm supporting distance constraints and multivariable constraints limited to **three variables**.
- **Wang and Lai** [20]: more general graph-based method using graph operations to speed up $\mathbf{B}^{-1}$ computation. Uses a **reduced core matrix** whose size is proportional to the number of multivariable constraints. Outperforms pure simplex when multivariable constraints are fewer than distance constraints. **Limitations**: no general procedure for initial feasible solutions with generic multivariable constraints; objective function restricted to a single variable.

**Conclusion from the survey**: existing graph-based methods remain limited either in objective function form or in the types of constraints supported. The **multivariable constraint-graph based simplex method** presented in Sect. 5.5 alleviates both limitations.

## Algorithms & Methods

### Longest-Path Algorithm (Constraint-Graph Compaction)

```
Input: Constraint-graph G(V, E), source vertex v_0
Output: Minimal x-coordinates for all vertices

1. Initialize x_0 = 0
2. Topologically sort G (it is a DAG)
3. For each vertex v_i in topological order:
     x_i = max over all predecessors v_j of (x_j + d_ji)
     // i.e., longest path from v_0 to v_i
4. The total layout width = x_n (value at end vertex)
```

- **Complexity**: $O(V + E)$ -- linear in graph size, making it extremely efficient
- **Limitation**: produces the long-wire problem; does not support multi-variable constraints

### Simplex Method for Layout Compaction

See the detailed 8-step algorithm above in Section 5.4.2. Key characteristics:
- Supports **arbitrary linear constraints** including symmetry ($x_b - x_a = x_d - x_c$) and hierarchy
- Supports **arbitrary linear objective functions**
- **Complexity**: worst-case exponential in the number of constraints, but typically polynomial for practical layout problems
- **Bottleneck**: $\mathbf{B}^{-1}$ computation at each iteration

### Hybrid Graph-Based Simplex (Preview of Section 5.5)

The chapter's main contribution is a **multivariable constraint-graph based simplex method** that:
- Uses a novel **coefficient constraint-graph** (Definition 5.2) as a signal flow graph to replace matrix operations
- Supports all forms of linear objectives and linear constraints
- For simple constraints (distance only), complexity approaches that of graph-based methods ($O(V + E)$)
- For complex constraints, complexity approaches that of the simplex method
- Detailed in [[5.5 Multivariable Constraint-Graph Simplex Method]]

## Connections to Bigger Picture

This sub-chapter establishes the **motivation and theoretical foundation** for analog layout retargeting, bridging between the routing techniques of Chapter 4 and the core algorithmic contribution of the chapter (the multivariable constraint-graph simplex method in Sect. 5.5). The retargeting flow in Sect. 5.3 shows how industrial tools (Calibre suite) are integrated into the migration pipeline -- a pragmatic approach that distinguishes this work from purely academic methods. The constraint-graph vs. LP comparison in Sect. 5.4 sets up the central tension of the chapter: graph methods are fast but limited to two-variable distance constraints, while the simplex method is general but slow. The rest of Chapter 5 resolves this tension with a hybrid algorithm. This chapter also connects to the broader theme of Part III (Layout in the Design Flow), where layout is treated not as an isolated step but as part of an end-to-end design methodology that must preserve analog design intent across process nodes.
