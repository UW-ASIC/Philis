# 1.1 Introduction to Device-Level Analog Placement

> **Chapter 1**: Device-Level Topological Placement with Symmetry Constraints (Florin Balasa)
> **Part**: Part I: Placement

## Key Concepts

### 1.1.1 CAD for Analog Layout

- Modern **systems-on-a-chip (SoC)** integrate analog, digital, and RF sections on one die. While digital CAD is mature and largely automated (Boolean representations, algorithmic modeling), **analog CAD lags significantly behind**.
- Reasons analog automation is harder:
  - Analog design is **less systematic and more heuristic** than digital, requiring specialized knowledge and years of experience.
  - Analog circuits are **more sensitive** to parasitic disturbances, crosstalk, substrate noise, and supply noise.
  - Greater variety of schematics, device sizes, and shapes.
- As a result, analog designs are still largely **handcrafted** with limited CAD support beyond simulators and interactive layout editors.
- The analog physical implementation step splits into two areas:
  1. **Circuit-level (block-level) layout synthesis** -- transforming a sized transistor-level schematic into a mask layout.
  2. **System-level layout assembly** -- floorplanning, placing, and routing already laid-out functional blocks, plus power/ground distribution.
- This chapter focuses on **optimization-based place-and-route** approaches, which differ from:
  - **Procedural module generation** -- layout is precoded in software, generated for given parameter values at run time.
  - **Template-driven methods** -- a geometric template fixing relative positions and interconnections is stored per circuit. Less flexible, but effective when expert-designed templates are available.

### 1.1.2 The Device-Level Analog Placement Problem

- Packing a set of fixed-oriented rectangles (with real-valued widths and heights) onto a chip of known dimensions is **NP-complete**; finding the minimum-area packing is **NP-hard**.
- Beyond basic rectangle packing, an analog placement tool must handle:
  1. **Topological constraints for symmetry and device matching** -- ensuring differential paths have balanced parasitics.
  2. **Device merging / geometry sharing** -- overlapping devices in beneficial ways to reduce layout density and induced parasitics.
  3. **Module generators with reshaping capabilities** -- exploiting a library of predefined module generators during placement.

### 1.1.3 Overview of Analog Placement Methods

- **Constructive approaches**: Evolve the placement by selecting one module at a time and placing it in the "best" available location.
  - Examples: Kayal et al. (expert knowledge base), Mehranfar (schematic-driven).
  - **Pros**: Fast, scales well with problem size.
  - **Cons**: Dependent on device selection order; lacks global view, yielding poor solutions.
- **Min-cut partitioning + force-directed placement**: Iteratively combines partitioning and force-directed methods for better global optimization.
- **Constrained combinatorial optimization**: Translates the placement problem into an optimization problem.
  - Earlier techniques: hard and soft nonquantitative constraints.
  - Later approaches: **performance-driven**, using estimation models to evaluate placement solutions quantitatively.
- **Stochastic optimization engines**:
  - **Simulated annealing** (SA) -- the most mature stochastic technique. Uses stochastically controlled "hill-climbing" to avoid local minima. Used in: **ILAC**, **KOAN/ANAGRAM II** (evolved into NeoLinear), **PUPPY-A**, **LAYLA**.
  - **Genetic algorithms** (GA) -- similar hill-climbing properties.
  - **Advantages**: No severe constraints on problem size or cost function mathematical properties; support incremental addition of new functionality; relatively easy to implement.
  - **Disadvantages**: Require careful tuning.
- **Two-phase approaches**: Combining GA and SA with dynamic parameter adjustment.
- **Template-driven tools**: Built on databases of expert-designed analog circuits. Given a new design, the system selects a suitable template and re-generates the layout for the target technology and device sizes.

### 1.1.4 Placement for Layout Symmetry

Symmetry in placement is critical because:
- **Differential circuits** require matched layout parasitics in the two halves of the differential signal path. Failure leads to higher offset voltages and degraded power-supply rejection ratio (PSRR).
- **Thermal gradient sensitivity**: Bipolar devices (especially) are sensitive to ambient temperature. Symmetrically placed devices are equidistant from thermally radiating components, eliminating temperature-induced mismatch.

**Three forms of symmetry**:

1. **Mirror symmetry** -- Cells in every pair have identical geometry and **mirror-symmetric orientation** about a common axis. The most standard form.
   - Advantages: (a) sibling devices forced to have identical geometry $\Rightarrow$ device-related parasitics are balanced; (b) aligns terminals for mirror-symmetric routing.

2. **Perfect symmetry** -- Paired devices have **identical** (not mirrored) orientations. Required for very stringent matching (e.g., anisotropic fabrication disturbances like oblique-angle ion implantation).
   - Disadvantage: Terminals are no longer mirror-symmetric, so routing must use **parasitic-matched (but not geometrically symmetric) wires** -- significantly harder.

3. **Self-symmetry** -- A device has geometrical symmetry and shares the symmetry axis with other symmetric pairs. Two uses:
   - Placing asymmetric devices (e.g., bias networks) in the middle of a mirror-symmetric layout, simplifying wiring.
   - Creating thermally symmetric layouts.

**Symmetry group**: A subset of cells all exhibiting symmetry and sharing a **common symmetry axis**. For a pair $(B_i, B_j)$ in the $k$-th symmetry group, the constraints are:

$$(x_i + w_i) + x_j = 2 \cdot x_{\text{symAxis}_k} \quad \text{and} \quad y_i = y_j$$

where $(x_i, y_i)$ are the left-bottom coordinates of device $B_i$ and $w_i$ is its width. For a **self-symmetric** device $B_i$:

$$x_i + \frac{w_i}{2} = x_{\text{symAxis}_k}$$

> The symmetry axes are typically considered **vertical**, as this is how most layouts are designed.

### 1.1.5 The Absolute (Flat) Representation

- Cells are specified in terms of **absolute coordinates** on a plane. Moves are simple translations (coordinate shifts) or changes in cell orientation (rotations, mirrors).
- Cells **are allowed to overlap illegally** -- no restriction on relative cell positions. A **quadratic penalty cost** is associated with illegal overlap, driven to zero during optimization.
- **Advantages**:
  - Well-suited for device matching and symmetry constraints (easy to model and maintain).
  - Allows exploration of beneficial device overlaps (device merging).
  - Inherently simple.
  - Used in **KOAN/ANAGRAM II**, **PUPPY-A**, **LAYLA**.
- **Shortcomings**:
  - **Slow optimization**: Exploration space is very large; many moves yield small cost decreases.
  - **Non-zero overlap in final solution**: Post-processing needed to eliminate gaps and overlaps, degrading solution quality and computation time.
  - **Weight tuning problem**: The overlap penalty weight must be carefully chosen -- too large impedes the search for good placement; too small lets cells collapse. The TimberWolf system used a "negative control scheme" to determine optimal weights.
- The flat representation trades a **larger number of moves** for **easier/quicker** (but not always physically realizable) layout constructions.

### 1.1.6 Topological Representations of the Layout

In contrast to flat representations, **topological representations encode cell positions relatively**, based on topological relations between cells. Cells cannot overlap illegally, improving optimization efficiency.

- **Slicing model** (Otten, 1982): Cells organized in recursively bisecting slices recorded in a **slicing tree** or **normalized Polish expression**. The annealing moves are modifications to the encoding (not explicit cell translations).
  - **Limitation**: Restricts reachable layout topologies, degrading density when cells vary greatly in size (common in analog). Symmetry constraints are difficult to maintain between moves (must be modeled in cost function via "virtual symmetry axes").

- **Post-1995 non-slicing representations**:

| Representation | Authors | Evaluation Complexity | Key Property |
|---|---|---|---|
| **Sequence-pair** | Murata et al. | $O(n^2)$ originally; $O(n \log \log n)$ latest (Tang et al.) | Encodes "left-right" and "above-below" relations via two cell permutations |
| **Bounded-sliceline grid (BSG)** | Nakatake et al. | $O(n^2)$ | Meta-grid without physical dimensions |
| **Ordered tree (O-tree)** | Guo et al. | Linear | Reduces code redundancy vs. sequence-pair and BSG |
| **Binary tree** | Chang et al. / Balasa | Equivalent to O-tree | Based on forest-to-binary-tree correspondence |
| **Corner block list (CBL)** | -- | -- | Encodes mosaic (zero dead-space) floorplans |
| **Transitive closure graph (TCG)** | Lin and Chang | -- | Two directed graphs; edges = horizontal/vertical relations |

- Key distinction: Tree representations (O-tree, binary tree) define topological relations that **depend on cell dimensions**, while sequence-pair, BSG, CBL, and TCG define relations **independent of dimensions**.

### 1.1.7 Selecting a Topological Representation for Analog Placement

**Selection criteria** beyond the usual block-placement concerns:

1. **Low/zero code redundancy** -- smaller exploration space.
2. **Efficient evaluation algorithm** -- preferably linear complexity, to build the placement from the encoding quickly at each SA inner-loop iteration.
3. **Ability to handle symmetry constraints** -- this is the critical analog-specific criterion.

**The symmetry feasibility problem**: Most codes in any topological representation are **infeasible from a symmetry standpoint**. In preliminary experiments with sequence-pairs, simply discarding symmetric-infeasible codes during SA exploration proved "extremely ineffective" because infeasible codes overwhelmingly outnumber feasible ones.

**Key questions** a good topological representation must answer:
- How to **recognize** codes complying with symmetry constraints **without building the layout**?
- How to **prevent** the annealer from moving to an infeasible code once on a feasible one?
- How to **restrict exploration** to the subspace of **symmetric-feasible codes**?

> A topological representation is a good candidate if it possesses a **characterizing property** for codes that generate placements satisfying symmetry constraints. Without such a property, even linear-complexity evaluation is of lesser importance since most codes would be infeasible.

**Approaches developed** for handling symmetry in topological representations:
- **Sequence-pairs**: [[1.3 Symmetric-Feasible Sequence-Pairs]] -- a subset of sequence-pairs proven to be symmetric-feasible.
- **Trees**: Exploiting properties of ordered tree codes to detect and discard infeasible codes efficiently.
- **Transitive closure graphs**: Separate handling of symmetry within the TCG framework.

> Note: Symmetry constraints affect evaluation complexity. For example, the evaluation algorithm with symmetry handling in one approach is $O(n^2)$, whereas the base O-tree evaluation without symmetry is $O(n)$.

## Algorithms & Methods

### Segment Tree for Computing Device Abscissae

The segment tree is used to compute the $x$-coordinates of devices when the $y$-coordinates are already known. It represents the **right border contour** of the partial placement and is updated as each device is placed.

**Overall complexity**: $O(n \log n)$ (dominated by sorting the $y$-coordinate endpoints).

**Algorithm outline**:

```
1. Initialize all abscissae: x_i = 0
2. Sort the set S = Union_i {y_i, y_i + h_i}, eliminate duplicates -> m elements
3. Create root node v0 with interval [0, m-1] and value x = 0
4. For each cell B_i (in topological sort order):
   a. Let a_i = index of y_i in S, b_i = index of (y_i + h_i) in S
   b. UpdateSegmentTree(v0, [a_i, b_i])   -- computes x_i
   c. UpdateRightContour(v0, [a_i, b_i])  -- sets standard nodes to x_i + w_i
5. W = max{v.x} over all v in SegmentTree  -- placement width
```

**UpdateSegmentTree** decomposes the normalized interval $[a_i, b_i]$ into standard intervals in the segment tree, computing $x_i$ as the maximum $v.x$ over all standard-interval nodes:

```
procedure UpdateSegmentTree(v, [a_i, b_i]):
  if v.I subset of [a_i, b_i]:
    if v.x > x_i: x_i = v.x        // take maximum
  else:
    let [c, d] = v.I, mid = floor((c+d)/2)
    if v is a leaf:
      create children with intervals [c, mid] and [mid, d]
    if a_i < mid: UpdateSegmentTree(v.left, [a_i, b_i])
    if mid < b_i: UpdateSegmentTree(v.right, [a_i, b_i])
```

**UpdateRightContour** updates the segment tree to reflect the new right border:

```
procedure UpdateRightContour(v, [a_i, b_i]):
  if v.I subset of [a_i, b_i]:
    v.x = x_i + w_i                 // right edge of new cell
  else:
    let [c, d] = v.I, mid = floor((c+d)/2)
    if a_i < mid: UpdateRightContour(v.left, [a_i, b_i])
    if mid < b_i: UpdateRightContour(v.right, [a_i, b_i])
```

**Key implementation detail**: In a simulated annealing framework, the segment tree should be created **once** (with root interval $[0, n]$) and **re-initialized** at each inner-loop iteration, rather than rebuilt from scratch. Since $[0, k] \subseteq [0, n]$ for any iteration's root interval $[0, k]$, the same tree structure can be reused. This reduces computation time by **15--20%**.

**Per-cell complexity**: Each call to UpdateSegmentTree and UpdateRightContour is $O(\log n)$ because the segment tree depth is at most $\lceil \log_2(m-1) \rceil \leq \lceil \log_2 n \rceil$.

## Connections to Bigger Picture

This introductory section sets the stage for the entire chapter by motivating **why topological representations matter** for analog placement -- the key insight being that flat (absolute) representations, while simple, suffer from enormous search spaces and non-physical intermediate solutions. The symmetry feasibility problem is the central challenge: most topological codes are infeasible under symmetry constraints, making naive exploration useless. The chapter will next present the **data structures** needed for efficient topological evaluation ([[1.2 Data Structures for Rectilinear Border Contours]]), followed by the **symmetric-feasible sequence-pair** formulation ([[1.3 Symmetric-Feasible Sequence-Pairs]]) that restricts exploration to only valid codes. The broader book (Graeb, 2011) surveys multiple topological approaches across placement, routing, and sizing -- this chapter by Balasa covers the foundational placement layer upon which routing and performance optimization build.
