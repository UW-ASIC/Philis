# 5.7 Practical Retargeting

> **Chapter 5**: Analog Layout Retargeting (Said, Dessouky, El-Adawi, Abbas, Shahein)
> **Part**: Part III: Layout in the Design Flow

## Key Concepts

Section 5.7 addresses the **complementary modules** required beyond the core compaction algorithm (the [[5.5 Multivariable Constraint-Graph Simplex Method]]) to handle industrial-level layout complexity in process migration. The central argument is that the multivariable graph-based simplex method provides a unified framework into which all of these practical concerns integrate naturally, thanks to its ability to handle arbitrary linear constraints with any number of variables.

### 5.7.1 Symmetry Enforcement

- **Why it matters**: Analog design relies on *relative* component accuracy (matching) rather than absolute accuracy, because IC components have large tolerances from process and temperature variations. Layout symmetry and matching strategies must be **detected** in the source layout and **replicated** in the target.
- **Symmetry detection**: For small layouts, symmetry constraints can be identified manually. For large hierarchical layouts, multilevel symmetry detection (Bhattacharya et al.) uses the circuit structure and hierarchy from the extracted netlist.
- **The core problem**: Standard graph-based compaction techniques (constraint-graph + longest path) only support two-variable minimum-distance constraints of the form $x_j - x_i \geq d_{ij}$. Symmetry constraints have the multivariable form:
  $$x_b - x_a = x_d - x_c$$
  which cannot be represented in a standard directed acyclic constraint-graph.
- **Prior compromise (Okuda et al.)**: Solve the main problem with graph-based techniques, then construct a separate reduced LP problem for symmetry constraints and solve it with the revised simplex method. Once satisfied, convert symmetry constraints to simpler distance constraints and feed them back into the main graph. **Limitation**: still cannot handle general multivariable constraints, and the optimization function is restricted to a very simple form.
- **Solution**: The multivariable graph-based simplex algorithm (Sect. 5.5) overcomes all of these problems -- it supports any kind of linear constraint and allows complex objective functions simultaneously.

### 5.7.2 Device Aspect Ratio

- **Problem**: When migrating between processes, device dimensions can change dramatically even when the same electrical performance is conserved. Device characteristics (threshold voltage, oxide thickness, mobility) differ across technology nodes, causing large changes in device area and aspect ratio.
- **Consequence**: The initial relative device placement, optimized for the source layout, may no longer be optimal. This leads to **wasted area** after migration (empty corners appear due to changed device shapes under the same relative placement).
- **Ideal solution**: Two-dimensional compaction could rearrange devices (e.g., move device A to a different corner). However, 2-D compaction is **NP-complete**, making it infeasible for practical layouts.
- **Practical solution (Okada et al.)**: Change the **device aspect ratio** while keeping the same relative placement. This is done by investigating different realizations for each device -- for example, varying the **number of transistor fingers**. Devices are then replaced by their new realizations (see Sect. 5.7.4). This yields far better area utilization than naive migration without requiring full 2-D compaction.

### 5.7.3 Layout Hierarchy

- **Goal**: Preserve layout hierarchy during migration. Hierarchical compaction was first treated by Marple by formulating the problem as LP.
- **Key technique**: Express edge locations inside hierarchical cells by their **relative position** with respect to their cell origin, rather than absolute (flattened) coordinates. If an edge is at distance $x_{\text{edge}_k^i}^{\text{cell}}$ from the cell origin placed at absolute position $x_{\text{cell}_k}$, the edge location is:
  $$x_{\text{cell}_k} \pm x_{\text{edge}_k^i}^{\text{cell}}$$
- **Benefit**: The cell location variable $x_{\text{cell}_k}$ cancels out of all **intracell constraints**, so intracell constraints appear only once in the constraint set regardless of how many times the cell is instantiated. This both preserves hierarchy and reduces variable count.
- **Multi-level hierarchy**: For an $n$-level hierarchical structure, an edge is represented as:
  $$x_{\text{cell}_i}^{\text{top}} \pm x_{\text{cell}_i}^{\text{level 1}} \cdots \pm x_{\text{cell}_i}^{\text{level } n} \pm x_{\text{edge}_i}$$
- **Trade-off**: This increases the number of variables per linear constraint equation. Lee & Tang further modified the algorithm to trim both the number of variables and equations.
- **Fit with the algorithm**: The multivariable graph-based simplex method is a natural fit because it has **no limitations** on the number of variables in each constraint, requiring no artificial techniques to limit this number.

### 5.7.4 Device Replacement

- **When needed**: Some devices have different structures and/or layers between source and target processes. Examples include:
  - Changing the number of fingers of a transistor
  - POLY resistors not supported in the target process
- **Solution**: Replace the entire device with a new one from the target technology design kit, using **parameterized cells (Pcells)** where the new device is regenerated via a Pcell script.
- **Methodology (Batterywala et al.)**: Based on the ability to describe the entire hierarchical layout using multivariable LP constraints (as in Sect. 5.7.3). The cell-swapping approach fits naturally into the compaction-based migration framework.

### 5.7.5 Layout Parasitics

- **Impact**: Layout parasitics significantly affect analog performance, especially on **matched nets**. This effect is magnified in modern process technologies where parasitic control is worsening.
- **Parasitic-aware retargeting (Zhang et al.)**: Uses **nonlinear optimization** to constrain layout parasitics within predetermined bounds during retargeting. Most useful for **high-frequency and RF designs**.
- **When compaction suffices**: If the source layout was carefully designed with minimized and matched parasitics on sensitive nets, and device dimensions do not change significantly, the target layout has a high probability of satisfying the same parasitic constraints. Compaction objective functions that **privilege closeness to the source layout** (Bhattacharya et al.) help keep parasitics under control.

## 5.8 Examples

The section presents several migration examples that validate the multivariable graph-based simplex method:

### Miller Opamp and Folded-Cascode Opamp

Both migrated from **0.35 um to 0.18 um** process. New device sizes were calculated using netlist migration tools. Symmetry constraints were included.

| Case | Dir | # Variables | # Constraints | Avg. Iter. Time (ms) Graph | Avg. Iter. Time (ms) Simplex | Total Time (s) Graph | Total Time (s) Simplex |
|------|-----|-------------|---------------|---------------------------|-----------------------------|-----------------------|------------------------|
| Miller opamp | X | 521 | 1,831 | 2.517 | 4.555 | 0.375 | 3.594 |
| Miller opamp | Y | 521 | 2,067 | 1.164 | 5.175 | 0.234 | 4.265 |
| Folded-cascode | X | 2,431 | 8,599 | 9.270 | 21.492 | 8.232 | 91.345 |
| Folded-cascode | Y | 2,443 | 11,495 | 7.260 | 28.297 | 7.391 | 118.141 |

**Key observations**:
- The graph-based method is **2-4x faster per iteration** and **10x+ faster in total time** than the revised simplex method.
- The X-direction iteration time is higher than Y despite fewer constraints, because CPU time depends on graph complexity (number of loops to remove), not just problem size.
- The total speedup comes from both faster iterations *and* fewer iterations (due to a good initial solution from the longest-path algorithm, Sect. 5.5.2.3).
- **Miller opamp**: source area 6,060 um^2, target area 2,800 um^2.
- **Folded-cascode**: source area 10,270 um^2, target area 4,445 um^2. Some empty area remains due to nonrelevant edge-constraints (Sect. 5.6 edge-order problem).

### VCO Example (130 nm to 65 nm)

- Demonstrates the **edge-order problem**: after migration, the MOS capacitor device on the left was greatly reduced relative to devices at the top-right, creating empty space. Due to maintained edge-order constraints, devices could not be moved to fill the gap.
- **Fix**: Manual deletion of problematic edge-order constraints, or running a second compaction pass (regenerating constraints from the first result).

### Astable Oscillator (0.6 um to 0.25 um)

- Most complex example: ~500 devices including a bandgap reference, biasing cells, digital decoder for trimming, amplifier, and comparators.
- Some capacitors and resistors were **completely replaced** by different device kinds (demonstrating device replacement, Sect. 5.7.4).

| Direction | # Edges | # Min. Constraints | # Symmetry/Equal Constraints | # Iterations |
|-----------|---------|--------------------|-----------------------------|-------------|
| X | 14,495 | 71,197 | 2,857 | 6,750 |
| Y | 14,469 | 75,494 | 2,676 | 6,540 |

This confirms that minimum-distance constraints vastly outnumber symmetry/equal constraints (the $u \gg v$ regime from the complexity analysis), validating the near-linear complexity of the graph-based algorithm in practice.

## 5.9 Conclusion

The chapter concludes that **compaction-based layout retargeting** with an appropriate objective function is one of the most suitable techniques for analog layout process migration, as it preserves the physical design knowledge embedded in the original layout. The multivariable graph-based simplex algorithm combines:
- The **efficiency** of graph-based methods (near-linear complexity when $u \gg v$)
- The **generality** of LP methods (arbitrary multivariable constraints and objective functions)

**Complexity characterization**:
- **Best case** (only distance constraints, $v = 0$): $O(k + k_f + u)$ -- same linear complexity as longest-path
- **Typical case** ($u \gg v$): $O(k + k_f + u)$ for connection values, $O(v \cdot p \cdot u)$ for loop elimination -- still manageable
- **Worst case** ($u \ll v$, $p = N$): $O(v^3)$ -- same as matrix-based simplex

## Algorithms & Methods

### Compaction-Based Retargeting Pipeline (Fig. 5.1)

The retargeting tool consists of several modules, all integrating through the multivariable graph-based simplex method:

1. **Layer Mapping** -- Map source layout layers to target process layers (Sect. 5.3.1). Merge contact/via arrays into single large contacts to reduce constraint count.
2. **Constraint Generation** -- Extract minimum-distance, symmetry, equal, and hierarchical constraints from the layout. Use DRC tools (e.g., Calibre nmDRC) to capture complex design rules.
3. **Device Size Recalculation** -- Compute new device dimensions for the target process using netlist migration tools.
4. **Device Replacement** -- Replace devices that cannot be simply remapped (e.g., POLY resistors, transistors requiring different finger counts) using Pcells.
5. **Compaction** -- Solve the LP problem using the multivariable graph-based simplex method with symmetry, hierarchy, and equal constraints.
6. **Post-processing** -- Reconstruct contact/via arrays from merged contacts; apply any manual edge-order constraint fixes.

### Symmetry Constraint Handling

Symmetry constraints of the form $x_b - x_a = x_d - x_c$ are rewritten as:

$$x_b - x_a - x_d + x_c = 0$$

and represented directly in the coefficient constraint-graph as a node with four variable arcs (coefficients +1, -1, -1, +1). If the initial solution from longest-path does not satisfy the constraint, an artificial variable $a_i$ is added and penalized with a large constant $M$ in the objective function (Big-M method), ensuring it drops to zero in the optimal solution.

### Hierarchical Constraint Formulation

Edge positions expressed relative to cell origins:

$$x_{\text{absolute}} = x_{\text{cell}}^{\text{top}} \pm x_{\text{cell}}^{\text{level 1}} \cdots \pm x_{\text{cell}}^{\text{level } n} \pm x_{\text{edge}}$$

This creates multivariable constraints (one variable per hierarchy level plus the edge variable) that the graph-based algorithm handles natively.

## Connections to Bigger Picture

This section bridges the theoretical compaction algorithm of Chapter 5 (the multivariable graph-based simplex method) with the practical demands of industrial analog layout migration. It demonstrates that symmetry, hierarchy, device replacement, and parasitic awareness -- features essential for real-world retargeting -- all reduce to multivariable linear constraints that the proposed algorithm can handle in a unified framework. The examples validate that the algorithm scales to industrial complexity (~500 devices, ~75,000 constraints) while maintaining a 10x speedup over pure simplex methods. The discussion of layout parasitics in Sect. 5.7.5 directly connects to Chapter 6's [[6.1 Introduction to Layout-Aware Sizing]], where parasitic-aware synthesis is the central theme: Chapter 5 addresses parasitics *after* sizing (during migration), while Chapter 6 brings them *into* the sizing loop.
