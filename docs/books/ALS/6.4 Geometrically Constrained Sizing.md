# 6.4 Geometrically Constrained Sizing

> **Chapter 6**: Layout-Aware Sizing (Castro-Lopez, Roca, Fernandez)
> **Part**: Part III: Layout in the Design Flow

## Key Concepts

### 6.4.1 Floorplan Sizing

The **floorplan-sizing problem** is the geometry optimization problem for integrated circuits. Given a set of device sizes (e.g., transistor $W$ and $L$) and the fact that each device can be laid out in multiple ways (different geometric parameter values), the problem is to find:

1. **Placement**: the relative arrangement of devices (already fixed by the [[6.3 Layout Templates|layout template]])
2. **Geometric Parameter (GP) values**: e.g., the number of fingers of a MOS transistor, strip width of resistors, side length of unit capacitors

...such that some objective function $\Phi(W, H)$ of the total circuit layout width $W$ and height $H$ is minimized.

- **Primary objective**: Minimize total occupied area $\Phi(W, H) = W \times H$
- **Secondary objective**: Minimize **area loss** -- the ratio of unused silicon area (not occupied by blocks, routing wires, or design-rule spacing) to total area. This measures how much further the layout could be compacted with a different placement.

#### Slicing Floorplans

The approach uses **slicing floorplans**, where the layout area is recursively divided into horizontal and/or vertical slices. Represented as **rooted binary trees** (slicing trees) with:

- $m$ nonleaf nodes (slices combining sub-components)
- $n = m + 1$ leaf nodes (building blocks implementing one or more circuit devices)

Advantages of slicing floorplans over nonslicing:

- Easier placement specification via relative positions
- More compact layout instances
- Easier evaluation of routing characteristics
- Naturally eases geometrically constrained sizing

Each leaf node has a **shape function**: the set of Pareto-optimal $(width, height)$ pairs arising from varying its geometric parameters. A Pareto-optimal element has lower width and/or height than all other elements -- no other element is strictly better in both dimensions.

### 6.4.2 Proposed Approach: The GC Module

The **Geometric Constraint (GC) module** performs the floorplan-sizing task using a **modified Stockmeyer's algorithm**. It operates in two phases:

#### Phase 1: Bottom-Up Shape Composition

1. Associate each leaf node with a sorted list of $(h_i, w_i)$ pairs (its shape function), sorted by $h_i > h_{i+1}$ and $w_i < w_{i+1}$.
2. A database of **generators** provides the shape function for each leaf node type (folded transistor, MOS differential pair, cascode group, current mirror, capacitor array, folded resistor), given device sizes and the fabrication process.
3. Combine leaf nodes into vertical ($v$) and horizontal ($h$) nonleaf nodes per the slicing tree using Stockmeyer's rules:
   - For a nonleaf node $v$, the list of $s$ pairs satisfies $s \leq \prod_{i=1}^{L(v)} l_i$, where $L(v)$ is the number of leaf nodes in the subtree and $l_i$ is the cardinality of each leaf's shape function.
   - Only Pareto-optimal pairs are retained (pairs strictly dominated in both dimensions are pruned).
   - Additional template info (physical separation between slices) is incorporated.
4. The result is the **global shape function** of the overall slicing tree.

**Complexity**: $O(d \cdot l_T)$ where $d$ is the depth of the slicing tree and $l_T$ is the sum of shape function cardinalities across all leaf nodes.

The main output is the **floorplan-sizing matrix**: each row is a point in the global shape function, columns include $W$, $H$, area, aspect ratio, and area loss.

#### Phase 2: Top-Down Shape Propagation

All points in the floorplan-sizing matrix that violate user-specified **geometric goals** are removed. Supported goals:

1. **Aspect ratio**: $AR = W/H$ with acceptable deviation $\Delta_{AR}$, so that $AR - \Delta_{AR} \leq W/H \leq AR + \Delta_{AR}$
2. **Maximum/minimum width and/or height** bounds

The row with minimal area meeting all geometric goals is selected. The slicing tree is then traversed **top-down** to recover the $(width, height)$ of each leaf node, from which all GP values are retrieved.

#### Integration with Optimization Loop

The GC module is called at **every iteration** of the optimization engine, before simulation:

1. Optimization engine proposes a circuit sizing (design variables)
2. GC module determines GP values that minimize area and area loss while satisfying geometric goals
3. Complete geometric description enables parasitic extraction
4. Simulator evaluates the circuit with parasitics
5. Area is also included as a design objective in the cost function (equation 6.3), so the evolutionary algorithm naturally drives toward area minimization

### 6.5 Layout-Aware Sizing of AMS Circuits

#### 6.5.1 Completing the Methodology with Parasitic Extraction

Accurate parasitic estimates require complete layout geometry information -- which the GC module provides before extraction. Two approaches for parasitic estimation are implemented:

**Approach A -- Full Geometric + 3-D A-G Extraction:**

- **Transistors**: Geometric methods (direct measurement of diffusion areas and perimeters)
- **Interconnects**: 3-D analytical-geometrical (A-G) methods -- analytical parameterized models for common interconnect configurations, with geometric methods to obtain layout parameters
- Equivalent to commercial parasitic extractors
- Very accurate but traditionally considered slow for optimization loops

**Approach B -- Analytical + Lookup Table Extraction:**

- **Transistors**: Analytical methods computing diffusion capacitances from equations relating area/perimeter to $W$, $L$, number of fingers, layout style, and process data (following the approach in [38])
- **Interconnects**: Layout template **sampling technique** with lookup tables:
  1. **Step 1 (Coarse sampling)**: Generate a reduced number (~100) of layout template instances by sampling $n$ layout parameters with $m$ data points. Extract interconnect parasitics with 3-D A-G methods. Identify and eliminate **noncritical parasitics** (negligible impact on performance).
  2. **Step 2 (Dense sampling)**: Densely sample only the **relevant layout parameters** (those associated with critical parasitics). Parameters with nonsignificant impact use a single sample. Result: $N \ll m^n$ instances generated and extracted; only critical parasitics stored.
- The lookup table is generated **once per template** and remains valid for any sizing process.

**Parasitic extraction taxonomy** (accuracy vs. speed tradeoffs):

| Method | Speed | Accuracy | Notes |
|--------|-------|----------|-------|
| Numerical (Laplace equation) | Slow | High | High computational resources |
| A-G (analytical-geometrical) | Fast | High | 2-D, 2.5-D, or 3-D models |
| Table lookup | Fast | Medium-High | Storage grows with parameter count |
| Geometric (for transistors) | Fast | High | Direct diffusion measurement |

### 6.6 Conclusions

The layout-aware sizing methodology described in this chapter:

- **Minimizes iterations** between electrical and physical design phases in traditional design methodologies
- Is **flexible**: simulation-based optimization applicable to many analog circuit types
- Ensures **accurate performance evaluation** via electrical simulator in the loop
- Guarantees **specification compliance** by including parasitics in sizing
- Enables **realistic area minimization** at both template and global levels
- Supports **geometric goals** (aspect ratio, width/height bounds) as design objectives

**Future directions**:

- Hierarchical decomposition and specification transmission for larger circuits
- Multiobjective optimization (Pareto front of electrical performance vs. layout template efficiency) to enable layout template selection depending on the design space region

## Algorithms & Methods

### Modified Stockmeyer's Algorithm (GC Module)

**Input**: Slicing tree, device sizes, GP ranges, geometric goals
**Output**: Optimal GP values for all devices, minimal area layout

```
Phase 1: Bottom-Up
  for each leaf node:
    compute shape function from generator database
    sort pairs by h_i > h_{i+1}, w_i < w_{i+1}
  for each nonleaf node (bottom-up traversal):
    combine child shape functions per Stockmeyer rules
    prune dominated (non-Pareto-optimal) pairs
    incorporate template spacing info
  result: global shape function -> floorplan-sizing matrix

Phase 2: Top-Down
  remove rows violating geometric goals (AR bounds, W/H limits)
  select row with minimal area
  traverse slicing tree top-down:
    propagate selected (W, H) to each leaf node
    retrieve GP values from shape function
  return: GP values for all building blocks
```

**Complexity**: $O(d \cdot l_T)$

### Parasitic-Aware Optimization Flow

```
1. Optimization engine proposes design variables (W, L, bias currents, etc.)
2. GC module determines geometric parameters (number of fingers, etc.)
3. Parasitic extraction (Approach A or B)
   - Approach A: Full geometric + 3-D A-G extraction
   - Approach B: Analytical transistor models + lookup table for interconnects
4. Netlisting with parasitics
5. HSPICE simulation
6. Performance evaluation against specifications
7. Cost function computation (includes area, power, area loss)
8. Return to step 1 (next iteration of GA or optimization algorithm)
```

### Parasitic-Aware Experiments (Section 6.5.2)

Three experiments on a fully differential opamp (Fig. 6.6) with tighter specs (DC gain >= 110 dB, UGF >= 90 MHz, PM >= 65 deg):

| Metric | Exp. I (no layout info) | Exp. II (Approach B) | Exp. III (Approach A) |
|--------|------------------------|---------------------|----------------------|
| **DC Gain (dB)** | 110.0 (111.0) | 113.0 (113.0) | 111.7 |
| **UGF (MHz)** | 91.8 (89.8) | 105.7 (105.4) | 106.6 |
| **PM (deg)** | 67.6 (63.4) | 65.4 (65.0) | 66.2 |
| **Layout Size** | 195.8 x 358.8 um | 173.8 x 191.25 um | 189.6 x 193.05 um |
| **Aspect Ratio** | 0.55 | 0.91 | 0.98 |
| **Power (mW)** | 7.3 | 8.0 | 8.3 |
| **Iterations** | 2,116 | 2,437 | 3,044 |
| **CPU Time (s)** | 507.8 | 612.3 | 880.3 |

Values in parentheses are post-layout extraction results. Key observations:

- **Exp. I** (no geometry info): Layout has large empty areas, poor compaction, and **specification violations after extraction** (PM = 63.4 deg < 65 deg, UGF = 89.8 MHz < 90 MHz) -- requiring redesign iterations.
- **Exp. II** (Approach B): All specs met post-extraction; ~21% more CPU time than Exp. I.
- **Exp. III** (Approach A): All specs guaranteed by construction; ~15% more CPU time than Exp. II (extraction takes 17% of total sizing time). Demonstrates that full parasitic extraction is feasible within an optimization loop for analog cells with tens of devices.

## Connections to Bigger Picture

The geometrically constrained sizing methodology bridges the gap between electrical sizing (Chapter 5, [[6.1 Introduction to Layout-Aware Sizing]]) and physical layout generation ([[7.1 Introduction to Constraint-Driven Design]]). By embedding floorplan-sizing and parasitic extraction inside the optimization loop, it eliminates the costly back-and-forth iterations between schematic-level and layout-level design that plague traditional analog design flows. The modified Stockmeyer's algorithm provides polynomial-time geometric optimization, making it practical for inclusion in iterative sizing. This work sets the stage for the constraint-driven design methodology of Chapter 7, which formalizes the broader set of analog layout constraints (symmetry, matching, shielding) beyond the geometric/area constraints addressed here. It also connects to the broader theme of Part III: that layout awareness during sizing is essential for first-pass silicon success in analog IC design.
