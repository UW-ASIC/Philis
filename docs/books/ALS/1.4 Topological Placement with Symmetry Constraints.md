# 1.4 Topological Placement with Symmetry Constraints Using Other Layout Representations

> **Chapter 1**: Device-Level Topological Placement with Symmetry Constraints (Florin Balasa)
> **Part**: Part I: Placement

This section evaluates alternative topological representations -- transitive closure graphs (TCGs) and tree-based representations (O-trees / binary trees) -- for analog placement with symmetry constraints, comparing them against the [[1.3 Symmetric-Feasible Sequence-Pairs|symmetric-feasible sequence-pair]] approach presented earlier.

---

## Key Concepts

### 1.4.1 Comparative Overlook on Transitive Closure Graphs

The **transitive closure graph (TCG)** representation, introduced by Lin and Chang, encodes placement using two directed graphs:

- **$C_h$** (horizontal TCG): arc $(A, B)$ means cell $A$ is to the left of cell $B$.
- **$C_v$** (vertical TCG): arc $(A, B)$ means cell $A$ is below cell $B$.
- Every pair of vertices must be connected by exactly one edge in either $C_h$ or $C_v$ (but not both).

#### Equivalence with Sequence-Pairs

A critical insight (noted by Zhang and El-Masry, and by the TCG authors themselves) is that **TCG and sequence-pair representations are equivalent**:

- The $\beta$ sequence in the sequence-pair is the **topological sorting** of both graphs $C_h$ and $C_v$. That is, $A$ precedes $B$ in $\beta$ if there is an arc $A \to B$ in either $C_h$ or $C_v$.
- The $\alpha$ sequence is the topological sorting of $C_h$ and $C_v$ with the arcs of $C_v$ **reversed**.
- Both topological sortings are unique and can be built in $O(n \log n)$ time.

#### Conversion Complexity

| Direction | Complexity |
|-----------|-----------|
| TCG $\to$ Sequence-pair | $O(n \log n)$ |
| Sequence-pair $\to$ TCG | $O(n^2)$ (cannot be improved since total arcs in $C_h$ and $C_v$ is $\Theta(n^2)$) |

#### Solution Space Size

Since the representations are equivalent, the solution space size is the same: $\Theta((n!)^2)$.

#### Why Sequence-Pairs Win

- One can define **symmetric-feasibility** within TCG (either by translating condition (1.1) from sequence-pairs, or by defining direct conditions on $C_h$ and $C_v$).
- However, there is **no advantage** in solution space size or quality -- both representations are **P-admissible**.
- The proposed evaluation algorithms for TCG with symmetry (TCG-S) have **quadratic complexity** $O(n^2)$, whereas the S-F sequence-pair evaluation algorithm from [[1.3 Symmetric-Feasible Sequence-Pairs]] achieves $O(n \log \log n)$.
- **Conclusion**: S-F sequence-pairs are more advantageous in terms of computational speed.

### 1.4.2 Comparative Overlook on Tree Representations

#### O-Trees

A placement of $n$ rectangular blocks can be represented by an **ordered tree (O-tree)** with $n+1$ nodes, encoded as $(T, \pi)$ where:

- $T$ is a **$2n$-bit string** identifying the branching structure relative to a traversal order ("0" = descending an edge, "1" = ascending that edge).
- $\pi$ is a **permutation** of the block names.

**Example**: The O-tree in Fig. 1.23a has encoding $(T, \pi) = (00110100011011, adbcegf)$.

#### O-Tree to Binary Tree Transformation

Given an O-tree $T = (T_1, \ldots, T_k)$ with subtrees $T_1, \ldots, T_k$ relative to the root, it can be recursively transformed into a binary tree $B(T)$:

1. If $k = 0$, then $B(T)$ is empty.
2. If $k > 0$, the root of $B(T)$ is the root of $T_1$; the left subtree of $B(T)$ is $B(T_1)$; the right subtree of $B(T)$ is $B(T')$, where $T' = (T_2, \ldots, T_k)$ is the O-tree minus subtree $T_1$.

The root of the resulting binary tree becomes obsolete. This transformation is invertible, establishing a **one-to-one correspondence** between O-trees and binary trees with one fewer node.

#### Solution Space Size Comparison

The number of labeled binary trees with $n$ nodes is $b_n \cdot n!$, where $b_n$ is the $n$-th **Catalan number**:

$$b_n = \frac{1}{n+1}\binom{2n}{n}$$

**Lemma 2**: The number of labeled binary trees with $n$ nodes is **smaller** than the number of $n$-block sequence-pairs (for $n \geq 3$).

*Proof sketch*: For any integer $p$ with $1 < p < n$: $\binom{n+p}{p} < n - p + 2$. Substituting $p = 2, 3, \ldots, n-1$ and multiplying yields $\binom{2n}{n} < (n+1)!$, hence $b_n < n!$. Multiplying both sides by $n!$ gives $b_n \cdot n! < (n!)^2$.

| Representation | Solution space size |
|----------------|-------------------|
| Sequence-pairs | $(n!)^2$ |
| Labeled binary trees | $b_n \cdot n!$ (smaller) |
| S-F sequence-pairs (all devices symmetric, $n=2p$) | $\leq (2p)!$ (can be smaller than trees) |

**Key nuance**: Although tree representations have a smaller search space in general, when **symmetry groups are dominant** (many cells are symmetric), the number of symmetric-feasible sequence-pairs can be smaller than the number of tree representations. For instance, if all $n = 2p$ devices form one symmetry group, S-F sequence-pairs are upper-bounded by $(2p)!$, while trees number $b_{2p} \cdot (2p)!$ -- at least twice as large.

#### Prior O-Tree Approach (Lin and Chang)

An earlier approach built horizontal and vertical **constraint graphs** from the current O-tree and tested feasibility:
- If the horizontal constraint graph has **cycles**, or the vertical constraint graph has **positive cycles**, the O-tree is infeasible from a symmetry standpoint and is disregarded.
- Complexity of these tests: **quadratic** $O(n^2)$.

This is suboptimal -- a better strategy is to restrict exploration to only symmetric-feasible trees from the outset.

### 1.4.2.1 Symmetric-Feasible Binary Trees

A binary tree layout representation induces positioning constraints:

1. **Vertical constraint**: Each cell whose node is in the left subtree is **above** the cell at the parent node.
2. **Horizontal constraint**: If the $y$-projections of two cells overlap, the cell visited **first in preorder traversal** is to the **left** of the cell visited second.

A binary tree is uniquely determined by its **(inorder, preorder)** traversal pair. (Note: this pair must **not** be confused with the sequence-pair $(\alpha, \beta)$ of Murata et al. -- there exist pairs $(\alpha, \beta)$ that do not correspond to any binary tree's traversals, e.g., $(CAB, ABC)$.)

#### Symmetric-Feasibility Condition (Property 1.2)

A binary tree representation is **symmetric-feasible** if its (inorder, preorder) traversal pair satisfies, for any distinct nodes $A$, $B$ in a symmetry group:

$$A \xrightarrow{\text{inorder}} B \iff \text{sym}(B) \xrightarrow{\text{preorder}} \text{sym}(A) \tag{1.2}$$

That is, $A$ precedes $B$ in the inorder traversal **if and only if** $\text{sym}(A)$ succeeds $\text{sym}(B)$ in the preorder traversal.

Additionally, for nodes $A$, $B$ belonging to **different** symmetry groups, the following pattern is forbidden:

$$A \xrightarrow{\text{inorder}} B \xrightarrow{\text{inorder}} \text{sym}(B) \xrightarrow{\text{inorder}} \text{sym}(A)$$
$$B \xrightarrow{\text{preorder}} A \xrightarrow{\text{preorder}} \text{sym}(A) \xrightarrow{\text{preorder}} \text{sym}(B)$$

This prevents situations where cell $A$ is above cell $B$ but $\text{sym}(B)$ is above $\text{sym}(A)$, which would prevent both pairs from aligning horizontally within their groups.

Evaluation algorithms for this S-F binary tree subset can use any data structures from [[1.2 Data Structures for Placement Evaluation|Section 1.2]] (e.g., longest common subsequence, priority queues).

### 1.4.2.2 The Design of the Move Set

Designing a complete move set for tree representations -- where any valid code is reachable from any other via a finite sequence of moves -- was previously under-addressed.

#### (a) Move Sets for Binary Trees with Provable Reachability

Two move sets are presented, each guaranteeing complete exploration:

**Move Set 1: Structural rotation + label interchange**

- Based on the **Stasheff polytope** (associahedron): parenthesized products like $(\ldots((a_0 a_1) a_2) \ldots a_n)$ can be transformed into $(a_0 (a_1 (\ldots(a_{n-1} a_n)\ldots)))$ via basic transformations $((xy)z) \mapsto (x(yz))$.
- Applied to binary trees: $((S_1 S_2) S_3) \mapsto (S_1 (S_2 S_3))$ -- "sliding" a right-descendant subtree of a left-descendant node past its parent.
- NULL pointers are treated as dummy children so every node has exactly two children.
- Vertices of the Stasheff polytope are edge-connected, so any unlabeled tree is reachable.
- **Label interchange** (swapping two node labels) ensures reachability of any labeled tree with a given structure, since any permutation decomposes into transpositions.
- Together: structural rotation + label swap = complete exploration.

**Move Set 2: Grid-path swap E-N + label interchange** (used in the placement tool)

- There is a **one-to-one mapping** between unlabeled binary trees with $n$ nodes and rectangular grid paths connecting opposite corners of an $n \times n$ square that do not cross the diagonal.
- Paths are encoded as sequences of $n$ E-segments (East/horizontal) and $n$ N-segments (North/vertical), with the constraint that in any prefix, $\#N \leq \#E$ (to stay below the diagonal).
- A **swap E-N** move interchanges an E-segment and an N-segment while maintaining the diagonal constraint. This modifies the tree's branching structure.
- Any path $\gamma_0 = E \cdots E\, N \cdots N$ can be transformed into any other path $\gamma$ by a finite sequence of E-N swaps. Arbitrary $\gamma_1 \to \gamma_2$ is achieved by composing $\gamma_1 \to \gamma_0$ (inverse) and $\gamma_0 \to \gamma_2$.
- **Cell interchange + swap E-N** = complete exploration of all labeled binary trees.

#### (b) The Move Set with Symmetry Constraints

The placement tool builds an initial binary tree satisfying property (1.2) for each symmetry group, then preserves it through three move types:

**1. Interchange of two cells** (constant complexity)
- Same symmetry group (not symmetric pairs of each other): interchange must be accompanied by swapping their symmetric pairs to preserve (1.2).
- Different symmetry groups, or one cell in a group: interchange allowed only between cells in a **parent-child relation**.
- Ensures reachability of any S-F binary tree with a given branching structure.

**2. Move of cells** (linear complexity)
- Asymmetric cells: standard swap E-N, no restrictions.
- Symmetric cells: **two simultaneous swaps E-N** are performed -- one for the cell and one for its symmetric pair -- based on the (inorder, preorder) sequences. The tree is locally modified around both corresponding nodes to maintain property (1.2).

**3. Group-level moves** (specific to multiple symmetry groups)
- Complex moves operating with entire symmetry groups.
- Performed with low probability, decreasing with the annealing temperature.

## Algorithms & Methods

### Evaluation Algorithm Complexity Summary

| Representation | Evaluation Complexity | Notes |
|---------------|----------------------|-------|
| S-F Sequence-Pairs | $O(n \log \log n)$ | Best known; uses LCS + priority queues |
| TCG with Symmetry (TCG-S) | $O(n^2)$ | Quadratic; no improvement possible |
| O-tree (Lin & Chang) | $O(n^2)$ | Feasibility test via constraint graph cycle detection |
| S-F Binary Trees | $O(n \log \log n)$ (achievable) | Using same data structures as S-F sequence-pairs |

### Multiple Symmetry Groups Handling

From [[1.3 Symmetric-Feasible Sequence-Pairs|Section 1.3.2]]:

1. Groups are processed **one by one**; after each iteration, symmetry constraints for one group are fixed and positions "frozen."
2. For **embedded** groups, inner groups must be processed before outer ones (ordered via an embedding DAG of symmetry groups).
3. If groups do not intermingle in the sequence-pair, processing order is irrelevant.
4. Overall complexity: $O(G \cdot n \log \log n)$ where $G$ is the number of symmetry groups.
5. If the sequence-pair is not symmetric-feasible for all groups, the algorithm may **loop forever**.

### Simulated Annealing Move Design (Sequence-Pairs)

1. Start with an initial S-F sequence-pair:
$$(\alpha, \beta) = (a_1 \cdots a_p\, c_1 \cdots c_s\, b_p \cdots b_1, \quad a_1 \cdots a_p\, c_s \cdots c_1\, b_p \cdots b_1)$$
   where $(a_i, b_i)$ are symmetric pairs and $c_j$ are self-symmetric cells.
2. Moves preserve symmetric-feasibility:
   - Interchange two cells in $\alpha$ $\Rightarrow$ interchange their symmetric counterparts in $\beta$.
   - Move a cell in $\alpha$ $\Rightarrow$ move its symmetric pair in $\beta$ (range depends on the first move).
   - Rotations/mirroring affect both symmetric cells simultaneously.
3. Asymmetric cells have **unrestricted** moves (subject to annealing temperature).

## Connections to Bigger Picture

This section serves as a comparative analysis that justifies the choice of symmetric-feasible sequence-pairs as the preferred topological representation for analog placement with symmetry constraints. It establishes that while TCGs are representation-equivalent to sequence-pairs, they suffer from worse evaluation complexity ($O(n^2)$ vs. $O(n \log \log n)$). Tree representations offer a smaller search space in general ($b_n \cdot n! < (n!)^2$), but this advantage can reverse when symmetry groups dominate the circuit. The introduction of symmetric-feasible binary trees with property (1.2) and provably complete move sets based on grid-path E-N swaps provides an alternative framework that will be experimentally compared in [[1.5 Experimental Results - Ch1]]. The move set design principles here -- preserving feasibility invariants through constrained moves within simulated annealing -- are a recurring theme throughout the book's treatment of placement representations in later chapters.
