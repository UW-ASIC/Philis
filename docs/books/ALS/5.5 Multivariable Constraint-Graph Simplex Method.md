# 5.5 Multivariable Constraint-Graph Simplex Method

> **Chapter 5**: Analog Layout Retargeting (Said, Dessouky, El-Adawi, Abbas, Shahein)
> **Part**: Part III: Layout in the Design Flow

## Key Concepts

This section presents the core contribution of Chapter 5: a **graph-based simplex method** that supports all forms of linear objective functions and linear constraints. It combines the computational efficiency of [[5.4 Layout Compaction Methodologies|constraint-graph techniques]] (near-linear time for sparse problems) with the full generality of the [[5.4 Layout Compaction Methodologies|simplex method]] (arbitrary multivariable constraints and objective functions).

### 5.4.3 Graph-Based Simplex Methods (Predecessor Work)

Prior graph-based simplex methods attempted to bridge the gap between fast constraint-graph approaches and flexible LP:

- **Marple et al.** -- supported only minimum-distance constraints plus a special long-wire-minimization objective function.
- **Onozawa** -- extended to multivariable constraints but limited to at most **three variables** per constraint.
- **Wang and Lai** -- more general multivariable support via a "core matrix" approach: graph operations speed up inversion of the basis matrix $B$, with matrix operations only on a reduced core matrix whose size is proportional to the number of multivariable constraints. However:
  - No general procedure for finding an initial feasible solution (only handled path-delay constraints).
  - Objective function restricted to a **single variable**; complex objectives required adding extra constraints.

**Conclusion**: all prior graph-based methods were limited either in objective function form or in the constraint types they supported. The multivariable constraint-graph simplex method presented in Sect. 5.5 removes both limitations.

### 5.5.1 Basic Coefficient Constraint-Graph

The **coefficient constraint-graph** is a new graph representation that models layout locations and multivariable constraints as a signal flow graph.

**Definition 5.2 (Coefficient Constraint-Graph)**:
- Each variable $x_i$ (including slack variables) is a **graph node**.
- Each constraint $c_j$ is also a **separate node**.
- For constraint $c_j$ with $p$ variables: $c_j: f(x_1, x_2, \ldots, x_p) = 0$, a **weighted directed arc** from variable node $x_i$ to constraint node $c_j$ represents the coefficient of $x_i$ in that constraint.
- Arcs go only from variable nodes to constraint nodes.
- A **bias node** $x_{\text{bias}}$ (value always 1) accounts for constant terms in constraints:
$$c_j: f(x_1, x_2, \ldots, x_p, x_{\text{bias}}) = 0$$
- A **supernode** $(c_j, x_k)$ consists of a constraint node associated with a variable node. The connection coefficient between them inside a supernode is always $-1$. The supernode represents:
$$c_j: x_k = f(x_1, x_2, \ldots, x_p, x_{\text{bias}})$$
- The weight of the arc from $x_i$ to supernode $(c_j, x_k)$ represents the partial derivative $\partial x_k / \partial x_i$.
- A supernode acts as a variable node of its variable to successive nodes in the graph.

**Example**: The distance constraint $c_1: x_2 - x_1 - s_1 = 5$ is rewritten as $c_1: 5x_{\text{bias}} - x_2 + x_1 + s_1 = 0$, and the bias node connects to $c_1$ with weight 5.

A symmetry constraint $x_2 - x_1 = x_4 - x_3$ is rewritten as $x_2 - x_1 - x_4 + x_3 = 0$ and represented with four variable-to-constraint arcs with appropriate $+1/-1$ weights.

**Definition 5.3 (Basic Coefficient Constraint-Graph)**: A coefficient constraint-graph where each constraint node is associated with a basic variable forming a supernode. An additional supernode contains the objective function $f$ and its corresponding equation. The number of supernodes equals the number of constraints plus one (for the objective function).

### 5.5.2 Multivariable Graph-Based Simplex Algorithm

The algorithm replaces **matrix operations** of the standard simplex with **graph traversal operations** (connection value calculations). The basic coefficient constraint-graph is a signal flow graph; its rules follow from Mason's gain formula.

#### Gain Equation

For any two nodes $x_i$ and $x_j$, the derivative $\partial x_j / \partial x_i$ is found by Mason's equation. When there are **no loops**, it simplifies to:

$$\partial x_j / \partial x_i = \sum_i G_i \tag{5.28}$$

where $G_i$ are the gains of all paths from $x_i$ to $x_j$. This defines the **connection value** between any two nodes.

#### Graph Mathematics -- Three Rules

All rules assume no loops in the basic coefficient graph:

**Rule 1** (Basic Variable Values): From the BFS equation $x_B = \partial x_B / \partial x_{\text{bias}}$:
$$\bar{x}_{\text{basic}}(i) = \partial x_{\text{basic}}(i) / \partial x_{\text{bias}} \tag{5.30}$$
The basic variable value is the **connection value from the bias node to the basic variable's supernode**.

**Rule 2** (Relative Cost Vector): From $z = \partial f / \partial x_N$:
$$z = \partial f / \partial x_N \tag{5.31}$$
The cost rate $z(i)$ is the **connection value from the nonbasic variable node to the objective function supernode $f$**.

**Rule 3** (Step Vector): From $\Delta x_B = -\partial x_B / \partial x_e$:
$$\Delta x_B = -\partial x_B / \partial x_e \tag{5.32}$$
The step vector element is $-1$ times the **connection value from the entering variable node to each basic variable supernode**.

#### Algorithm Steps

1. Obtain an initial BFS (see Sect. 5.5.2.3).
2. Construct the corresponding basic coefficient constraint-graph.
3. Calculate basic variable values $\bar{x}_{\text{basic}}(i)$ using **Rule 1** -- connection value from $x_{\text{bias}}$ to each supernode.
4. Calculate relative cost $z(i)$ of each nonbasic variable using **Rule 2** -- connection value from nonbasic nodes to the $f$ supernode.
5. **Entering variable** $x_e$: if all $z(i) \geq 0$, the solution is optimal (stop). Otherwise, select the nonbasic variable with the most negative $z(i)$.
6. **Leaving variable** $x_l$: apply **Rule 3** to compute step vector $\Delta x_{\text{basic}}(i)$, then use the minimum ratio test:
$$\frac{x_l}{\Delta x_l} = \min\left\{\frac{\bar{x}_i}{\Delta x_i} \;\middle|\; \Delta x_i > 0,\; 1 \leq i \leq m\right\} \tag{5.18}$$
7. **Update the graph**: associate $x_e$ with a constraint (form supernode), detach $x_l$ from its supernode.
8. Go to step 3. Repeat until optimal.

### 5.5.2.1 Updating the Basic Coefficient Constraint-Graph

After selecting entering ($x_e$) and leaving ($x_l$) variables:

1. Find a **path from $x_e$ to $x_l$** in the graph.
2. **Detach** all variables inside supernodes along this path from their supernodes.
3. **Re-associate** each variable with its **successive constraint** in the path to form new supernodes.
4. Adjust coefficients so the coefficient connecting the constraint and the basic variable inside each new supernode is always $-1$.

Only coefficients connected to updated nodes change; arcs connecting two nodes outside the updated area remain intact. This locality property is a key efficiency advantage.

### 5.5.2.2 Dealing with Loops

The simple application of Mason's formula (5.28) assumes **no loops**. When multivariable constraints create loops, they must be eliminated by **successive substitution** of constraint equations.

**Example**: A loop of three constraints $c_x, c_y, c_z$:
- $c_x: x_6 = 5 + 4x_8 + s_6$
- $c_y: x_7 = 4 + x_6 + s_7$
- $c_z: x_8 = 0 + x_7 + s_8$

Substituting $c_z$ and $c_y$ into $c_x$ eliminates the loop:
$$c_x: x_6 = -7 + \frac{4}{3}s_7 - \frac{4}{3}s_8 - \frac{1}{3}s_6$$

The resulting graph has no loops, but may have more coefficient links.

**Theorem 5.1**: Each loop in the basic coefficient constraint-graph contains **at least one nondistance constraint**.

**Proof sketch**: Assume a loop of $k$ distance constraints. Summing all constraint equations cancels all basic variables, producing a row of zeros in the basis matrix $B$ -- contradicting the requirement that $B$ is nonsingular. Therefore, loops cannot consist solely of distance constraints.

**Implication**: In layouts dominated by simple distance constraints, loops are rare.

### 5.5.2.3 Initial Basic Feasible Solution

The initial BFS strongly affects performance. The algorithm uses a three-step initialization:

1. **Apply the longest path algorithm** ([[5.4 Layout Compaction Methodologies|Sect. 5.4.1]]). Use the obtained locations as initial values. Variables not in any distance constraint are initialized to zero.
2. **Check each multivariable constraint**: if satisfied, associate its constraint node with its slack variable.
3. **If a constraint is unsatisfied** (or has no slack variable, e.g., symmetry): add an **artificial variable** $a_i$ whose value satisfies the constraint. Add a penalty term $M \cdot a_i$ to the objective function with a huge positive constant $M$ (Big-M method). This ensures $a_i \to 0$ in the optimal solution.

**Example**: Symmetry constraint $x_4 - x_3 = x_2 - x_1$ is unsatisfied by longest-path values $x_1=10, x_2=30, x_3=10, x_4=50$. Adding $a_1 = 20$ satisfies the modified constraint, and $M \cdot a_1$ is added to $f$.

**Equal-constraints** of the form $x_j - x_i = K$ (critical for device sizing accuracy) are handled identically -- artificial variable + penalty.

**Advantage**: Adding new terms is straightforward in the graph-based method, unlike the traditional constraint-graph or earlier graph-based simplex methods.

### 5.5.3 Complexity Analysis

A single iteration of the graph-based algorithm produces the **same output** as the matrix-based simplex, so both have the same number of iterations from the same BFS.

#### Baseline Complexities

- **Standard simplex** (single iteration): dominated by basis matrix inversion:
$$C_{\text{simplex}} = O(R^3) \tag{5.38}$$
where $R$ is the number of rows/columns of the basis matrix.

- **Longest path algorithm**:
$$C_{\text{longest path}} = O(N + E) \tag{5.39}$$
where $N$ = number of nodes, $E$ = number of links. Practically $O(N)$.

#### Graph-Based Algorithm Complexity

**Variables defined**:
- $k$ = number of location variables
- $u$ = number of distance constraints
- $v$ = number of nondistance (multivariable) constraints
- $p$ = maximum number of variables in a nondistance constraint (5 for simple symmetry, tens for hierarchical layouts)
- $m = u + v$ = total constraints
- $N = k + u + v$ = total variables (after adding slacks)
- $E = v(p-1) + 3u + k_f$ = total links ($k_f$ = links to objective supernode)

**Two main operations per iteration**:

1. **Finding connection values** (steps 3, 4, 6):
$$C_{\text{graph-connection}} = O(N + E) = O(k + k_f + u + pv) \tag{5.40}$$

2. **Loop elimination** (worst case):
   - Per nondistance constraint: $O(p \cdot (u + v))$ -- (5.41)
   - All nondistance constraints: $O(v \cdot p \cdot (u + v))$ -- (5.42)

#### Special Cases

| Case | Connection Value | Loop Elimination | Notes |
|------|-----------------|------------------|-------|
| **Only distance constraints** ($v=0$) | $O(k + k_f + u)$ -- linear | No loops (Thm 5.1) | Same as longest-path |
| **$u \gg v$** (common case) | $O(k + k_f + u)$ -- linear | $O(v \cdot p \cdot u)$ -- manageable | Most practical layouts |
| **$u \ll v$, $p = N$** (worst case) | $O(v^2)$ | $O(v^3)$ | Same as matrix inversion |

**Key insight**: The algorithm **inherently exploits matrix sparsity** without special handling. When matrices are sparse (most practical cases), the graph has fewer links and the algorithm is much faster than $O(R^3)$. The graph size is at most the same size complexity as the simplex method.

**Efficiency enhancement**: Only the **subset of updated nodes** affected by the entering variable (plus nodes on paths through the objective supernode $f$) are processed. All other nodes retain values from the previous iteration.

### 5.6 Layout Constraints Revisited

The complexity of compaction is closely tied to the number and types of constraints. This section addresses practical constraint-related issues.

#### Constraint Number Reduction

**Contact/via array merging** reduces constraint count dramatically:
1. During [[5.3 Analog Layout Retargeting Flow#Layer Mapping|layer mapping]], merge each contact/via array into a single large contact/via.
2. Set internal design-rule constraints to maintain at least the original number of vias.
3. After compaction, a postprocessing step reconstructs minimum-sized contacts/vias.

This eliminates the many inter-contact constraints (e.g., a 16-contact array generates far fewer constraints when merged into one rectangle).

#### Complex Design-Rules

Modern processes introduce challenges beyond simple edge-based rules:
- **Conditional design-rules**: constraint values depend on external factors (e.g., metal separation is larger for wide metals).
- **Conjunctive/context-based rules**: constraint depends on the presence/absence of an unrelated layer.
- **Shape/polygon-based rules**: replace traditional edge-based rules in nanometer processes.

The Calibre nmDRC tool captures these complex rules and transforms them to edge-based format for compaction.

#### Edge Order

Minimum-distance constraints $x_j - x_i \geq d_{ij}$ impose a **fixed ordering** ($x_j > x_i$ always). When device sizes change drastically between processes, this ordering can prevent optimal placement.

**Example**: Four devices A, B, C, D with horizontal constraints. After migration, device D could move left but is blocked by a now-meaningless constraint with device A. The compactor has no vertical information during horizontal compaction.

**Solutions**:
- Iterate horizontal-vertical compaction until no further area reduction.
- Two-dimensional compaction (but NP-complete; impractical for large layouts).

#### Nanometer Process Effects

Modern processes require constraints beyond design rules to preserve electrical performance:
- **STI stress** and **well proximity (WP) effects** significantly impact transistor performance.
- Layout migration preserves floorplanning/placement/routing, helping mitigate these effects if they were accounted for in the source layout.
- **Special handling of wells**: wells not at minimum sizes in the source must be detected. Objective functions privileging closeness to the source layout can help.

## Algorithms & Methods

### Multivariable Graph-Based Simplex Algorithm (Pseudocode)

```
Input: Layout constraints, objective function f
Output: Optimal variable assignments minimizing f

1. x_init <- LongestPathAlgorithm(distance_constraints)
2. For each multivariable constraint c_j:
     if c_j satisfied by x_init:
       associate c_j with its slack variable
     else:
       add artificial variable a_j, set a_j so c_j satisfied
       add M * a_j to objective function f
3. Construct basic coefficient constraint-graph G

4. REPEAT:
   // Step 3: Compute basic variable values (Rule 1)
   for each supernode (c_j, x_basic(i)):
     x_bar(i) <- ConnectionValue(x_bias -> supernode_i)  // Eq. 5.30

   // Step 4: Compute relative costs (Rule 2)
   for each nonbasic variable x_nb(i):
     z(i) <- ConnectionValue(x_nb(i) -> f_supernode)     // Eq. 5.31

   // Step 5: Check optimality / select entering variable
   if all z(i) >= 0: RETURN x_bar (optimal)
   x_e <- argmin_i z(i)  // most negative relative cost

   // Step 6: Select leaving variable (Rule 3 + min ratio)
   for each supernode (c_j, x_basic(i)):
     delta_x(i) <- -1 * ConnectionValue(x_e -> supernode_i)  // Eq. 5.32
   x_l <- argmin { x_bar(i)/delta_x(i) | delta_x(i) > 0 }  // Eq. 5.18

   // Step 7: Update graph
   path <- FindPath(x_e, x_l, G)
   DetachSupernodes(path)
   FormNewSupernodes(path)  // coefficient of basic var in supernode = -1
   EliminateLoops(G)        // if any created by multivariable constraints
```

### ConnectionValue Procedure

Uses a topological traversal of the DAG (equivalent to longest-path traversal). For two nodes $x_i, x_j$:
- Sum the gains $G_i$ of all directed paths from $x_i$ to $x_j$.
- Complexity: $O(N + E)$, same as longest path.

### Loop Elimination Procedure

For each loop detected:
1. Identify the nondistance constraint(s) in the loop (guaranteed by Theorem 5.1).
2. Substitute the constraint equations of other loop members into the nondistance constraint.
3. This eliminates the shared basic variables and breaks the loop, at the cost of potentially increasing the number of coefficient arcs.

## Connections to Bigger Picture

The multivariable constraint-graph simplex method is the central technical contribution of Chapter 5 and arguably the most significant algorithmic advance in the layout retargeting flow. It resolves the long-standing tension between the efficiency of constraint-graph compaction ([[5.4 Layout Compaction Methodologies|Sect. 5.4.1]], $O(N)$ but limited to two-variable distance constraints) and the generality of LP-based compaction ([[5.4 Layout Compaction Methodologies|Sect. 5.4.2]], $O(R^3)$ but handles arbitrary constraints). In practice, since most layout constraints are simple distance rules ($u \gg v$), the algorithm operates near linear time while still supporting symmetry, hierarchy, and device replacement constraints. [[5.7 Practical Retargeting]] demonstrates how this generality enables seamless integration of symmetry enforcement, hierarchical compaction, device aspect ratio optimization, and device replacement -- modules that were previously either impossible or required cumbersome workarounds with pure graph methods.
