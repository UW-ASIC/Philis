# 1.3 Symmetric-Feasible Sequence-Pairs

> **Chapter 1**: Device-Level Topological Placement with Symmetry Constraints (Florin Balasa)
> **Part**: Part I: Placement

## Key Concepts

### Symmetric-Feasible Sequence-Pairs: Definition

A **sequence-pair** $(\alpha, \beta)$ encodes a placement configuration containing a number of **symmetry groups** (each group composed of pairs of symmetric devices and self-symmetric devices) relative to a common vertical axis. Denoting $\alpha(\cdot)$ the position of cell $i$ in sequence $\alpha$ and $\beta(\cdot)$ in $\beta$:

- If $\alpha(d_1) < \alpha(d_2)$ and $\beta(d_1) < \beta(d_2)$: then cell $A$ is to the **left** of cell $B$.
- If $\alpha(d_1) < \alpha(d_2)$ and $\beta(d_1) > \beta(d_2)$: then cell $A$ is **above** cell $B$.

A sequence-pair $(\alpha, \beta)$ is called **symmetric-feasible** (S-F) if all its distinct cells $c_i$ in any of the symmetry groups satisfy the following property:

> **Property (1.1):** Taking $\gamma \in \{\alpha, \beta\}$, and noting that $\gamma(c_1) < \gamma(c_2)$ for some ordering, if a cell $c$ belonging to a *different* symmetry group appears between $c_1$ and $c_2$ in one of the sequences $\alpha$ or $\beta$, it must appear between them in the **other** sequence as well. The same constraint applies to self-symmetric cells within their group.

In other words, cells from different symmetry groups must not **interleave** within the sequences in a way that breaks the symmetry structure. This property prevents topologically infeasible configurations: if two cells from different symmetry groups interleaved, it would be impossible to simultaneously satisfy both groups' symmetry constraints.

### Why Symmetric-Feasibility Matters

- The property guarantees that a valid symmetric placement **exists** for the encoded topology. Without it, the placement algorithm could produce constraint violations that cannot be resolved.
- Property (1.1) is both a **necessary** and **sufficient** condition: it ensures the building of a valid placement from a symmetry point of view (as shown in Sect. 1.3.1).
- It also guarantees that placements are **intrinsically symmetric-unfeasible** when violated -- no amount of coordinate adjustment can fix a topological violation.

### Counting S-F Sequence-Pairs

The number of S-F sequence-pairs is upper bounded by:

$$\text{For a symmetry group of } n = 2p \text{ cells: from Lemma 1, at most } (2p)! \text{ S-F pairs}$$

whereas the number of general sequence-pairs would be $(2p)!^2$. So the S-F constraint reduces the search space by a factor of $(2p)!$, which is a **significant reduction**.

For a placement with a group of three pairs of symmetric devices $(F,G)$, $(K,L)$, and $(C,J)$:
- The widths and heights: $A(2 \times 4)$, $B(3 \times 1)$, $C(4 \times 2)$, $D(5 \times 3)$, $E(4 \times 2)$, $F(2 \times 10)$, $G(2 \times 10)$, $H(2 \times 3)$, $I(5 \times 5)$, $J(4 \times 2)$, $K(3 \times 2)$, $L(3 \times 2)$.

## 1.3.1 Evaluation of Symmetric-Feasible Sequence-Pairs

The evaluation algorithm computes the **coordinates** (both ordinates and abscissae) of all devices in a placement encoded by an S-F sequence-pair. It extends the classical [[1.2 Data Structures for Rectilinear Border Contours|longest-path evaluation]] to handle symmetry constraints.

### Step 1y: Computation of Device Ordinates (y-coordinates)

The device ordinates must be determined first. The key observation from Property (1.1) is that the **equality of symmetric devices must be enforced**: if a $y$-coordinate that was previously computed must be subsequently increased due to symmetry, then *Step 1y* must be repeated since, otherwise, some vertical topological constraints may be violated.

**Algorithm (using Johnson's priority queue):**

1. Insert `bucket(0,1)` in the priority queue.
2. Pop the smallest bucket. Let the index in $\beta$ of cell $B_i$ be $w_i$, and the length of cell $y_i$.
3. Find `bucket_pred` whose index in the largest buckets is smaller than $i$.
4. Set $y_i = \max(y_i, \text{length of pred})$.
5. Insert `bucket(y_i + w_i)` into the queue.
6. Remove buckets with an index greater than $i$ and a length lesser than or equal to $y_i + w_i$.

**Key detail:** Because of the symmetry constraint, when a symmetric pair $(B_i, B_j)$ is encountered, both cells must be assigned the **same** $y$-coordinate. If $B_j$ has already been visited and $y_j$ was set, then *Step 1y* is repeated, restarting with the $y$-values obtained so far. This repetition is needed because topological constraints may cascade.

- The computation of $y$-coordinates necessitates $\Theta(p)$ iterations, where $p$ is the number of symmetric pairs.
- The priority queue has at most $n + 1$ buckets; the insert and remove operations in this data structure can be performed in $O(\log k)$ time where $k$ is the queue size.

### Step 1x: Computation of Device Abscissae (x-coordinates) -- Initialization

The position of the symmetry axis is **not known** in advance -- it is chosen to minimize the total area. The algorithm uses a **directed acyclic graph (DAG)** built from the S-F sequence pair, showing the embedding relation between pairs along the $Ox$ axis.

Each symmetric pair or self-symmetric device is a node in this DAG. An edge from node $u$ to node $v$ means that $v$'s cells are placed **outside** (farther from the symmetry axis than) $u$'s cells. The embedding DAG for the placement in Fig. 1.19b is shown in Fig. 1.19(b7).

**Construction of the DAG:**

The segments visible from the right side of the placement (from the $Oy$ axis perspective) are identified. Then, for each node in the DAG:
- Find the end points of the interval $[x_l, x_r = x_l + \text{width}]$ and insert them into the queue.
- Add edges from successors to the current node.

Each node receives a $d$-value equal to the minimum one among its children (in the DAG). The abscissae of the nodes are updated so that:

$$x(\text{node}) = d(\text{node}) + \text{width}/2$$

for all nodes without successors; $B_0$ is in the DAG. In our example, cell $Z$ corresponding to the pair $(C_1, C_2)$ has $d=0$ and starts at the symmetry axis.

### Step 2x: Sweep-to-the-Right

The **sweep-to-the-right** traversal serves to satisfy the **topological constraints** (as computed at *Step 1x*). The $d$-values of the embedding DAG's nodes position the leftmost cells of the pairs as close as possible from the symmetry axis. The sweep-to-the-right will shift the rightmost cells in the pairs just enough to satisfy topological constraints (like $E_1$ in Fig. 1.21a), or symmetry constraints (like $D_1$), or both (like $F_1$).

### Step 3x: Sweep-to-the-Left

This traversal (`sweep-to-the-left`) is similar to the initialization step, but before inserting the bucket $(i, x + y)$ into the queue, if $(B_i, B_j)$ is a symmetric pair and $d = 2x_{\text{axis}} - (x + y) > 0$, then $y$ is increased with $d$. For the pair $(D_1, D_2)$: for instance, $d = 2 \times 14 - (6 + 7 + 3) = 2$, therefore $D_2$'s abscissa will be further increased with 2, becoming 19 (see Fig. 1.21a).

### Step 4x: Final Fixup

At the end of the *sweep-to-the-left* traversal, some of the **horizontal symmetry constraints** may still be unsatisfied since some rightmost cells in the pairs were pushed farther to the right. A third traversal of $\alpha$ (*sweep-to-the-right*) will fix all the symmetry constraints.

**Overall Complexity:**

- Steps 1y and 2x-4x each take $O(n \log n)$ time.
- With similar reasoning, both *Step 3x* and *Step 4x* take $O(n \log n)$ time as well.
- The overall time complexity is $O(n \log n)$. If $p = n/2$ (all pairs), the complexity becomes $O(n \log n)$ with up to $p$ repetitions of Step 1y, giving $O(p \cdot n \log n)$ in the worst case, though in practice no more than three iterations are needed.

### 1.3.1.2 Computation of Device Abscissae (Block Algorithm)

**Step 1x:** The first traversal, called initialization, computes the **block abscissa** using a **boring node** for the base being the symmetry constraints:

```
insert bucket(n+1, W) in the priority queue;
    // this bucket acts as a sentinel
for each index i in alpha (i = n to 1):
    let l be the index in beta of cell B_i, w_i;
    find bucket_pred, whose index is the smallest greater than l;
    if (w_i) will always be due to the sentinel bucket (n+1, W)
        x_i = length of w(c_i) - w_i
    if (B_i, B_j) is a symmetric pair and d = x_j + (x_j + w_j) - 2*x_axis > 0:
        then x_i = w_i + d;
    insert bucket(l, x_i) into the queue;
    remove buckets with an index lesser than l
        and a length greater than or equal to x_i
end for
remove all buckets from the priority queue;
```

The worst-case complexity of *Step 1x* is $O(n \log n)$ time.

## 1.3.2 Handling Multiple Symmetry Groups

When multiple symmetry groups exist, additional care is needed:

- **Precaution:** Two symmetry groups must not prevent each other from being correctly built. If two cells $s$, $t$ belong to different symmetry groups and satisfy simultaneously the inequalities $\alpha(s) < \alpha(t) < \alpha(\gamma(s))$ and $\beta(\gamma(t)) < \beta(s)$ (or variants), then cell $s$ results above cell $\gamma(t)$ and cell $\gamma(s)$ results above $s(\gamma(t))$, which means the two groups are **preventing each other** from aligning horizontally within their groups.
- **Solution:** Design the move set to **prevent cells from different groups from intermingling** with each other in any of the sequences $\alpha$ and $\beta$ -- a solution adopted from [43].

### Embedded Symmetry Groups

If the design requires **embedded symmetry groups** (as revealed by the schematic), the move set can be modified to allow cells from one group between cells of another group in **both** sequences $\alpha$ and $\beta$ simultaneously (Fig. 1.22).

For example, with three symmetry groups:
- **Group 1** = $\{(A_1, A_2), (B_1, B_2), (C_1, C_2), D, Z\}$
- **Group 2** = $\{(U_1, U_2), V\}$
- **Group 3** = $\{(X_1, X_2), (Y_1, Y_2), W, Z\}$

The third group is embedded in the first one. An encoding sequence-pair has cells of groups 2 and 3 **surrounded** by the cells of Group 1 in both sequences $\alpha$ and $\beta$ (though it is not essential to occupy contiguous positions in any of the sequences).

**Processing order matters:** Inner groups must be processed before outer ones. An **embedding DAG** of the symmetry groups is used to order group processing. If $G$ is the number of symmetry groups, the complexity of the evaluation algorithm is basically $O(G \cdot n \log n)$.

- If the cells of the groups **do not interleave**, the processing order is irrelevant.
- If the sequence-pair is **not** symmetric-feasible relative to all the groups, the algorithm may **loop forever** attempting to fix the symmetry constraints.

## 1.3.3 Design of the Move Set

The move set for simulated annealing was adapted to restrict the exploration of sequence-pairs to the subset that is **symmetric-feasible**.

### Initial Configuration

It is sufficient to start the exploration with an initial sequence-pair that is symmetric-feasible relative to all symmetry groups [43]. A canonical starting form:

$$(\alpha, \beta) = (a_1 \cdots a_p \, c_1 \cdots c_q \, b_p \cdots b_1, \quad a_1 \cdots a_p \, c_1 \cdots c_q \, b_p \cdots b_1)$$

where $(a_i, b_i)$, $i = 1, \ldots, p$ are the pairs of symmetric cells and $c_j$, $j = 1, \ldots, q$ are self-symmetric cells. This corresponds to a placement where symmetric pairs are disposed in line, like embedded brackets, surrounding self-symmetric cells stacked on top of each other.

### Move Types Preserving Symmetric-Feasibility

The move set must be customized so that the property of symmetric-feasibility is preserved after each move:

1. **Interchange of symmetric pairs:** If two cells from distinct symmetric pairs are interchanged in sequence $\alpha$, then their symmetric counterparts must be interchanged as well in $\beta$.
2. **Cell movement:** If a cell is moved (changing its position in $\alpha$), its symmetric pair must be moved too in $\beta$, and the range of possible positions depends on the move of the former cell.
3. **Device rotations and mirroring:** These also affect **simultaneously** two symmetric cells.
4. **Asymmetric component:** Moves of the cells in the asymmetric component are **unrestricted** (interchanges and changes of position in both sequences, device rotations) -- except for move amplitude restrictions due to cooling temperature of the annealing.
5. **Entire symmetry group moves:** More complex moves operating with entire symmetry groups are also performed, although with low probability, decreasing with temperature.

## Algorithms & Methods

### Evaluation Algorithm Summary

The complete evaluation of an S-F sequence-pair proceeds in two phases:

**Phase 1 -- y-coordinates (ordinates):**
1. **Step 1y:** Traverse sequence $\beta$ using Johnson's priority queue. For each cell, compute its $y$-coordinate from the longest-path in the vertical constraint graph. When a symmetric pair $(B_i, B_j)$ is encountered and $B_j$ was already assigned a different $y$-value, **restart** Step 1y with the updated values.
2. Repeat Step 1y up to $\Theta(p)$ times (in practice $\leq 3$).

**Phase 2 -- x-coordinates (abscissae):**
1. **Step 1x (Initialization):** Traverse $\alpha$ right-to-left. Build the embedding DAG for symmetric pairs. Assign initial $d$-values.
2. **Step 2x (Sweep-to-the-right):** Fix topological constraints by pushing rightmost cells outward.
3. **Step 3x (Sweep-to-the-left):** Similar to Step 1x but adjusts for symmetry axis distance, ensuring leftmost symmetric cells are equidistant from axis.
4. **Step 4x (Sweep-to-the-right again):** Final pass to fix any remaining horizontal symmetry violations.

### Complexity

| Phase | Step | Complexity |
|-------|------|-----------|
| y-coordinates | Step 1y ($\times p$ iterations) | $O(p \cdot n \log n)$ |
| x-coordinates | Steps 1x, 2x, 3x, 4x | $O(n \log n)$ each |
| **Overall** | | $O(p \cdot n \log n)$ worst case |

In practice, for most "pathological" examples, the computation of $y$-coordinates with $O(n \log n)$ per Step 1y takes at most 3 iterations. The priority queue size is bounded by $n + 1$ buckets, and by normalization (sorting by root coordinates) the queue is kept minimal: at most $\frac{n}{2} + 2$ entries for $n$ cells after removing duplicates.

### Johnson's Priority Queue (from Section 1.2.4)

The evaluation relies on [[1.2 Data Structures for Rectilinear Border Contours|Johnson's priority queue]], where:
- Keys (integers in $\{1, \ldots, N\}$) are kept in $N$ buckets.
- The nonempty buckets, together with bucket 0, are kept in the **bucket list** (a doubly-linked list sorted on key values).
- Buckets in the list correspond to leaves of a binary **host tree** $H = \{1, \ldots, 2^k + N\}$ where $k = \lfloor \log_2(N+1) \rfloor$.
- Insert, delete, and find-minimum operations are all $O(\log k)$ time.

## Connections to Bigger Picture

Section 1.3 is the core algorithmic contribution of Chapter 1. While [[1.2 Data Structures for Rectilinear Border Contours]] provides the foundational data structures (Johnson's priority queue, border contour representations), this section builds the **evaluation engine** that turns a topological encoding (sequence-pair) into actual device coordinates while respecting symmetry constraints. The symmetric-feasibility property (1.1) is what makes it possible to restrict the simulated annealing search space to only those sequence-pairs that can produce valid symmetric layouts -- a significant reduction over the general sequence-pair space. The next section, [[1.4 Topological Placement with Symmetry Constraints]], assembles these components into the complete placement flow, including the simulated annealing loop, cost function, and experimental results. The comparison with other topological representations (TCG, O-trees) in Section 1.4 confirms that S-F sequence-pairs offer better computational speed for the same solution quality.
