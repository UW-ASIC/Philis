# 4.6 Specialized Routers and Manufacturability

> **Chapter 4**: Routing Analog Circuits (Dundar & Unutulmaz)
> **Part**: Part II: Routing

## Key Concepts

### 4.5.7 Other Routing Strategies (Concluding Prior Section)

Pages 200-203 conclude the prior section on template-based routing using the **Layout Description Script (LDS)** approach:

- **LDS** is a constraint-based language that describes the relative placement and routing topology of analog layouts. Routing affects both horizontal and vertical constraints: after entering placement in an array (as a path on the extended graph), all horizontal paths are updated and corresponding LDS is generated.
- **Template compilation**: LDS is compiled for specific circuits (e.g., an OPAMP using Fig. 4.25a). The same template (e.g., Fig. 4.25b) is synthesized with different device dimensions. The M3-M4 pair is enlarged or M6/M7 narrowed, yet the resulting layouts remain free of overlaps and satisfy design rules (minimum width, spacing, etc.).
- **Key advantage**: A single template encodes topological relationships; the constraint solver adapts the layout to any set of device sizes while preserving design-rule correctness.

### 4.5.7 Continued: Other Routing Strategies

- A **routing methodology based on candidate generation** has an inherent global approach and tries to satisfy all constraints simultaneously. For all nets, candidates are considered together instead of using an incremental net-by-net approach, which may be unable to route all nets respecting all constraints as routing congestion increases.
- It was also shown that $s$-$t$ routing can be extended to **45-degree routing** as well.
- **Widths, vias** can also be included by the designer. These are accounted for during the routing process to obtain optimized routing solutions respecting given constraints.
- The routing methodology achieves **constraint-based candidature routing** -- an efficient scheme for generating candidate routes for each net. A single route-finding method has been used for identifying routes, and a final set of compatible routes is then chosen. This routing methodology need not be limited to digital routing; it is directly applicable to analog routing.

### 4.6 Specialized Analog Routers

There are many applications in analog design which may require entirely different or enhanced routers compared to those discussed above. Two such applications are **RF circuit routing** and **analog array routing**.

### 4.6.1 Routing for RF Circuits

- The design of **RF circuits** has also been addressed recently in many design automation tools, though most concentrate on placement. Technologies such as **CYCLONE** use a tool for the complete layout of passive devices (inductors, transmission lines, capacitors), but the placement and routing are done by **LAYLA**. It is thus generally assumed that **maze and channel routing approaches are necessary** for routing RF circuits.
- **CORAL** (2003) is a routing tool targeted specifically for RF circuits. It adopts a routing arena (routing area) because of the importance of routing parasitics. The **N-type dibit** is used for maze routing. Parasitic effects such as **inductive and capacitive crosstalk** are modeled in terms of the degradation induced on the characteristics of the signal. Rather than the area-based model of a regular maze router, a **wire-based model** can be used. Analytical models of all considered parasitics are obtained by fitting appropriate mathematical expressions to data obtained from 2D and 3D field solvers.
- RF routing is performed in **two phases**:
  1. **Constraint-based routing**: Length constraints on interconnects cannot be effectively enforced during this phase.
  2. **Refinement phase**: A refinement scheme is applied after the constraint-based phase. It consists of **progressive expansion of all nets simultaneously**, thus allowing enforcement of all net constraints, while no new violations are created on remaining parasitic constraints.
- To achieve **high performance**, **channel segmentation** and **buffer insertion** are proposed along with phase-based routing. This is because in RF circuits, signal integrity depends heavily on routing parasitics, and the combined application of buffer insertion and segmentation can yield more optimal results.
- **Power routing** is handled explicitly: power and ground nets in RF circuits tend to have wider wires, and thus more optimal routing in **designated structures and reconfigurable CABs** (Fig. 4.26). These CABs in the example are all digitally configurable gate-level blocks. Thus every CAB can be configured on location such that necessary interconnection is provided.

### 4.6.2 Routing for Analog Arrays

- An important class of layout generation tasks has not been discussed yet: **Field Programmable Analog Arrays (FPAAs)**. FPAAs, analogous to FPGAs in digital design, are **reconfigurable analog platforms**.
- **FPAA architecture**: An FPAA is a highly regular architecture of basic cells (e.g., examples of the flash type: AD converters, Gilbert Neural Networks, or current-steering DAC converters). Typically, the regular structure used in analog blocks consists of an **array of unit cells** (generally with different versions), which process one or more signals in parallel via one or more output stages.
- **Routing challenges unique to FPAAs**:
  - More routing constraints must be incorporated since **routing resources are fixed** in number and preplaced
  - Constraints exist on **permissible connections**
  - Classical analog **channel routing algorithms are not very suitable** for array-based FPAAs because of the difficult nature of subdividing the routing problem into independent channels
  - FPGA routers cannot be used directly since they target typical FPGA architectures
  - Graph-based FPGA routers use **minimum-rectilinear-Steiner-tree (MRST) heuristics**, which is not quite necessary in most FPAA cases because of the inability to have bends in a route owing to the single-segment architecture
- **FAAR (FPAA Array Router)**: Accepts as input a netlist of placed CABs (Computational Analog Blocks) and IO cells, and the **parasitic bound** for each net that limits the number of switches used. This bound keeps performance degradation within acceptable limits.
- **Architectural parameters** modifiable by FAAR: size of the CAB array, number of tracks per horizontal channel and vertical channel.

#### Four Sub-problems of FPAA Routing

1. **Routing between two terminals of a net**: Find the shortest path between two terminals where the distance is defined by the number of routing resources required. Four types of possible alternative routes:
   - (a) Using the local interconnect (no global wires)
   - (b) Using one global wire if it is an allowed connection
   - (c) Using two global wires (one horizontal + one vertical) if they cannot share the same wire
   - (d) Using three global wires (two horizontal + one vertical, or vice versa) if neither terminal can make a connection to its allowed horizontal/vertical wire

2. **Routing multiterminal nets**: Find a minimum-length route between all terminals of a given net. A multiterminal net can be viewed as a set of two-terminal nets. All local connections are completed first, then the unconnected terminals are routed using global wires. **Sharing should be maximized** and as few additional routing resources as possible should be used.

3. **Routing multiple nets**: The problem is to find the shortest path between two terminals of a set of nets. Problems are to be solved simultaneously (this is the **compatibility problem**, and it is NP-complete). FAAR uses sequential routing and the problem is then addressed with **performance-constrained FPAA routing**: the main performance-degrading parasitics are identified as the number of switches (which bring additional resistance and capacitance to the corresponding path) and the number of net crossings (which bring parasitic coupling). A **parasitic bound** for each net limits the number of switches used.

4. **Routing as routing**: If the net's parasitic bound is violated, the net fails to keep its performance; FAAR then initially makes all possible connections using local interconnect, then subsequently routes each **unresolved destination terminal** to the source terminal using global interconnect. Each two-terminal net is added to the existing **partial routing tree**. As a built-in feature, FAAR tries to maximize reuse of the partial net route. Every routing resource used by a net is then block-listed for future use.

## 4.7 Manufacturability and Yield Issues in Routing

- The goal of a **performance-driven routing tool** is to route an analog circuit such that the **performance degradation** caused by layout parasitics remains within the specification margins imposed by the designer. For a given set of circuit specifications, several valid routing solutions can be found. Among these, the choice should be toward those solutions with **higher yield** and easier **manufacturability** and testability.
- Several algorithms have been proposed to increase yield in routing, but there have been **only for digital channels**. One of the first studies oriented toward yield maximization in analog routing is referenced to [71].
- **Sensitivity analysis** and **line expansion** routing are at the core of the performance-driven router. If the performance-driven router reports a routing solution that satisfies the performance constraints, a **testability and reliability optimization loop** is entered:
  1. **Defect files** (line, nets) are entered
  2. **Nets are removed and rerouted** until the available performance margin is consumed or a yield/testability improvement is found
  3. During **rerouting of a net**, the geometry of all other nets is known

### Specific Manufacturability Techniques

- **Photolithographic defects**: Can cause shorts between wires on the same routing level. The expected number of faults for two parallel conductors separated by a start-up $s$ can be calculated by combining the critical area as a function of the defect size $r$ and a defect size distribution function.
- The problem of **electroconnection** was addressed by developing a **current-driven router** [99, 100] and further studied in [101, 102]. The current path in each path was determined by simulations, either based on input parasites provided by the user, or based on Monte Carlo type simulations. The net widths were determined accordingly.
- **Connection of multifingered cells**: A **current density simulator** was developed to verify the layout. A comprehensive topology modification approach was developed based on **Kirchhoff's current laws** prior to detailed routing; at least the segments of all resistances to be connected must be known. A **terminal-to-terminal routing sequence** is then defined: the final terminal-to-terminal connections which directly link a new (yet unconnected) terminal with its respective target terminal add the least or no influence on current strength calculated in the prior routed subnet (with the calculation based on all terminals).
- Hence, the **main router-graft approach** provides for current-driven routing without preventing layout modification -- it is based on a **predefined terminal-to-terminal routing sequence**. The integration of this methodology within a constraint-based layout generator is described.

### Yield-Aware Routing Algorithm

The algorithms calculate the **wire widths** after routing a **terminal-to-terminal** routing tree that obtains a minimum total length, and later minimize the total area of the routing net. Another approach would be to construct the terminal tree, considering **minimum area estimation** [112], then consider annotating the connections after the area is within the initial estimate. The routing tree will be constructed as follows:

1. The terminal with **minimum current** value is selected, and its nearest neighbor is found
2. The pair of segments with minimum current is identified
3. A **current density simulator** checks the routing
4. The last terminal added onto the terminal tree will be the root node

## 4.8 Conclusions

- This chapter has given an **overview of routing techniques for analog layout** synthesis. Routers for full-custom analog circuits have been discussed based on the cost functions they are trying to minimize. Furthermore, domain-specific optimization strategies have been presented, and their suitability for routing has been explored.
- As a second routing problem, **template-based routing** has been dealt with. A new approach to this routing problem has been presented. Finally, routers for **RF circuits and analog arrays** have been discussed in addition to manufacturability and yield issues.
- **Key opinion from the authors**: The problem of routing analog circuits is still an open problem. It is affected directly by **process-level steps**, such as placement, partitioning, and module generation. One research direction would be to pass more effort into **one-step layout generation** rather than the conventional sequential approach.
- **Another open problem**: Routing of RF circuits, where every interconnect is actually a device. These interconnects must be carefully designed and modeled in the final layout. As the technology moves to **deeper submicron dimensions**, designs get more complicated. Performance, manufacturability and yield of a circuit become very important issues.
- **Template-based layout generation**: If a template precludes a few system variations, it becomes more appropriate and will probably become a commonly used layout generation approach in the near future. The same problem (namely routing at RF frequencies, or yield-aware routing) will still be valid for template-based approaches as well.

## Algorithms & Methods

### LDS (Layout Description Script) Template Compilation

1. Define the **routing template** as a set of geometric constraints in LDS (left, right, top, bottom relationships between wires W1, W2, ..., Wn)
2. For each constraint, encode minimum width rules: e.g., $\text{right}(W2) - \text{left}(W2) \geq \text{minWidth}(\text{MET1})$
3. Compile the LDS against specific device dimensions from the schematic
4. Solve the constraint system to produce the physical layout
5. The same template can be reused for different sizing -- only the constraint values change

### FAAR (FPAA Array Router) Algorithm

1. **Input**: Netlist of placed CABs and IO cells, parasitic bound per net
2. **Step 1**: For each net, identify all possible local interconnect connections
3. **Step 2**: Complete all local connections first
4. **Step 3**: For unconnected terminals, route using global wires:
   - Try single global wire first
   - If not possible, try two global wires (horizontal + vertical)
   - Last resort: three global wires
5. **Step 4**: For multiterminal nets, maximize sharing of routing resources
6. **Step 5**: Check parasitic bounds -- if violated, attempt rerouting with alternative paths
7. **Constraint**: The number of switches on any path must remain below the parasitic bound to maintain performance

### Current-Driven Routing (Yield-Aware)

1. Perform initial routing to obtain a minimum-length terminal-to-terminal tree
2. Run **current density simulation** on the routed net
3. Calculate wire widths based on current densities
4. Apply **Kirchhoff's current laws** to determine current distribution
5. Define a **terminal-to-terminal routing sequence** that minimizes current density impact
6. The terminal with minimum current is selected first; its nearest neighbor is found
7. Iterate: each new terminal added to the tree contributes minimal additional current to the previously routed subnet
8. Final step: minimize total area of the routing net while satisfying current density constraints

## Connections to Bigger Picture

This sub-chapter bridges the gap between general-purpose analog routing (covered in [[4.3 Analog Routing Fundamentals]] and [[4.5 Advanced Routing Strategies]]) and the domain-specific challenges that arise in specialized analog applications like RF and FPAA design. The discussion of manufacturability and yield in Section 4.7 connects directly to the broader theme of the book -- that analog layout synthesis must consider not just connectivity but also physical effects (parasitics, current density, photolithographic defects) that impact circuit performance. The chapter's conclusion explicitly advocates for **one-step layout generation** over sequential placement-then-routing, foreshadowing the retargeting-based approaches discussed in [[5.1 Introduction to Layout Retargeting]].
