# 2.5 The HB-Tree Algorithm

> **Chapter 2**: Hierarchical Placement with Layout Constraints (Lin & Chang)
> **Part**: Part I: Placement

## Key Concepts

The placement algorithm operates on top of the [[2.4 The Hierarchical Framework|HB*-tree and ASF-B*-tree]] data structures using **simulated annealing** (SA). Given a set of modules and symmetry constraints, it constructs an initial HB*-tree solution and iteratively perturbs it to search for a desired configuration until a termination condition is met.

### Cost Function

The placement cost function $\Phi(P)$ combines area and wirelength:

$$\Phi(P) = \alpha \cdot A_P + \beta \cdot W_P$$

where:
- $\alpha, \beta$ are user-specified weighting parameters
- $A_P$ is the area of the bounding rectangle of the placement
- $W_P$ is the **half-perimeter wire length (HPWL)**

### Simulated Annealing Setup

- **Initial solution**: a left-skewed HB*-tree
- **Initial temperature**: $T_0 = -\Delta_{\text{avg}} / \ln P$, where $\Delta_{\text{avg}}$ is the average uphill cost and $P$ is the initial acceptance probability for uphill moves
- **Cooling schedule**: temperature reduced by factor 0.9 per pass
- **Iterations**: 20,000 per temperature/pass

## Algorithms & Methods

### 2.5.1 HB*-Tree Perturbation

Three perturbation operations are applied to the HB*-tree:

- **Op1 -- Rotate a module**: Changes a module's orientation (width/height swap).
- **Op2 -- Move a node**: Relocates a node to another position in the tree.
- **Op3 -- Swap two nodes**: Exchanges the positions of two nodes in the tree.

**Key constraints on perturbation:**
- **Non-hierarchy nodes have higher selection probability** because rotating, moving, or swapping hierarchy nodes causes large jumps in solution space, which can deteriorate SA quality.
- A non-hierarchy node **cannot** be moved to the right child of a hierarchy node or the left child of a contour node (these positions are structurally reserved per [[2.4 The Hierarchical Framework|Property 2.2]]).
- **Contour nodes always move with their hierarchy node** and cannot be moved individually.

### 2.5.2 ASF-B*-Tree Perturbation

In addition to Op1--Op3, two additional operations are introduced for perturbing [[2.3 Placement of a Symmetry Group|ASF-B*-trees]]. All perturbations must preserve **Property 2.1** (the left-boundary / right-boundary constraint for self-symmetric modules).

#### Op4 -- Representative Change (Section 2.5.2.4)

Changes which module serves as the representative for a symmetry pair or self-symmetric module. This optimizes **wirelength without changing area**.

- **Case 1 (Symmetry pair)**: For a pair $(b_j, b_j')$, the representative switches from $b_j$ to $b_j'$ or vice versa. This can shorten wire length to nearby connected modules (see Fig. 2.16).
- **Case 2 (Self-symmetric module)**: For a self-symmetric module $b_k^s$, the representative is changed by flipping it horizontally or vertically according to its symmetry axis (see Fig. 2.17).
- **Complexity**: Each operation takes **constant time** $O(1)$.

#### Op5 -- Symmetry-Type Conversion (Section 2.5.2.5)

Converts between vertical and horizontal symmetry for a symmetry group.

- **Case 1**: Vertical symmetry $\to$ horizontal symmetry
- **Case 2**: Horizontal symmetry $\to$ vertical symmetry

**Procedure**: First rotate every module (including the representative), then swap the left and right children of each node in the ASF-B*-tree (see Figs. 2.18 and 2.19).

> **Note**: The symmetry type is usually predefined by the analog designer based on power/ground lines or signal flows. Therefore, Op5 is **seldom applied** in real applications.

#### Module Rotation (Section 2.5.2.1)

When rotating modules within a symmetry group, the ASF-B*-tree structure remains unchanged.

- **Case 1 (Symmetry pair)**: Both modules in the pair must be rotated simultaneously to maintain symmetric placement relative to the symmetry axis.
- **Case 2 (Self-symmetric module)**: After rotation, the shape of the representative must be updated accordingly (see Fig. 2.15 -- the representative covers only half the module).

#### Node Movement (Section 2.5.2.2)

- **Case 1 (Symmetry pair representative)**: Can be moved to **any** position in the ASF-B*-tree.
- **Case 2 (Self-symmetric module representative)**: Can only be moved **along the rightmost (leftmost) branch** of the ASF-B*-tree for vertical (horizontal) symmetric placement, so that Property 2.1 remains satisfied.

#### Node Swapping (Section 2.5.2.3)

- **Case 1 (Two symmetry-pair representatives)**: Can be **arbitrarily swapped**.
- **Case 2 (At least one self-symmetric module representative)**: The other node must be located on the **same branch** (leftmost or rightmost) of the ASF-B*-tree, preserving Property 2.1.

### 2.5.3 Contour Node Related Updates

When an ASF-B*-tree is perturbed, the number of top contour segments of the symmetry island may change, requiring updates to the corresponding contour nodes in the HB*-tree.

**Two scenarios:**
1. **Contour nodes increase**: The HB*-tree structure can be kept unchanged (new contour nodes are simply added).
2. **Contour nodes decrease**: Some nodes lose their parents and become **dangling nodes**. These must be reassigned:
   - Find the **nearest contour node** for each dangling node.
   - If the nearest contour node has **no right child**, the dangling node becomes its right child.
   - If it **has a right child**, traverse to the **leftmost-skewed child** of that right child. The dangling node is assigned as the left child of that leftmost-skewed child.

**Complexity**: Amortized **constant time** $O(1)$ to update contour-related nodes.

**Example** (Fig. 2.20): After performing Op2 on an ASF-B*-tree with three contour segments that reduces to one contour segment, two contour nodes disappear and the previously attached nodes $n_3$ and $n_5$ become dangling. They are reassigned by searching for the nearest contour node $n_0'$ and traversing its right-child subtree to find insertion points.

## 2.6 Comparisons with Other Approaches

### 2.6.1 Time Complexity Comparison

The table below compares perturbation and packing times for all major topological analog placement approaches with symmetry constraints ($n$ = number of modules, $m$ = number of symmetry pairs):

| Approach | Perturbation Time | Packing Time |
|---|---|---|
| B\*-tree [1] | $O(\lg n)$ | $O(n^2)$ |
| B\*-tree + Segment tree [3] | $O(\lg n)$ | $O(n \lg n)$ |
| B\*-tree + RB-tree [4] | $O(\lg n)$ | $O(n \lg n)$ |
| B\*-tree + Skip list [26] | $O(\lg n)$ | $O(n \lg n)$ |
| Sequence Pair (SP) [2] | $O(1)$ | $O(n^2)$ |
| SP + LP [14] | $O(1)$ | $\Omega(n^2)$ |
| SP w. dummy [31] | $O(1)$ | $O(n^2)$ |
| SP w. priority queue [15] | $O(1)$ | $O(m \cdot n \lg \lg n)$ |
| TCG-S [22] | $O(n^2)$ | $O(n^2)$ |
| TCG [34] | $O(n)$ | $O(n^2)$ |
| B\*-tree w. ESF + LP [30] | N/A | $\Omega(n^2)$ |
| **ASF-B\*-tree + HB\*-tree** | $O(\lg n)$ | **$O(n)$** |

The **ASF-B\*-tree + HB\*-tree is the only approach achieving linear-time packing** $O(n)$, which is the key theoretical advantage. Approaches using linear programming (LP) have at least $\Omega(n^2)$ packing time. The deterministic approach [30] does not require perturbation since it enumerates all configurations.

### 2.6.2 Experimental Results

Experiments were run on a 3.2 GHz Intel Pentium 4 under Linux, using two benchmark sets:

**MCNC Benchmarks** (apte, hp, ami33, ami49):
- HB\*-tree achieved average area reductions of **3%, 2%, 1%, and 2%** over SP [2], Segment tree [3], TCG-S [22], and SP w. dummy [31], respectively.
- Speedup approximately **4.09x** faster than SP w. dummy [31].
- The area improvements come from both the symmetry-island formulation (pruning undesired solutions) and the short linear-time packing.

**Industry Benchmarks** (biasynth\_2p4g, lnamixbias\_2p4g):
- HB\*-tree achieved average area reductions of **7.1%, 6.6%, 1.6%, and 10.3%** over SP [2], Segment tree [5], SPCLP [14], and SP w. dummy [31].
- **Without module rotation**: only 2.4% and 4% area overhead compared to SPCLP [14] and HB\*-tree with rotation.
- Speedups: approximately **39.88x** over SPCLP [14] and **5.68x** over SP w. dummy [31].

## 2.7 Advanced Symmetry Constraints

### 2.7.1 Multiple Symmetry-Group Alignment

In some analog layouts, the symmetry axes of different symmetry groups must be **aligned to share a common symmetry axis**. The technique:

- Insert a **zero-height (zero-width) dummy block** at the left (bottom) of each to-be-aligned symmetry island.
- Introduce a **dummy node** as the parent of the hierarchy node representing the corresponding symmetry island in the HB\*-tree. The hierarchy node becomes the left (right) child of this dummy node.
- By adjusting the width (height) of each dummy block, the symmetry islands can be aligned to a common vertical (horizontal) axis.

This is an extension of the alignment technique in [32].

### 2.7.2 Non-Symmetry-Island Placements

The ASF-B\*-trees and HB\*-trees can also generate **non-symmetry-island placements** by integrating nonsymmetric modules into symmetry groups:

- **Self-symmetric cluster**: Nonsymmetric modules (e.g., $b_3, b_4$) form a self-symmetric module cluster $C_1$ within a symmetry group. After packing the B\*-tree for the cluster, a representative node $n_{C_1}^r$ is introduced in the ASF-B\*-tree (Fig. 2.24a).
- **Symmetry pair of clusters**: Nonsymmetric modules form two clusters ($C_2$ and $C_2'$) as a symmetry pair. A representative node $n_{C_2}^r$ denotes the larger dimensions of both cluster placements (Fig. 2.24b).

## 2.8 Hierarchical Constraints

### 2.8.1 Hierarchical Symmetry

For **fully symmetric analog designs** (e.g., Fig. 2.3), device layouts must be hierarchically symmetric. A symmetry group $S_i$ may contain:
- A self-symmetry group $S_j^s$
- A symmetry-group pair $(S_k, S_k')$

The top-level symmetry group $S_{Top}$ contains all device modules and other symmetry groups hierarchically. A **hierarchical tree structure** mixing both ASF-B\*-trees and HB\*-trees is constructed. The optimized fully symmetric placement is obtained by searching a desired tree configuration and packing hierarchically to form symmetry islands.

### 2.8.2 Hierarchical Clustering / Proximity

The HB\*-tree also handles **hierarchical clustering constraints** in analog placement and mixed-signal floorplanning.

Let $C = \{C_1, C_2, \ldots, C_l\}$ be a set of device module clusters. Each cluster contains at least two modules, or one module and one other cluster, or two other clusters. If $C_i$ contains $C_j$, then $C_i$ is a **super-cluster** and $C_j$ is a **sub-cluster**. The constraint requires all modules/subclusters of the same super-cluster to have a **connected placement**.

**Formulation**: Each hierarchy node $n_{C_i}$ denotes a cluster and contains another HB\*-tree representing topological relations within that cluster. The number of HB\*-trees equals the number of subcircuits plus one (for the top design).

**Perturbation**: Select one of the HB\*-trees, then apply any B\*-tree perturbation to it.

**Packing**: Uses preorder tree traversal (like B\*-tree packing). When a hierarchy node is traversed, its linked HB\*-tree nodes are traversed before continuing to the next node in the parent HB\*-tree. Proximity constraints are also considered during packing.

**Integration with other approaches**: The HB\*-tree framework can integrate:
- Corner block list (CBL) and grid-based approaches for **common-centroid placement**
- Signal-flow driven approaches for subcircuits with clear signal flows
- Other specialized placement approaches for different subcircuit requirements

## 2.9 Conclusion

The chapter introduced the **HB\*-tree**, a hierarchical analog placement framework that considers layout design hierarchy and hierarchical placement constraints. The key contributions:

1. **Linear-time packing** -- different from all existing approaches which require at least log-linear time
2. **Symmetry-island formulation** -- prunes the solution subspace formed by non-symmetry-island placements, avoiding redundant search
3. **High quality and efficiency** -- experimental results demonstrate superior area utilization and runtime efficiency compared to all prior topological approaches

## Connections to Bigger Picture

This sub-chapter completes the algorithmic description of the HB\*-tree placement framework introduced in [[2.4 The Hierarchical Framework]]. The SA-based algorithm with its five perturbation operators (Op1--Op5) is the engine that searches the solution space defined by the ASF-B\*-tree and HB\*-tree representations from [[2.3 Placement of a Symmetry Group]]. The linear-time packing complexity is the central theoretical result that distinguishes this work from all prior topological approaches, enabling significantly faster SA iterations and therefore better solution quality within the same runtime budget. The advanced symmetry constraints (Section 2.7) and hierarchical constraints (Section 2.8) extend the framework's applicability to fully symmetric designs and mixed-signal floorplanning, bridging toward the deterministic placement methods covered in [[3.1 Introduction to Deterministic Analog Placement]].
