# 3.2 Placement Constraint Generation

> **Chapter 3**: Deterministic Analog Placement by Enhanced Shape Functions (Strasser, Eick, Graeb, Schlichtmann)
> **Part**: Part I: Placement

This section describes how placement constraints (symmetry, matching, proximity) are systematically extracted from a circuit netlist and organized into a hierarchical structure suitable for the deterministic placer **Plantage**. The pipeline has three stages: (1) identify placement requirements, (2) build an SMP graph encoding all pairwise requirements, (3) cluster the SMP graph into a hierarchical HSMPG tree, and (4) translate the tree into placer-specific constraints.

## Key Concepts

### 3.2.1 Placement Requirements

A **placement requirement** encodes a constraint that two or more devices must satisfy in the final layout. Each requirement has a **type** $t \in T$ drawn from five categories:

| Symbol | Type | Origin | Meaning |
|--------|------|--------|---------|
| $M_S$ | Matching (symmetry) | Symmetric device pairs | Devices must have equal electrical properties; arises from differential symmetry |
| $M_B$ | Matching (building block) | Recognized building blocks | Devices inside the same functional block must match (e.g., current mirror transistors) |
| $P_B$ | Proximity (building block) | Building blocks | Devices of a block must be spatially close |
| $S$ | Symmetry | Symmetry compounds | Device coordinates must satisfy the symmetry equations from [[3.1 Introduction to Deterministic Analog Placement|Section 3.1]]: $x_i = 2c - x_{i'}$ and $y_i = y_{i'}$ |
| $P_N$ | Proximity (netlist) | Netlist connectivity | Devices sharing a net should be close for shorter routing |

#### Importance Order

When multiple requirements conflict, a **strict priority order** resolves them:

$$M_S \succ M_B \succ P_B \succ S \succ P_N$$

**Rationale**: Matching from symmetric device pairs ($M_S$) is the most critical because it preserves differential balance (e.g., offset error). Matching inside building blocks ($M_B$) is next -- a mismatch there affects gain but not offset. Building-block proximity ($P_B$) outranks symmetry ($S$) because proximity requirements exist only *within* blocks and therefore do not conflict with symmetry requirements across blocks. Netlist proximity ($P_N$) is least important.

**Example**: In a fully differential circuit with transistors $N_1$--$N_4$ where $(N_1, N_3)$ and $(N_2, N_4)$ form current mirrors and $(N_1, N_2)$, $(N_3, N_4)$ are symmetric pairs: the $M_S$ matching between $N_1$/$N_2$ and $N_3$/$N_4$ takes priority over the $M_B$ matching within each current mirror, because violating cross-pair symmetry degrades offset (critical), while violating intra-mirror matching degrades gain (less critical).

### 3.2.2 SMP Graph and Its Generation

**Definition (SMP Graph)**: The SMP graph $G_{SMP}(N_{SMP}, E_{SMP}, t_{SMP})$ is an undirected multigraph where:
- **Nodes** $N_{SMP}$ = devices of the circuit
- **Edges** $E_{SMP}$ = pairwise placement requirements (multiple edges allowed between the same pair)
- **Type function** $t_{SMP}: E_{SMP} \to T$ assigns each edge its requirement type

The SMP graph is built incrementally in three steps:

#### Step 1: Netlist Proximity Initialization

For every net $n$ in the circuit, a **complete subgraph** (clique) is created among all devices connected to $n$, with every edge typed $P_N$. This ensures devices sharing a net are encouraged to be placed nearby for shorter routing.

#### Step 2: Building Block Recognition

Building blocks are identified via **subgraph isomorphism** against a library of known analog structures. The library includes:

- **Two-transistor blocks** (differential pair, level-shifter, simple current mirror): one $M_B$ matching edge between $T_1$ and $T_2$
- **Four-transistor blocks** (cascode current mirror, 4-transistor current mirror, wide-swing current mirror): two $M_B$ matching edges ($T_1$--$T_2$ and $T_3$--$T_4$) plus two $P_B$ proximity edges ($T_1$--$T_3$ and $T_2$--$T_4$)

For the example amplifier, five simple current mirrors ($cm_1$--$cm_5$) and one differential pair ($dp_1$) are recognized.

#### Step 3: Symmetry Analysis

The symmetry analysis algorithm (similar to the approach in [10]) identifies **symmetric device pairs** and groups them into **symmetry compounds**.

- A **symmetry compound** $C$ is a set of device pairs sharing the same symmetry axis
- For each pair in $C$: an $M_S$ edge is added
- For the whole compound: a complete subgraph of $S$ edges is added (reflecting the shared axis constraint)

For the example circuit, four symmetric pairs are found:
$$p_1 = (P_1, P_2), \quad p_2 = (N_1, N_2), \quad p_3 = (N_3, N_4), \quad p_4 = (P_3, P_4)$$

forming one symmetry compound $C_1 = \{p_1, p_2, p_3, p_4\}$ and thus $\mathcal{S} = \{C_1\}$.

### 3.2.3 HSMPG Tree and Its Generation

**Definition (HSMPG Tree)**: A **Hierarchical Symmetry/Matching/Proximity Group tree** is a tree structure where:
- **Leaf nodes** = individual devices
- **Inner nodes** = groups, each with a type:
  - **Proximity Group (PG)**: children should be placed close together
  - **Matching Group (MG)**: children must have matched layouts
  - **Symmetry Group (SG)**: children must satisfy symmetry coordinate constraints

#### Generation Algorithm (Algorithm 3.1)

The algorithm is an **agglomerative clustering** method driven by the importance order. It processes requirement types from highest priority ($M_S$) to lowest ($P_N$):

```
Input:  SMP graph G_SMP, importance-ordered type set T_I
Output: HSMPG tree

for each tau in T_I from max(T_I) to min(T_I):
    1. FILTER: Extract subgraph G*_SMP containing only edges of type tau
       and their incident nodes
    2. CONNECTED COMPONENTS: Find all connected components G_SMPC,i of G*_SMP
    3. CREATE GROUPS: For each component with |N_SMPC,i| > 1,
       create a new group:
         - tau in {M_B, M_S}  -->  Matching Group (MG)
         - tau = S            -->  Symmetry Group (SG)
         - tau in {P_B, P_N}  -->  Proximity Group (PG)
       The component's nodes become children of the new group.
    4. BUILD SUPER NODES: Replace each new group's nodes with a single
       super node in G_SMP. Redirect edges accordingly.
```

#### Worked Example

For the amplifier circuit, processing proceeds as follows:

| Iteration | Type | Action | Groups Created |
|-----------|------|--------|----------------|
| 1 | $M_S$ | Symmetric pairs clustered | $MG_{S,1}(P_1,P_2)$, $MG_{S,2}(N_1,N_2)$, $MG_{S,3}(N_3,N_4)$, $MG_{S,4}(P_3,P_4)$ |
| 2 | $M_B$ | Building block matches clustered | $MG_{B,1}(MG_{S,2}, MG_{S,3})$, $MG_{B,2}(P_5,P_6,P_7)$ |
| 3 | $S$ | Symmetry compound clustered | $SG_1(MG_{S,1}, MG_{B,1}, MG_{S,4})$ |
| 4 | $P_N$ | Remaining netlist proximity | $PG_{N,1}$ (entire circuit) |

The final tree has $PG_{N,1}$ at the root, containing $SG_1$, $MG_{B,2}$, $MG_{S,4}$, device $N_5$, and capacitor $C_C$.

#### Discussion

The static importance order has produced correct results across all experiments reported by the authors. However, a **dynamic approach** is possible: one could use circuit simulation to determine a priority function $\Phi: E_{SMP} \to \mathbb{N}$ that assigns each edge a priority based on the performance impact of violating that constraint, then process edges in order of decreasing $\Phi$.

### 3.2.4 Constraint Generation

The HSMPG tree is translated into **placer-specific constraints** for Plantage (see [[3.3 B-Tree Placement with Constraints]]):

#### Matching Groups (MG)

- **Same layout variants**: all devices in the group must use the same layout variant (orientation, finger count, etc.)
- **Alignment constraint**: device centers are aligned along one axis
- **Inherent proximity**: grouping already ensures spatial closeness
- **Common centroid**: if devices consist of multiple subdevices (e.g., parallel sub-transistors), the alignment constraint is replaced by a **common centroid constraint**

#### Symmetry Groups (SG)

The hierarchy is exploited to implement the symmetry equations $x_i = 2c - x_{i'}$ and $y_i = y_{i'}$:

1. **Symmetry (pair) constraint**: Inside each $M_S$-matching group, device centers are aligned in the direction of the symmetry axis. For a vertical axis:

$$y_{P_1} = y_{P_2}, \quad y_{N_1} = y_{N_2}, \quad y_{N_3} = y_{N_4}, \quad y_{P_3} = y_{P_4}$$

2. **Symmetry (groups) constraint**: For each matching group $MG_{S,i}$ the center in $x$-direction is computed as:

$$x_{MG_{S,i}} = \frac{1}{2}(x_{m_1} + x_{m_2})$$

where $m_1, m_2$ are the group's two modules. Then all group centers are aligned:

$$x_{MG_{S,1}} = x_{MG_{S,2}} = x_{MG_{S,3}} = x_{MG_{S,4}}$$

Together, these two constraints implement the full symmetry conditions.

#### Proximity Groups (PG)

**No explicit constraints** are generated. The placement algorithm constructs the layout bottom-up using the HSMPG tree hierarchy, which inherently keeps elements of each group in close spatial proximity.

## Algorithms & Methods

### Algorithm 3.1: HSMPG Tree Generation

```
Input:  SMP graph G_SMP, importance ordered type set T_I
Output: HSMPG tree

FOR EACH tau in T_I from max(T_I) to min(T_I):
    G*_SMP       <-- filter(G_SMP, tau)
    G_SMPC       <-- connectedComponents(G*_SMP)
    Gamma        <-- createGroups(G_SMPC, tau)
    G_SMP        <-- buildSuperNodes(G_SMP, Gamma)
```

**Complexity**: The algorithm iterates over $|T| = 5$ requirement types. For each type, it performs graph filtering ($O(|E|)$), connected component detection ($O(|N| + |E|)$), and super-node construction ($O(|E|)$). Overall complexity is $O(|T| \cdot (|N| + |E|))$.

### Building Block Recognition

Based on the algorithm from [13]: finds subgraph isomorphisms between the netlist and a library of known building blocks. Each library element defines:
- The block's topology (transistor connectivity)
- Associated placement requirements (matching and proximity edges to add to the SMP graph)

### Symmetry Analysis

Similar to [10]: identifies symmetric device pairs by analyzing the circuit structure. All pairs sharing the same symmetry axis are grouped into a symmetry compound $C$. The set of all compounds is $\mathcal{S}$.

## Connections to Bigger Picture

The placement constraint generation described in Section 3.2 is the critical bridge between circuit-level analysis and the deterministic placement engine. It takes raw netlist information, building block structure, and symmetry properties and distills them into a compact hierarchical representation (the HSMPG tree) that the B*-tree-based placer in [[3.3 B-Tree Placement with Constraints]] can directly consume. The importance ordering ensures that the most performance-critical constraints (differential matching) are never violated in favor of less critical ones (netlist proximity). This hierarchical approach also connects to the broader theme in the book of exploiting analog circuit structure -- similar ideas appear in hierarchical sizing and routing. The constraint generation methodology is deterministic and systematic, in contrast to the heuristic or optimization-based constraint handling seen in simulated-annealing placers discussed in [[2 Template-Based Analog Layout Synthesis|Chapter 2]].
