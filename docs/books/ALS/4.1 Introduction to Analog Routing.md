# 4.1 Introduction to Analog Routing

> **Chapter 4**: Routing Analog Circuits (Dundar & Unutulmaz)
> **Part**: Part II: Routing

## Key Concepts

Routing is one of the **final steps** in analog layout synthesis. Its main objective is to electrically connect terminals of layout modules (transistors, capacitors, differential pairs, etc.) and I/O ports using conductor paths (wires).

### Why Analog Routing is Harder than Digital

- **Parasitic sensitivity**: Analog circuit performance is critically dependent on layout parasitics (wire resistance, coupling capacitance, substrate coupling). Digital circuits are largely immune to these effects.
- **Fewer nets, more constraints**: Analog ICs typically have fewer routing paths than digital ICs, but each path carries significantly more constraints (matched lengths, symmetric routing, shielding, current density requirements).
- **Upstream dependency**: Routing quality is strongly affected by all preceding synthesis steps -- [[3.5 Hierarchically Guided Enumeration|device generation]], folding, merging, placement, and shaping. A sophisticated router cannot rescue a poor placement.

### The Impact of Device Merging on Routing

Device merging reduces both the number of required connections and the associated parasitics. Even for a simple differential input stage of an OPAMP, merging transistors dramatically decreases routing overhead (Fig. 4.1).

![[assets/ch4-intro-163.png]]
*Fig. 4.1: Routing overhead (black rectangles) for the differential input stage of an OPAMP. (a) Without merging -- many wires required. (b) After merging transistors -- routing overhead is considerably reduced. This demonstrates that routing quality depends heavily on folding, merging, placement, and device shaping.*

## Algorithms & Methods

### 4.2.1 Maze Router (Lee's Algorithm)

**Lee's maze routing algorithm** [Lee, 1961] is one of the earliest and most well-known wire routing algorithms, extending Moore's earlier work to uniform grids.

**How it works:**
1. **Wave propagation**: Number every grid point starting from the source $S$. Propagate the wavefront outward, assigning increasing numbers to each reachable grid point.
2. **Termination**: Continue until the wavefront reaches the target $T$.
3. **Backtracing**: Trace back from $T$ to $S$ by following decreasing numbers to extract the shortest path.

**Properties:**
- **Guaranteed to find a solution** if one exists
- **Solution is the shortest path**
- **Time complexity**: $O(n \cdot m)$ where $n$ and $m$ are the grid dimensions
- **Memory**: Each grid point requires a memory location for each layer -- extremely large memory for large grids
- Historically the **dominant** solution for wiring at both PCB and IC level

![[assets/ch4-maze-router-164.png]]
*Fig. 4.2: Lee's maze routing algorithm. A wave starting from source S is propagated to target T. Numbers denote wave numbers; X denotes obstacles. By backtracking, the shortest path (gray) is found.*

### 4.2.2 Line Expansion Routers (Line-Search)

Line-search algorithms represent the search space using **line segments** rather than individual grid points.

**How it works:**
1. Add horizontal and vertical line segments around the source, target, and obstacles.
2. Combine these line segments to construct a path from $S$ to $T$.

**Advantages over maze routing:**
- **Reduced memory**: No per-grid-point allocation
- **Reduced run time**: Fewer elements to process
- **Fewer unnecessary bends** in routes

**Disadvantages:**
- **No guarantee of shortest path**
- Becomes cumbersome as routing complexity increases -- memory and computation can surpass the maze router in complex cases
- Some variants (e.g., Heyns et al.) do **not guarantee** finding a solution even when one exists

### 4.2.3 Channel Routing

Channel routing is commonly used in digital design and was adopted by early analog routers. It routes within **channels** -- horizontal areas with fixed pins on top and bottom.

**Problem formulation:**
- Pins on top and bottom of a channel are labeled with net numbers
- Pins with the same number belong to the same net (must be connected)
- Pins with different numbers must be electrically isolated
- Channel height is computed by the router (not specified in advance)

**Two constraint graphs** are extracted from pin positions:

1. **Vertical Constraint Graph (VCG)**: Directed graph. Vertex $v_x$ for each net $x$. Edge $(v_x, v_y)$ added if pins in nets $x$ and $y$ overlap horizontally and pin $x$ is above pin $y$. Handles vertical ordering of nets.

2. **Horizontal Constraint Graph (HCG)**: Undirected graph. Vertex for each net. Edge $(v_x, v_y)$ added if horizontal spans of nets $x$ and $y$ overlap. Handles horizontal span conflicts.

**Solving the channel routing problem:**
- If VCG has **no edges**: solvable by the **Left-Edge Algorithm** [Hashimoto & Stevens]
- If VCG has **acyclic constraints**: solvable by the **Constrained Left-Edge Algorithm**
- If VCG has **cyclic constraints**: more complex approaches needed (e.g., Yoshimura & Kuh; Rivest & Fiduccia; Luk)

**Limitation for analog**: Poor estimation of parasitic effects, so channel routing is not commonly preferred in modern analog tools.

### 4.2.4 Steiner Routing

When routing nets with **more than two terminals**, the problem becomes NP-complete -- this is the **Steiner Problem** (named after Jacob Steiner, 1796-1863).

**Key tree types:**

| Tree | Description |
|------|-------------|
| **SMT** (Steiner Minimal Tree) | Connects nets with minimum total wirelength, allows arbitrary angles |
| **MRST** (Minimum Rectilinear Steiner Tree) | Only horizontal and vertical paths allowed; computationally cheaper than SMT |
| **Rectilinear MST** (Minimum Spanning Tree) | All wires go terminal-to-terminal, no intermediate Steiner points |

**Important bound**: In the worst case, the rectilinear MST solution is at most **1.5 times longer** than the MRST solution.

**Heuristic approaches to Steiner routing:**
1. Find an approximate Steiner point, then apply maze routing between terminals and the Steiner point.
2. Apply maze routing between a pair of points; once a path is found, use it as a new source for subsequent wavefronts.

**Extensions over the years:**
- Diagonal routing (beyond just horizontal/vertical)
- Multiple routing layers
- Performance-aware criteria
- Technology-specific optimizations

## Representations (Section 4.3)

### 4.3.1 Layout Representations

Three traditional representations exist for the routing problem:

#### Grid-Based Representations

**Uniform Grid:**
- Simplest representation, used since Lee's original algorithm
- **Trade-off**: Fine grid $\rightarrow$ dense layouts but excessive memory; Coarse grid $\rightarrow$ larger layouts but less memory
- Cannot precisely represent wires with dimensions comparable to the grid size
- Variable-width routing and constraint observance are difficult

**Nonuniform Grid:**
- Grid lines are placed at component boundaries (extended to layout edges)
- More memory-efficient than uniform grids
- Can be much finer in congested areas
- Faster parasitic evaluation than tile-based structures (neighborhood info is embedded in the regular structure)
- Grid cell count can be reduced by using component boundaries as blocks for boundary extension

**Grid Graph** $G(V, E)$: Constructed from the nonuniform grid where $V$ = set of empty cells, $E$ = edges connecting neighboring cells. Used for pathfinding with graph algorithms.

**Channel Intersection Graph**: A variant where vertices are channel intersection points and edges are channel segments. Suitable for line expansion-based routing.

**Design rule integration**: Component dimensions are expanded by minimum space requirements for their layer. Source/target terminals are NOT expanded (otherwise the router could not connect to them).

![[assets/ch4-grid-representations-170.png]]
*Fig. 4.7: Nonuniform grid representations. (a) Grid constructed by extending component boundaries. (b) Reduced grid using component boundaries as blocks. (c) Grid graph extracted from (a). (d) Grid with layer spacing added around components to prevent DRC violations.*

#### Tile-Based Representations

- Based on the **corner stitching** data structure [Ousterhout], which ties layout components via pointers at their corners
- Stores both empty spaces and layout components
- Suits **line expansion algorithms** (e.g., ANAGRAM II)
- **Advantage**: Handles blocks of very different dimensions efficiently (e.g., capacitors vs. transistors)
- **Disadvantage**: More complicated; may require **escape points** (points that are not tile corners) during path searching, which enlarges the tile graph
- A **tile graph** $G(V, E)$ is extracted for use with graph algorithms

#### Topological Representations

- Include slicing trees, **sequence-pair** (SP), and **O-trees**
- Represent **relative positioning** of blocks -- efficient for modeling placement constraints including symmetries
- Some have been proposed for simultaneous placement and routing: SP, Multi-layer SP, Channeled-BSG
- **Limitation**: Poor at extracting layout parasitics because block and wire vicinities are only partially expressed
- **Better suited to placement than routing**

### 4.3.2 Connectivity Representation

Routers frequently perform **rip-up and re-route** to improve routing quality, which changes connectivity information. Checking connectivity through layout extraction every iteration is too slow. A dedicated data structure is needed.

**Requirements:**
- Support **net-splitting** (separate high-current from low-current paths to prevent voltage drops)
- Fast servicing of connectivity queries
- Efficient nearest-connectable-component lookup

**Data structure hierarchy:**
$$C = \{N_{\text{Gnd}}, N_{\text{Vdd}}, N_i, \ldots\}$$

Each net $N_i$ is a set of **subnets**: $N_i = \{S_{i1}, S_{i2}, \ldots\}$

Each subnet $S_{ij}$ is a set of **groups**: $S_{ij} = \{G_{ij1}, G_{ij2}, \ldots\}$

Each group $G_{ijk}$ contains **layout components** $\{e_l\}$.

**Semantics:**
- Same **group** = physically connected
- Same **subnet**, different groups = connection expected but not yet made
- **Subnets** enable net-splitting: each subnet covers wires with similar current densities

### 4.3.3 Rule Representations

Design rules and electrical characteristics are checked frequently during routing. The time complexity of the router depends directly on the service time of these lookups.

**Data structure**: A hierarchy of **hash tables** indexed by layer identifiers.
- First-level hash table: keyed by Layer1, stores addresses of second-level hash tables
- Second-level hash table: keyed by Layer2, stores rule values (e.g., capacitance between layers)
- Provides **constant-time** rule lookup
- Example: `get_capacitance_between(layer1, layer2)` returns the inter-layer capacitance in $O(1)$
