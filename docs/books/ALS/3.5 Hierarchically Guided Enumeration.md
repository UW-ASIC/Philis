# 3.5 Hierarchically Guided Enumeration

> **Chapter 3**: Deterministic Analog Placement by Enhanced Shape Functions (Strasser, Eick, Graeb, Schlichtmann)
> **Part**: Part I: Placement

---

## Key Concepts

### 3.5.1 The Combinatorial Explosion Problem

A complete enumeration of the solution space would yield the globally optimal placement, but is computationally infeasible for realistic circuits:

- For $n = 4$ modules, there are **336** distinct B*-trees
- For $n = 8$ modules, there are **57,657,600** distinct B*-trees
- The number of B*-trees grows super-exponentially with $n$, making brute-force enumeration impossible for practical circuits

The solution: **hierarchy-guided enumeration**, where the [[3.2 Placement Constraint Generation|HSMPG tree]] (Hierarchical Symmetry, Matching, and Proximity Group tree) partitions the problem into tractable subproblems.

### 3.5.2 Bottom-Up Enumeration via the HSMPG Tree

The HSMPG tree (automatically generated from the netlist, see [[3.2 Placement Constraint Generation]]) defines a hierarchical decomposition:

- **Root node** = the whole circuit
- **Leaf nodes** = individual modules (transistors, capacitors, etc.)
- **Internal nodes** = analog structures (differential pairs, current mirrors, etc.)

The enumeration proceeds **bottom-up** through this hierarchy:

1. **Form basic groups**: Leaf nodes sharing the same parent in the HSMPG tree are grouped. For a Miller op amp (Fig. 3.30), these are: $\{P1, P2\}$, $\{N3, N4\}$, $\{P5, P6, P7\}$, $\{C, N8\}$.

2. **Basic enumeration** of each group: For each basic group, enumerate all B*-trees and all allowed variant combinations (e.g., different finger counts for transistors, aspect ratios for capacitors). Variant matching constraints are enforced during enumeration. The result is an **enhanced shape function** (see [[3.3 B-Tree Placement with Constraints]]) that stores only Pareto-optimal placements -- those that could contribute to a globally good result. Basic enumerations are **independent** and can be **parallelized**.

3. **Hierarchical combination**: Move up one level in the HSMPG tree. Combine the enhanced shape functions of sibling groups using **enhanced shape function addition** (see Sect. 3.4.3 in [[3.3 B-Tree Placement with Constraints]]). All permutation sequences of children are tried because enhanced shape function additions are **not commutative**.

4. **Recurse to root**: Continue combining until the enhanced shape function for the entire circuit is computed.

### 3.5.3 Enhanced Shape Function Addition

When combining two groups $G^{i-1}_k$ and $G^{i-1}_l$ with enhanced shape functions $\{\alpha_1, \alpha_2, \ldots\}$ and $\{\beta_1, \beta_2, \ldots\}$:

- For every pair $(\alpha_i, \beta_j)$, the two placements are combined both **horizontally** ($\alpha_i +_{\text{hor}} \beta_j$) and **vertically** ($\alpha_i +_{\text{vert}} \beta_j$)
- The resulting B*-trees are evaluated to generate placements (see [[3.3 B-Tree Placement with Constraints]])
- Suboptimal results are pruned; only Pareto-optimal placements are kept in the resulting enhanced shape function $G^i_m$

### 3.5.4 Proximity Constraints Through Hierarchy

The HSMPG tree implicitly enforces **proximity constraints**: modules that are close in the hierarchy tree are placed close to each other in the layout, because they are combined first during the bottom-up enumeration. This is a natural consequence of the hierarchical approach -- no explicit proximity constraint solver is needed.

### 3.5.5 Output

The final result is a **set of Pareto-optimal placements** with different aspect ratios (a shape function), not a single solution. This gives the designer flexibility to choose the aspect ratio best suited for the chip floorplan.

## Algorithms & Methods

### Algorithm 3.4: `enumerateOnHierarchyLevelOf(element)`

This is the core recursive algorithm driving the hierarchically guided enumeration:

```
function enumerateOnHierarchyLevelOf(element):
    resultESF <- empty enhanced shape function

    if element is a basic group G_0:
        basicEnumeration(G_0)
        store result in resultESF
    else:
        ESFList <- empty list

        // Step 1: Recurse into children
        for each child of element:
            childESF <- enumerateOnHierarchyLevelOf(child)
            append childESF to ESFList

        // Step 2: Combine children's ESFs in all orderings
        for each permutation sequence of ESFs in ESFList:
            for each pair of enhanced shapes to be added:
                combine B*-trees (Sect. 3.4.3)
                generate placements for evaluation (Sect. 3.3)
                append resulting shapes to resultESF
            drop suboptimal entries from resultESF

    return resultESF
```

**Key properties**:
- The recursion terminates at basic groups (leaf-level clusters)
- All permutation sequences are tried because ESF addition is non-commutative
- Suboptimal pruning at each level keeps the solution set manageable
- The algorithm is inherently **deterministic** -- no random seeds, no simulated annealing

### Basic Enumeration (Fig. 3.31)

For a basic group $G_0$ with $k$ modules:

1. Enumerate all B*-trees for $k$ modules
2. For each B*-tree, enumerate all allowed variant combinations (respecting variant matching constraints)
3. Generate the placement from each (B*-tree, variant-combination) pair using the constrained placement method from [[3.3 B-Tree Placement with Constraints]]
4. Store the placement in the enhanced shape function if it is Pareto-optimal; discard suboptimal placements

## 3.6 Experimental Results

### 3.6.1 Discussion of Plantage Results

The approach (implemented as **Plantage** in C++) was evaluated on five circuits of increasing complexity:

| Example | Circuit | Devices | Modules | Variants/Module | Groups | Placements | Best Area Usage | Runtime |
|---------|---------|---------|---------|-----------------|--------|------------|-----------------|---------|
| 1 | Miller amplifier | 9 | 13 | 3--6 | 5 | 35 | 115% | 14 s |
| 2 | Comparator | 10 | 10 | 2 | 8 | 4 | 110% | 1 s |
| 3 | Folded cascode | 22 | 22 | 2--4 | 17 | 12 | 121% | 44 s |
| 4 | Fully differential | 30 | 32 | 2--3 | 19 | 12 | 129% | 691 s |
| 5 | Buffer amplifier | 42 | 46 | 2--7 | 21 | 114 | 111% | 134 s |

**Key observations**:
- **Area usage** = (bounding rectangle area) / (module + well area). Ideal is 100%, but constraints and device shapes prevent this. Best achieved: 110--111%.
- **Group sizes** are typically small (2--5 modules), which is crucial for tractability. Average group size ranges from 2.2 to 2.9.
- **Module variants** (different finger counts, aspect ratios) multiply the enumeration space but are handled efficiently through variant matching constraints.
- **Constraint generation** is fast (~0.3--1.2 s) and automatic from the netlist.
- Even the largest circuit (Example 5, 46 modules) completes in ~2 minutes.
- Some devices are split into subdevices for **common centroid** placement, increasing the module count beyond the device count.
- Minimum distance constraints between nMOS and pMOS transistors reserve space for n-wells.

**Example 3 (Folded Cascode)**: The symmetry group MGS,1 through MGS,5 produces five symmetrical pairs. A common centroid constraint is used for the differential pair. The shape function has a characteristic corner ("?") caused by four large modules P7--P10. Area usage is 121% due to minimum distance constraints.

**Example 4 (Fully Differential Amplifier)**: High degree of symmetry with 10 matching groups (MGS,1 to MGS,10). Placements are tall and narrow because of the large symmetry group SG1. Runtime is the longest (691 s) due to the many constraints and variants.

**Example 5 (Buffer Amplifier)**: 42 devices, 46 modules (after splitting for common centroid). The top proximity group was manually subdivided due to its size (14 super nodes). Two differential pairs use common centroid arrays. 114 placements computed in 134 s. Different variants of P39 are visible across placements.

### 3.6.2 Comparison with Other Approaches

Plantage was compared against six other placement methods using two benchmark circuits ("biasynth_2p4g" with 65 modules and "lnamixbias_2p4g" with 110 modules):

| Approach | biasynth Area% | biasynth Time(s) | lnamixbias Area% | lnamixbias Time(s) |
|----------|---------------|-------------------|-------------------|---------------------|
| Sequence pair | 114.89 | 780 | 110.43 | 2,824 |
| Segment tree | 114.89 / 246 | -- | 109.35 | 726 |
| Seq. pair + LP | 106.38 | 403 | 108.59 | 3,252 |
| Seq. pair + dummy | 118.51 | 134 | 113.50 | 227 |
| Symmetry islands | 104.68 | 22 | 105.72 | 43 |
| Seq. pair + Johnson | N/A | N/A | ~109 | 480 |
| **Plantage** | **104.96** | **337** | **107.68** | **387** |

**Key findings**:
- Plantage area usage is within **1--2%** of the best published results (symmetry islands approach)
- Plantage is approximately **10% better** in area usage than several other approaches
- **Plantage is the only deterministic approach** -- all others use simulated annealing with variable runtimes depending on random seeds
- Runtimes are constant and allow interactive use even for 110-module circuits
- Setup time is short because constraints and HSMPG tree are generated automatically

### 3.6.3 Linear Minimum Distance Constraints

The benchmark circuits were modified by placing each symmetry group in a separate well, requiring minimum distance constraints:

- Module $m_1$ must keep distance $d_{\text{well}}$ to all modules outside its well
- Distance $2 \cdot d_{\text{well}}$ to modules in other wells

**Impact on runtime**:
- "biasynth_2p4g": 593 s (+76% over baseline)
- "lnamixbias_2p4g": 664 s (+72% over baseline)

Despite the overhead, runtimes remain in the range of minutes. Placements remain compact. No other approaches address minimum distance constraints in detail for comparison.

### 3.6.4 Piecewise-Linear (PWL) Minimum Distance Constraints

An example with **DTI (Deep Trench Isolation) transistors** was tested:

- 30 modules from the buffer amplifier input stage
- DTI stretching causes white areas between modules and some unused area in the layout
- Runtime: ~15 minutes (significantly slower because the **linear MIP solver** replaces the faster Simplex solver)
- Area usage: 110%
- Conclusion: PWL minimum distance constraints are handled at reasonable (though increased) computational cost

## 3.7 Conclusion

**Plantage** is a **deterministic** analog placement approach with the following key contributions:

1. **Automatic constraint generation**: The HSMPG tree captures the circuit's symmetry, matching, and proximity structure directly from the netlist, producing constraints automatically.

2. **Hierarchy-guided enumeration**: The HSMPG tree decomposes the placement problem into small subproblems (basic groups of 2--5 modules), enabling exhaustive enumeration within each subproblem.

3. **Enhanced shape functions**: A new data structure that represents Pareto-optimal placements at different aspect ratios. Enhanced shape function addition combines subproblem solutions while pruning suboptimal results.

4. **Comprehensive constraint handling**: Plantage handles device-proximity, symmetry, common centroid, minimum distance (linear and PWL), and variant constraints -- the first approach to handle all of these deterministically.

5. **Multiple output placements**: Unlike other approaches that produce a single solution, Plantage outputs a set of placements with different aspect ratios (a shape function), giving designers flexibility.

6. **Industrial applicability**: Runtimes in the range of seconds to minutes even for circuits with 100+ modules, with constant (deterministic) runtimes and automatic setup.

## Connections to Bigger Picture

This section completes Chapter 3's presentation of the Plantage deterministic placement methodology. The hierarchically guided enumeration (Sect. 3.5) is the orchestrating algorithm that ties together the constraint generation from [[3.2 Placement Constraint Generation]] (which builds the HSMPG tree) and the constrained B*-tree placement engine from [[3.3 B-Tree Placement with Constraints]] (which evaluates individual placements under linear and PWL constraints). Compared to the simulated-annealing-based approaches of Chapters 1 and 2 (e.g., [[1.4 Topological Placement with Symmetry Constraints]] and [[2.5 The HB-Tree Algorithm]]), Plantage trades potential optimality for determinism and reproducibility. The enhanced shape functions produced here serve as input to routing (see [[4.1 Introduction to Analog Routing]]), where the availability of multiple aspect ratios allows the router to choose a placement that best accommodates wiring.
