# 6.1 Introduction to Layout-Aware Sizing

> **Chapter 6**: Closing the Gap Between Electrical and Physical Design: The Layout-Aware Solution (Castro-Lopez, Roca, Fernandez)
> **Part**: Part III: Layout in the Design Flow

## Key Concepts

### 6.1 The Design Productivity Crisis and Layout-Aware Sizing

The CMOS semiconductor industry faces a **design productivity lag**: IC complexity grows at 58% per year while designer productivity grows at only 21% per year. For analog and mixed-signal (AMS) design, the situation is worse due to the scarcity of commercial CAD tools. Three research directions are proposed to bridge this gap:

1. **Reuse-based design practices** -- leveraging analog IP blocks across projects
2. **Improved hierarchical synthesis** -- managing subtle analog design knowledge more efficiently
3. **Avoiding iterations between separate design stages** -- the central focus of this chapter

**Layout-aware sizing** is the proposed methodology that concurrently solves geometrical and parasitic problems by bringing layout-related data into the sizing process itself. The key insight: in traditional design flows, **electrical synthesis** (mapping specs to device sizes/biasing) and **physical synthesis** (layout generation) are separate, causing costly back-and-forth iterations when layout parasitics degrade performance.

The two quality aspects -- **area** and **parasitics** -- are intimately related: optimizing geometry unavoidably affects parasitic robustness, and vice versa. The methodology therefore combines two techniques:

- **Parasitic-aware sizing**: Layout parasitics are computed interactively during sizing using specific layout information and actual device sizes
- **Geometrically constrained sizing**: Layout knowledge (e.g., number of MOS transistor folds) is included in the sizing process to optimize area and shape of the eventual layout

**Salient features** of the proposed solution:

1. **Generality** -- simulation-based approach supports many circuit types with high accuracy
2. **Global optimization** -- ensures high-performance solutions meeting demanding specs
3. **Parasitic robustness** -- accurate parasitic estimates incorporated directly into electrical synthesis
4. **Reasonable runtimes** -- efficient optimization-based and template-based layout generation
5. **Realistic area minimization** -- every layout detail (routing, guard-rings, block separation) is considered during electrical synthesis

### 6.2 Previous Work

#### 6.2.1 Circuit Sizing and Layout Generation

Two fundamental approaches to synthesis:

**Knowledge-based synthesis:**
- Uses predefined **design plans** (equations, heuristics) to map performance requirements to component characteristics
- **Knowledge-based sizing**: design equations calculate component parameters from performance specs (e.g., GAHA [3])
  - **Pros**: fast solutions
  - **Drawbacks**: limited accuracy (simple equations), large preparatory effort, difficult technology migration
- **Knowledge-based layout**: captures expert layout techniques
  - **Rule-based**: customizable rule set defining "good" analog layout, obeyed by placement/routing algorithms
  - **Template-based** (most common, [4-9]): captures spatial relationships, symmetry, device matching, parasitic minimization in reusable patterns

**Optimization-based synthesis:**
- Translates the problem into function optimization solved by iterative numerical methods
- Can be **single** or **multi-objective**
- Performance evaluation via:
  - **Equations** (manual or symbolic analyzers [11-16]) -- simpler but less accurate
  - **Simulation** (SPICE-based [17-21]) -- more accurate but slower, more general
- Optimization techniques:
  - **Statistical** (e.g., simulated annealing [16, 20, 21]) -- can escape local minima but higher computational cost
  - **Deterministic** [17] -- faster convergence but risk of local minima
- **Optimization-based layout generation** [22-24]: cost function considers area, net length, analog constraints (mismatch, crosstalk)
  - **Benefit**: generality (applicable to any AMS circuit)
  - **Drawbacks**: problem complexity, relatively low solution quality, difficult cost function setup, long turnaround times

#### 6.2.2 Previous Approaches to Layout-Aware Sizing

The authors analyze prior work along several axes: sizing engine type, performance evaluation method, parasitic estimation method, geometry-awareness, and layout generation inclusion. Key approaches (summarized in Table 6.1):

| Ref. | Sizing Engine | Perf. Eval. | Parasitic Est. | Layout Gen. | Geo. Constraints |
|------|--------------|-------------|----------------|-------------|-----------------|
| [16] | Perf. models + genetic | Fitted functions | 2.5-D analytical-geometrical | Yes (procedural) | Equations |
| [25] | Design plans | Equations | Analytical-geometrical | No (linear prog.) | Yes |
| [26] | Sim-based nonlinear opt. | SPICE | Analytical-geometrical | No | No |
| [27] | Sim-based opt. | NG-SPICE | Analytical + lookup tables | No | No |
| [28] | Sim-based opt. | Symbolic analysis | Off-the-shelf extractor | No | No |
| [29] | Equation-based opt. | Matrix nodal analysis | Analytical models | No | No |
| **This work** | **Sim-based opt.** | **HSPICE** | **Analytical + layout-sampling** | **Yes (slicing tree)** | **Yes** |

**Key criticisms of prior work:**

- **[16]**: Uses evolutionary algorithms with analytical-geometrical parasitic models and procedural layout generation. Geometric concerns addressed with coarse equations. However, **parasitic information is very limited**.
- **[25]**: Knowledge-based with design plans. Parasitics evaluated only for a few iterations. Uses linear programming (simplex on building blocks called "groups"). **Drawbacks**: design plan accuracy limits solution quality; geometric aspects not truly part of design space exploration; area not comprehensively minimized; dependent on starting guesses.
- **[26]**: Two-phase approach -- global sizing without layout info, then detailed sizing with procedural layout. Parasitics only considered for fine-tuning. Geometric concerns limited to MOS transistor folding.
- **[27]**: Simulation + optimization with analytical models and lookup tables for routing wires. **No geometry-aware information** during sizing.
- **[28]**: Template-based layout with commercial extractors. Parasitics via symbolic analysis. ~20% gain in sizing time vs. traditional simulation, but **limited to small-signal performances** and no geometric concerns.
- **[29]**: Equation-based models for performance and analytical parasitic models. **Accuracy limited** by equation simplicity. No geometry considerations.

### 6.3 Selected Approach to Layout-Aware Sizing

#### 6.3.1 Sizing: Simulation-Based Optimization Engine

The authors chose a **simulator-in-the-loop, optimization-based engine** [20] for circuit sizing, rejecting knowledge-based approaches because:
- Knowledge-based sizing forces simple design equations, causing deviations of **several hundred percent** in worst-case scenarios
- Large preparatory time/effort for design plans
- Difficult technology migration
- Ad hoc nature

The optimization problem is formally stated as:

$$\text{Minimize } y_{o_i}(\mathbf{x}), \quad 1 \leq i \leq P$$

$$\text{Subject to } y_{r_j}(\mathbf{x}) \leq Y_{r_j} \text{ and/or } y_{r_j}(\mathbf{x}) \geq Y_{r_j}, \quad 1 \leq j \leq R$$

where:
- $y_{o_i}(\mathbf{x})$ = value of the $i$-th design **objective** (e.g., minimize power consumption)
- $y_{r_j}(\mathbf{x})$ = value of the $j$-th design **constraint** (e.g., phase margin > 45 degrees)
- $Y_{r_j}$ = targeted specification value
- $\mathbf{x}$ = vector of design variables (transistor sizes, capacitor values, bias currents, etc.)

**Important distinction**: Objectives *improve* the design; constraints define *feasibility*.

**Cost function** (single-objective formulation):

For **infeasible** points (violating constraints):

$$\phi(\mathbf{x}) = \max\left[w_j \cdot \log\left(\frac{y_{r_j}}{Y_{r_j}}\right)\right]$$

For **feasible** points:

$$\phi(\mathbf{x}) = \hat{\phi}(y_{o_i}) = -\sum_i w_i \cdot \log(|y_{o_i}|)$$

where $w_j$, $w_i$ are weights for prioritization.

**Two-phase optimization** [20]:
1. **Global exploration**: Simulated annealing with adaptive temperature control, exploring a coarse multidimensional grid to find best regions
2. **Local optimization**: Powell's deterministic method [31] for fine-tuning

Key features of the optimization engine:
- Preliminary design space exploration using coarse multidimensional grid
- Adaptive temperature control in simulated annealing
- Synchronization of movement amplitude with temperature
- **Embeddable C-based programs** for incorporating design knowledge -- this capability is what enables layout-related aspects to be injected into sizing

Any transistor-level simulator (e.g., HSPICE) can serve as the performance evaluator, making the methodology applicable to any analog circuit that can be simulated at device level.

#### 6.3.2 Layout Generation and Parasitic Extraction

**Problems with traditional design flow:**
- Trial-and-error parasitic correction is unsystematic
- Degradation often due to **combined effect** of multiple parasitics, not a single one
- Number of extracted parasitics (depending on circuit complexity and extractor accuracy) makes correction time-consuming and error-prone

**Key requirement**: If parasitics are to be estimated during sizing, the layout must be generated at each iteration. The layout generation method must therefore be fast.

**Why template-based layout generation** is chosen over optimization-based:
1. **Speed**: Layout generation takes only a few seconds [5], much faster than optimization-based approaches
2. **Completeness**: Templates are parameterized structures containing all information for final layout implementation, essential for accurate parasitic estimation
3. **Expertise encapsulation**: Templates efficiently capture placement and routing expertise (e.g., device symmetries coded directly into building blocks)

**Trade-off**: Templates are relatively costly to create (1.5-2x the time of manual layout for the same block), and lack flexibility for certain device sizes. However, geometrically constrained sizing and careful template design mitigate flexibility issues.

Implementation uses **Cadence PCELLS** [33] and **SKILL programming** [34].

#### 6.3.3 Putting It All Together: The Layout-Aware Flow

The complete flow integrates the optimization engine with a **Geometric Constraints (GC) module** implemented in C++, which performs the floorplan-sizing task at each iteration.

**Required inputs:**
1. Circuit description (netlist) and electrical performance goals
2. Circuit template description: **binary slicing tree** representation of the layout template
3. Geometric goals: user-specified objectives for layout geometry (aspect ratio, max width/height)
4. Fabrication process data: layout design rules and process parameters

**Per-iteration flow:**
1. **Select design variables** -- randomly at start, then via optimization algorithm (e.g., simulated annealing)
2. **GC module processes** -- calculates all possible geometric parameter combinations for all layout styles; selects the combination meeting geometric objectives with minimal area and area loss
3. **Layout instance generated** -- parasitics extracted and added to circuit
4. **Circuit simulation** -- performances evaluated with extracted parasitics
5. **Cost function evaluation** -- electrical performances and geometric features fed into cost function controlling the optimization

## Algorithms & Methods

### Modified Stockmeyer's Algorithm (GC Module)

The GC module implements a **modified Stockmeyer's algorithm** operating in two phases on the slicing tree:

**Phase 1 -- Bottom-Up Shape Function Construction:**

1. **Initialize leaf nodes**: For each leaf node, generate its **shape function** -- a list of Pareto-optimal $\{width, height\}$ pairs from a database of generators. Generators provide shapes based on:
   - Leaf node type (folded transistor, MOS differential pair, cascode group, current mirror, capacitor array, folded resistor)
   - Device size(s)
   - Fabrication process parameters
   - Sorted by: $h_i > h_{i+1}$ and $w_i < w_{i+1}$

2. **Combine into nonleaf nodes**: For each vertical ($v$) or horizontal ($h$) nonleaf node, generate a list of $s$ pairs $\{(h_1, w_1), \ldots, (h_s, w_s)\}$ following Stockmeyer's rules:
   - $s \leq \prod_{i=1}^{L(v)} l_i$ where $L(v)$ = number of leaf nodes in subtree rooted at $v$, $l_i$ = cardinality of leaf $i$'s shape function
   - Only **Pareto-optimal** pairs are kept (no pair dominated in both $h$ and $w$ dimensions)
   - Pairs sorted by $h_i > h_{i+1}$ and $w_i < w_{i+1}$

3. **Incorporate template info**: Physical separation between slices from the layout template helps compose the top-most shape function accurately.

4. **Output**: **Global shape function** of the overall slicing tree; a **floorplan-sizing matrix** with columns for $W$, $H$, area, aspect ratio, and area loss.

**Complexity**: $O(d \cdot l_T)$ where $d$ = depth of slicing tree, $l_T$ = sum of cardinalities of all leaf shape functions.

**Phase 2 -- Top-Down Shape Propagation:**

1. **Filter by geometric goals**: Remove all rows from the floorplan-sizing matrix that violate:
   - Aspect ratio constraint: $AR - \Delta_{AR} \leq W/H \leq AR + \Delta_{AR}$
   - Maximum/minimum width and/or height bounds
2. **Select optimal**: Choose the row with minimal area from the filtered matrix
3. **Traverse top-down**: Walk the slicing tree to recover the width/height of each leaf node and retrieve the corresponding geometric parameter (GP) values

### Area Loss Calculation

$$\text{Area Loss} = W \times H - \left(\sum_i W_i \times H_i + A_{\text{routing}}\right)$$

where $i$ ranges over all leaf nodes and $A_{\text{routing}}$ is the area required by routing wires. Minimizing area loss improves the efficiency and flexibility of template-based layouts.

## Connections to Bigger Picture

This sub-chapter establishes the motivation and architectural framework for layout-aware sizing, which represents a significant departure from the traditional sequential design flow (size first, then layout, then verify parasitics, then iterate). It directly addresses the gap between electrical and physical design that Chapters 1-5 of the book have been building toward -- particularly connecting to [[5.7 Practical Retargeting]] which deals with migrating existing layouts across technologies, a complementary problem. The GC module and modified Stockmeyer's algorithm introduced here form the foundation for [[6.4 Geometrically Constrained Sizing]], where detailed design examples demonstrate the technique on real circuits. The parasitic-aware component (deferred to Section 6.5) completes the methodology. Within the broader field of analog layout synthesis, this work is notable for being one of the few approaches that simultaneously considers geometric optimization, parasitic awareness, and simulation-based accuracy all within a single optimization loop.
