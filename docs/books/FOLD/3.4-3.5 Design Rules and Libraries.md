# 3.4-3.5 Design Rules and Libraries

> **Chapter context**: Bridges to Technology: Interfaces, Design Rules, and Libraries

## Key Concepts

### 3.4 Geometrical Design Rules

Design rules are the formal encoding of manufacturing constraints into geometrical requirements that a layout must satisfy. Every structure dimension in a layout is constrained by one of three forms:

- **(a)** `structure_size >= min_value` -- the most common; e.g., minimum wire width.
- **(b)** `structure_size <= max_value` -- rare; e.g., maximum metal width to prevent CMP dishing, or maximum Active spacing to limit STI-induced mechanical stress.
- **(c)** `structure_size = exact_value` -- contacts and vias in advanced nodes, whose etch process is precisely optimized for a single size.

A value *range* can be expressed by combining cases (a) and (b).

#### 3.4.2 Basic Geometrical Design Rules

The fundamental quantity in every design rule is the **spacing between opposing polygon edges**. By varying which polygon(s) and which layer(s) those edges belong to, and whether the measurement is inside or outside the polygon, five basic rule groups emerge:

| Rule | Edge Relationship | Shapes | Layers |
|------|-------------------|--------|--------|
| **Width** | Inside / Inside | 1 | 1 |
| **Spacing** | Outside / Outside | 1 or 2 | 1 or 2 |
| **Extension** | Inside / Outside | 2 | 2 |
| **Intrusion** | Inside / Inside | 2 | 2 |
| **Enclosure** | Outside / Inside | 2 | 2 |

**When is a rule checked?** Two edges are considered "opposite" (and therefore subject to the rule) if the angle between them is less than 90 degrees in the region being measured -- i.e., they are parallel or form an acute angle. If edges are not opposite under this definition, the rule is not applied.

- **Width** and **Spacing** are single-layer rules driven by the **resolution capability** of the lithographic process -- the smallest feature the process can reliably print.
- **Extension**, **Intrusion**, and **Enclosure** are two-layer rules driven by the **maximum overlay error** (mask-to-mask alignment tolerances).

#### Robust vs. Non-Robust Design Rules

A critical distinction exists between *robust* and *non-robust* design rules:

- **Non-robust rules** set minimum dimensions that match the nominal process capability but do not account for manufacturing tolerances. An error-free layout drawn with non-robust rules can still fail in production -- wires may break (if they shrink) or short-circuit (if they grow).
- **Robust rules** incorporate safety margins for manufacturing tolerances, guaranteeing that even with worst-case process variation the layout remains functional. They prevent breaks when features shrink and short-circuits when features grow.

The same principle applies to two-layer rules: robust Enclosure and Extension rules absorb the overlay error budget so that misaligned masks do not cause shorts between source/drain and the substrate, source-to-drain shorts, or bad contacts.

#### Contacts and Vias

In state-of-the-art processes, contacts and vias are constrained to an **exact width** (case c), because the oxide etch process is precisely optimized for that single dimension. To increase the current-carrying cross-section between two metal layers, one must use **multiple vias** ("via arrays"), not larger individual vias.

#### Maximum-Value Rules

Maximum-value rules address effects like:
- **CMP dishing**: wide metal structures dish during chemical-mechanical polishing, so metal width is capped.
- **STI stress**: large spacings in the Active layer create embedded shallow-trench isolation structures that mechanically stress the silicon crystal, altering carrier mobility and conductivity.

A practical trick for checking maximum-width violations: perform an *undersize* by `max_value/2` followed by an *oversize* by the same amount on the layer of interest. Any shapes that survive this sequence violate the maximum-width rule and can be flagged.

### 3.4.3 Programmed Geometrical Design Rules

Many real-world layout constraints cannot be captured by a single basic rule applied to a single physical layer. **Programmed design rules** handle these cases by first computing intermediate "calculated layers" through Boolean and sizing operations, then applying a basic rule to the result.

**Example 1 -- Differentiating PMOS and NMOS Active regions:**

The n-well must *enclose* the PMOS Active area (to keep it fully embedded in the n-well backgate), while the NMOS Active area must be *spaced away* from the n-well (to remain in the p-substrate backgate). Since both come from the same physical Active layer, programmed rules first separate them:

```
PMOS-Active = Active INSIDE Nwell      (equivalently: Active AND Nwell)
NMOS-Active = Active OUTSIDE Nwell     (equivalently: Active ANDNOT Nwell)
```

Then basic rules are applied to the calculated layers:

```
ENCLOSURE(PMOS-Active, Nwell, min_value_2)
SPACING(NMOS-Active, Nwell, min_value_1)
```

**Example 2 -- Finding source/drain regions with missing contacts:**

Source and drain areas should have as many contacts as possible for uniform current flow. The detection sequence is:

1. `X1 = Active ANDNOT Poly` -- extracts source/drain regions.
2. `X2 = X1 ANDNOT Cont` -- removes areas already covered by contacts.
3. `X3 = SIZE(X2, -clear)` -- undersizes the remainder.
4. `Result = SIZE(X3, +clear)` -- oversizes back.

Any shapes surviving in `Result` indicate regions large enough for additional contacts that are currently missing -- these become DRC error markers.

### 3.4.4 Rules for Die Assembly

Beyond on-chip geometrical rules, the physical design must also satisfy **die assembly rules** that ensure the chip can be packaged and connected to the outside world.

**Chip packaging** (sectional view): the die is mounted on a metallic **lead frame**, connected via **bonding wires** from the on-chip **bond pads** to **contact points** on the lead frame (which become the **package leads**), and then encapsulated in **mold compound** (plastic).

**Pads** are more than simple metallic contact areas. They reside in **pad cells** that also contain:
- **ESD protection** circuitry (to shield the core from electrostatic discharge).
- **Driver circuitry** for buffering I/O signals.

Typical die assembly rules include:

- **Lead-frame enclosure rule**: the lead-frame rectangle must be larger than the die by a specified margin.
- **Bond pad width and spacing**: constrained by the bonding wire thickness and bonding equipment.
- **Minimum bonding-wire spacing**: wires must not touch each other in plan view.
- **Minimum bonding-wire angle**: the angle between a bonding wire and the die edge must not be too acute.
- **No bond pads in die corners**: corners are mechanically vulnerable and bonding there risks cracking the die.
- **Maximum bond wire length**: excessively long wires risk contacting each other during the molding process, creating short circuits. This also sets a lower bound on die size relative to the lead frame.

The **bond diagram** documents the electrical assignment (pinning) of die pads to lead-frame contact points.

### 3.5 Libraries

Every design flow is inherently coupled to libraries. For each component, a library must provide three views:

1. **Symbol** -- represents the device type and its interfaces (used in schematic entry).
2. **Model** -- describes the device's electrical behavior (used in simulation).
3. **Layout** -- characterizes the device's physical geometry (used in physical design).

These three views map directly onto the Gajski-Kuhn Y-chart domains (behavioral, structural, physical).

### 3.5.1 Process Design Kits (PDKs) and Primitive Device Libraries

A **Process Design Kit (PDK)** is provided by each foundry for each of their technologies. It is the complete technology interface used to design, simulate, draw, and verify a chip. A PDK contains:

- **Primitive device library** -- device symbols, simulation models, and parameterized cells (PCells) for transistors (MOSFETs, BJTs), resistors, capacitors, diodes, and I/O cells.
- **Verification decks** -- rule files for DRC, LVS, ERC, antenna checks, etc.
- **Technology data** -- layer definitions, graphical representations, sheet resistances, sheet/line capacitances, routing rules (preferred directions, pitch), and via pattern libraries (stacks, arrays).

**Key PDK elements in detail:**

| PDK Element | Used During | Purpose |
|-------------|------------|---------|
| Symbols + parameters | Schematic entry | Represent devices; define width, length, etc. |
| SPICE models | Simulation | DC, AC, transient analysis; corner + Monte-Carlo simulations for yield estimation |
| PCells (layout generators) | Physical design | Automatically generate device layout from parameters (e.g., transistor W, L) |
| Layer definitions | Layout + routing | Layer name, graphical style, sheet resistance, capacitance, preferred routing direction, pitch |
| DRC deck | Verification | Check geometrical design rules |
| LVS deck | Verification | Extract netlist from layout and compare to schematic netlist |
| PEX rules | Verification | Extract parasitic R, C, L from interconnects and substrate; produce "parasitics-extended" netlist for post-layout simulation |

Foundries offer **proprietary PDKs** tied to specific commercial EDA tools. PDKs enable both pre-silicon verification and yield estimation through Monte-Carlo simulation of process parameter variations and device mismatch.

### 3.5.2 Cell Libraries

#### Standard Cell Libraries

Standard cells implement low-level logic functions from multiple interconnected transistors. They have:
- **Variable width** but a **fixed height** (or one of a small number of standard heights), enabling row-based placement.
- Pre-optimized, **fixed layouts** (no layout generators needed).
- Models typically in **VHDL or Verilog** (behavioral/RTL), augmented with **timing information** for digital simulation.

Typical standard cell contents:

| Category | Examples |
|----------|----------|
| **Combinatorial** | NAND2, NAND3, NOR2, NOR3, AND2, OR2, INV, INV_2X, INV_4X, BUF_4X, BUF_16X, TRI_BUF_8X, XOR2, MUX21, MUX41 |
| **Memory** | D_FF_R (D flip-flop w/ reset), D_FF_RS (w/ reset+set), D_FF_R_SC (w/ scan), LD_R (latch w/ reset), LD_R_SC (latch w/ scan), BK (bus keeper) |

Standard cell libraries are **process-specific** and often provided by the foundry. Foundries may keep internal cell layouts secret, providing only external interface and shape information; the hidden structures are inserted during mask generation.

#### Pad Cell Libraries

Pad cells connect the IC core to the external system. Their functions include:
- Buffering input signals
- Driving external loads and adapting to external logic levels
- Providing supply voltage
- Shielding the core against ESD, wrong polarity, and transients

Pad cells include **protective guard structures** -- integrated diodes connected to pad supply rings for ESD protection.

#### Macro Libraries

Macro cells are pre-designed combinations of basic cells that perform extended functions:
- **Hard macros**: fully placed and routed with a fixed shape (e.g., SRAM blocks, PLLs).
- **Soft macros**: flexible shapes whose internal placement and routing is not yet defined.

### 3.5.3 Libraries for PCB Design

PCB libraries differ from IC libraries in that the three views (symbol, model, layout/footprint) are typically stored in **separate technology libraries** rather than combined in a single library. They are also often **tool-specific** and not interchangeable between different EDA vendors. Storage format varies (ASCII or binary) depending on the tool provider.

#### Symbol Libraries
Contain schematic symbols that can be searched, viewed, and instantiated via a library management system. Each symbol typically references one or more suitable footprints. Additional metadata (manufacturer, vendor, links to electrical models) can be stored.

#### Footprint Libraries
A **footprint** (or "land pattern") in the library context encompasses all physical information for a device: pad/through-hole geometry across all relevant layers (routing, solder-resist, solder-paste, silk screen, mechanical, drill holes, cut-outs), and optionally a **3D physical device model**. Every schematic symbol references its associated footprint(s); this link drives the transition from schematic to PCB layout.

#### Model Libraries
Contain electrical models for simulation tools (PSpice, LTSpice, SIMetrix, etc.). Models describe the electrical behavior of basic elements (R, C, L) and semiconductor devices (diodes, transistors) via characteristic parameter sets. Complex devices are modeled as networks of basic elements. Some vendor models are **encrypted** to protect intellectual property.

## Connections to the Bigger Picture

This sub-chapter completes Chapter 3's treatment of how physical design interfaces with semiconductor manufacturing technology. Design rules (Sec. 3.4) translate the physical limitations of lithography, etching, and mask alignment into precise, checkable geometric constraints that every layout must satisfy -- they are the input to the verification steps (DRC, LVS) covered in [[5.4 Verification]]. Libraries (Sec. 3.5) provide the reusable building blocks -- from primitive device PCells to standard cells to PCB footprints -- that make hierarchical design flows (Chapter 4) practical. Understanding robust design rules is essential before studying placement and routing (Chapters 7-8), because every placement and routing algorithm must operate within the feasibility envelope these rules define.
