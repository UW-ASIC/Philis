# 5.4-5.5 Verification and Layout Post Processing

> **Chapter context**: Steps in Physical Design

## Key Concepts

### 5.4.1 Verification Fundamentals

Verification ensures that every intermediate design result meets both **technological constraints** (imposed by the fab based on manufacturing limits) and **functional constraints** (derived from the project specification, such as signal-to-noise ratio or maximum IR drop). Because fabricating a flawed IC results in severe financial losses, all constraints must be checked with automated computer-based tools.

Constraints undergo a **two-stage mapping** to become machine-checkable:

1. **First abstraction (formalization)**: Real-world physics constraints are converted into formal rules or standards expressed in a human-readable meta format (e.g., geometrical design rules, netlists, electrical design rules).
2. **Second abstraction (formalization)**: These meta-level descriptions are converted into the data formats consumed by verification tools (e.g., DRC decks, technology files, LVS rule files).

A third category, **design-methodology constraints**, provides feedback from the second mapping back to the first. They restrict how rules at the meta level are written so that they remain programmable, and they promote standardization by reducing degrees of freedom within physical design.

An important subtlety: both mappings are abstractions. A formal design rule is not perfectly equivalent to the real physical requirement. When a technological constraint cannot be exactly modeled, a **safety margin** is added to the rule. This can cause a layout to fail DRC even though it meets the true manufacturing requirement -- such failures are called **dummy errors** or **false errors**. Experienced engineers may waive these, but doing so demands deep understanding of the underlying technology.

- Technological constraints tend to be conservatively formulated: a perfect DRC result typically guarantees 100% manufacturability.
- Functional constraints can only be partially modeled in modern design environments and therefore cannot be completely verified automatically -- this is why simulation remains essential.
- A valid **verification** ("Has the circuit been correctly designed?") can still produce an invalid **validation** ("Has the correct circuit been designed?").

The verification methods available are summarized in Table 5.1:

| Check | What is Checked | How | Method |
|---|---|---|---|
| Model check | Logical characteristic (is an assumption true?) | Mathematical models | Formal verification |
| Equivalence check | Logical equivalence of two descriptions | Mathematical models | Formal verification |
| Simulation | Circuit behavior vs. specification | Virtual experiment (stimuli + output) | Functional verification |
| DRC (OPC, RET) | Layout vs. technological constraints (manufacturability) | Geometrical design rules | Geometric verification |
| LVS | Layout vs. schematic | Netlist extraction from layout, rule-based | Geometric verification |
| PEX + simulation | Impact of parasitics on circuit behavior | Parameter extraction from layout + simulation | Geometric + functional verification |
| ERC | Layout vs. electric process boundaries (reliability) | Connectivity extraction from layout, rule-based | Geometric verification |
| Testing | Compliance for practical usage | Real experiment, customer checking | Validation |

### 5.4.2 Formal Verification

Formal verification (also called formal functional verification) uses **formal mathematical methods** to prove correctness of a circuit implementation with respect to its specification. The two principal techniques are:

- **Model checking** (property checking): Verifies that a design described in HDL satisfies its specification in every possible way. Both the design model and the spec are expressed in precise mathematical language. Essentially, a given structure must satisfy a given logical formula.
- **Equivalence checking**: Exhaustively compares two circuit descriptions (e.g., HDL code vs. derived gate-level netlist) to confirm they exhibit identical functional behavior. Both descriptions can be normalized to a common notation (e.g., netlist syntax) to simplify comparison. This is the primary methodology for **synthesis verification**.

Formal verification delivers either success or a concrete counterexample: (i) a property violation (model checking) or (ii) a functional mismatch (equivalence checking). It is a pre-layout verification step applied during HDL-based netlist generation, so layout designers typically do not interact with it directly.

### 5.4.3 Functional Verification: Simulation

Simulation verifies a circuit's functional correctness by applying **stimuli** (typical input patterns) and checking whether simulated outputs match intended outputs. Alternatively, stimuli can be applied to both the behavioral description and the final gate description, with their responses compared.

Discrepancies can arise from either **design errors** or **simulation errors/inaccuracies**; both require further investigation. Even when simulation results match perfectly, simulation **cannot guarantee** that a design is correct in its entirety.

**Simulator types:**
- **Analog simulators**: Based on SPICE (Simulation Program with Integrated Circuit Emphasis).
- **Digital simulators**: Use Verilog or VHDL syntax.
- **Mixed-mode simulators**: Combine analog and event-driven digital simulation. Mixed-mode simulation operates at three levels:
  1. Primitive digital elements with timing models and built-in digital logic simulator.
  2. Subcircuit models using actual transistor topology.
  3. In-line Boolean logic expressions.

Simulation tools interface to a schematic editor, a simulation engine, and an on-screen waveform display. They include extensive model and device libraries.

**Practical limitation**: Simulation-based verification is extremely time-consuming for large designs, and there is usually no comprehensive stimulus set to validate the entire design. Even for a simple 32-bit multiplier, exhaustive simulation would require 2^64 input patterns -- at 100 million multiplications/second, this would take **5,849 years**. Designers therefore rely on random stimuli generation, which means some errors may remain undetected. The infamous Pentium FDIV bug (a lookup-table error in a well-simulated Intel processor) cost Intel $475 million.

### 5.4.4 Timing Verification

Timing verification checks whether a digital circuit's timing remains valid after layout generation. Critical paths are calculated during logic synthesis, and all paths are checked for worst-case delay times. The resulting critical path defines the fastest possible clock rate.

A circuit must pass two timing checks:
- **Maximum delay** (setup / long-path constraint): Determines performance -- the signal must arrive at the next flip-flop before the clock edge plus setup time.
- **Minimum delay** (hold / short-path constraint): A failing hold check indicates a **faulty circuit** (data changes too quickly after a clock edge).

**Dynamic timing analysis** extracts all wire capacitances and resistances from the layout and simulates the circuit with these values. This is very time-consuming and requires many stimuli. Restricting analysis to the critical path from logic synthesis does not help because place-and-route may have generated a different critical path.

**Static timing analysis (STA)** is the more efficient alternative. It works on the extracted netlist (including wire R and C) and:
1. Propagates **actual arrival times (AATs)** and **required arrival times (RATs)** to every pin of every gate/cell.
2. Quickly locates timing violations by tracing critical paths responsible for failures.
3. Produces an optimized netlist as output.

**Wire delay calculation** uses several techniques:
- **Moment-based techniques**: Analyze impulse responses from RLC networks using time-frequency transformation.
- **Elmore delay model**: Uses the first moment of the impulse response -- a widely used approximation.

**Standard Delay Format (SDF)** files carry the timing information needed for post-layout simulation: interconnect delays, gate delays, and timing checks exported from physical design tools.

**Crosstalk** is another timing concern: capacitive coupling between adjacent wires during signal transitions causes charge transfer, inducing noise and altering delays. Accurate coupled-system delay calculation is essential for post-layout timing verification.

**Timing closure** is the process of satisfying all timing constraints through layout optimizations and netlist modifications. Key techniques:

- **Timing-driven placement**: Optimizes circuit delay using STA results to identify critical nets.
  - *Net-based*: (i) delay budgeting assigns upper bounds to net timing/length; (ii) net weighting gives higher priority to critical nets during placement.
  - *Path-based*: Shortens entire timing-critical paths rather than individual nets. More accurate but does not scale to large designs (path count can grow exponentially with gate count, e.g., in multipliers).
- **Timing-driven routing**: After detailed placement and clock network synthesis, corrects remaining violations by minimizing (i) maximum sink delay (max source-to-sink interconnect delay) and (ii) total wirelength (affects load-dependent gate delay). Methods include minimum-cost/minimum-radius trees for critical nets.
- **Re-buffering**: Applied if timing violations persist after routing optimizations.

### 5.4.5 Geometric Verification: DRC and ERC

#### Design Rule Check (DRC)

The DRC verifies that the finished layout complies with the **geometrical design rules** provided by the chip manufacturer in a technology file (DRC deck). Layout data is typically in GDSII/OASIS format.

The basic DRC rule categories (cf. Chap. 3):
- **Width rules**: Minimum feature width on a layer.
- **Spacing rules**: Minimum distance between features (same or different layers).
- **Extension rules**: How far one layer must extend beyond another.
- **Intrusion rules**: How far a feature may intrude into another region.
- **Enclosure rules**: How completely one layer must surround another.

**Antenna rules** are another important DRC category. During manufacturing, an interconnect (poly or metal) that is only partially complete acts as a temporary "antenna." Because upper layers are not yet processed, this conductor is temporarily ungrounded. Charge accumulates on these dead-end connections during wafer processing, potentially:
- Generating leakage currents through thin gate oxide.
- Causing permanent physical damage leading to immediate or delayed failure.

This is the **antenna effect**. Fabs supply antenna rules typically expressed as an **allowable ratio of poly/metal area to gate area**, one ratio per interconnect layer. Sometimes a ratio of poly/metal perimeter to gate area is also required, since charges are preferentially collected at conductor edges.

Modern DRC also includes **Design for Manufacturability (DfM)** checks: Boolean operations, sizing functions, inter-layer relations, and layer density checks -- all beyond basic geometric rules.

**Runtime**: DRC is extremely runtime-intensive. Checks run on each sub-section of the circuit to minimize top-level errors. Modern designs can have DRC runtimes **up to one week**; most companies require completion in **less than one day** since DRC is typically executed multiple times before design completion.

DRC ensures manufacturability but **cannot check functional correctness** -- that is left to simulators and formal verifiers.

**Dummy/false errors**: When a design rule is conservatively formulated with a safety margin, layouts may fail DRC despite meeting the true technological constraint. Experienced designers may "stretch" or waive certain rules to increase performance and density at the expense of yield.

#### Electrical Rule Check (ERC)

ERC occupies the "middle ground" between simple layout geometry checking and complex behavioral analysis. Electrical design rules make a circuit more robust (e.g., guarding against electrostatic discharge) and improve reliability by reducing aging due to electrical overstress.

ERC validates robustness and reliability at both schematic and layout levels by:
- Verifying correctness of power and ground connections.
- Checking for floating nets or pins.
- Detecting open and short circuits.
- Propagating power, ground, input, and clock signals to check for incorrect output drives, inconsistencies, and unconnected elements.

Electrical rules depend on (i) semiconductor technology, (ii) circuit type, and (iii) the circuit's use as a component in a larger system. They are often complemented by design-house-specific and experience-based rules.

Some rules, such as **voltage-dependent metal spacing rules**, combine both geometrical and electrical checks. Results are visualized in the schematic/layout editor or presented in a tabular report.

### 5.4.6 Extraction and LVS

#### Netlist Extraction

The LVS tool must first **extract a netlist** from the layout data. This extraction requires a technology-dependent **extraction file** containing three definitions:

1. **How are layers connected?** -- What forms a net? (Via definitions, layer connections)
2. **What combination of polygons and layers forms a device?** -- Device recognition rules.
3. **Which device polygon properties determine electrical parameters?** -- E.g., gate length/width for transistors.

Without these three pieces of information, a netlist cannot be derived from raw layout polygons.

The extraction algorithm proceeds as follows:
1. **Define basic devices**:
   - (a) Determine all geometrical structures representing basic devices.
   - (b) Separate basic devices from other layout structures.
2. **Determine electrical nodes**: Identify all geometrical structures forming electrically linked units (intra-mask operation).
3. **Generate the netlist**:
   - (a) Determine nodes adjacent to basic devices.
   - (b) Assign connection types (e.g., gate, source, drain for transistors).

Importantly, the extraction deliberately does **not** use library information. If it did, any library error would propagate to both the original and extracted netlists, making LVS comparison meaningless.

#### LVS Comparison

The extracted netlist is compared with the original netlist (from the circuit schematic) on three attributes:

- **Nets**: Are all electrical connections from the schematic -- and only those -- present in the layout?
- **Device types**: Are all devices from the schematic -- and only those -- present in the layout?
- **Device parameters**: Do all layout devices have the electrical parameters specified in the schematic?

The LVS produces a **report file** listing the number and types of devices and nodes in both netlists, plus all non-matching components. The designer must investigate these mismatches -- they can be serious faults or simply unrecognizable features flagged by the tool.

**Hierarchical verification** is critical for managing LVS runtime. Memory blocks and IP elements are compared hierarchically, while analog blocks and macro cells may use flat representation. This can drastically reduce debugging time.

#### Parasitic Extraction (PEX)

Extraction tools also perform **parasitic extraction**, calculating:
- **Parasitic capacitances**
- **Parasitic resistances**
- **Parasitic inductances**
- (Additional substrate coupling effects exist but are not handled by all tools)

PEX is essential for creating accurate analog circuit models. Interconnect parasitics became a significant concern below the **0.5 um technology node**, causing:
- Signal delays
- Signal noise
- IR drops

These affect timing and performance, especially in analog circuits. Timing analysis, power analysis, circuit simulation, and signal integrity analysis all rely on PEX results.

**PEX methodologies**:
- **Field solvers**: Physically accurate but only applicable to small problem instances.
- **Pattern matching techniques**: The only feasible approach for complete modern IC designs -- approximate but scalable.

The extraction tool is also reused for **antenna checks** (extracting gate area and conductor area to compute their ratio) and specific **ERC functions** (e.g., pin-to-pin resistance checks for ESD compliance).

### 5.5 Layout Post Processing

Traditionally, once a layout was DRC-clean and timing-verified, it was ready for fabrication: data files were sent to a mask shop, masks were written, and the fab manufactured the design. Today, however, IC layout data requires **extensive post processing** before mask fabrication.

Layout post processing converts a physical layout into mask production data through three steps:

1. **Chip finishing** (Sect. 3.3.2): Adding custom designations and structures to improve manufacturability:
   - Company logo and chip ID
   - Seal ring (protects die edges)
   - Filler structures (improve CMP uniformity)

2. **Reticle layout** (Sect. 3.3.3): Adding elements required at the reticle level:
   - Test patterns
   - Alignment marks

3. **Layout-to-mask preparation** (Sect. 3.3.4): The step most impactful to physical design:
   - Graphics operations (Boolean, sizing)
   - Resolution enhancement techniques (RET)
   - Fracturing (converting shapes into write-tool primitives)

#### Resolution Enhancement Techniques (RET)

RET must be applied to cutting-edge ICs to counter manufacturing and optical effects caused by extremely small feature sizes. Even when the final layout is what is required in silicon, it must be further processed before masks are fabricated. RET broadly classifies into:

**1. Distortion corrections** -- compensate for manufacturing process distortions:
- **Optical Proximity Correction (OPC)**: Addresses image errors due to diffraction effects. OPC counteracts by slightly **enlarging** the mask opening at underexposed regions and slightly **shrinking** it at overexposed regions. The resulting mask pattern looks distorted but produces the correct feature in photoresist.

**2. Reticle enhancement** -- improves manufacturability or lithographic resolution:
- **Phase shift masks**: Photomasks that exploit interference from phase differences to improve image resolution. By altering the phase of light passing through certain mask areas, the defocusing effect of sub-wavelength features is reduced.
- **Double/multiple patterning**: Splits dense patterns into two or more interleaved patterns of less-dense features using multiple masks and multiple lithographic exposures. This enhances feature density beyond single-exposure limits.

Double/multiple patterning imposes **new layout constraints** to avoid decomposition violations. Mask layers are assigned colors based on spacing requirements, which are used to split the original layout into two or more new layers.

## Connections to the Bigger Picture

Verification and post processing are the final gatekeepers of the physical design flow. They sit downstream of all the primary layout steps covered in [[5.3 Primary Steps in Physical Design]] -- partitioning, floorplanning, placement, and routing -- and their purpose is to ensure that the completed layout is both **manufacturable** (DRC, antenna checks) and **functionally correct** (LVS, PEX + simulation, ERC). Timing verification bridges the gap between logical synthesis and physical implementation, ensuring that the parasitic effects introduced by real wiring do not break circuit timing. Layout post processing, especially RET, directly feeds back into physical design by imposing additional layout constraints (e.g., double-patterning coloring rules) that designers must respect. Understanding verification is essential before moving to the technology-specific layout concerns in [[6.1-6.3 Sheet Resistance Wells and Devices]], where the physical structures that design rules protect are examined in detail.
