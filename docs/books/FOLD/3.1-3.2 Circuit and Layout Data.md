# 3.1-3.2 Circuit and Layout Data

> **Chapter context**: Bridges to Technology: Interfaces, Design Rules, and Libraries

This section covers the two fundamental data representations that bridge circuit design to physical implementation: **circuit data** (the input to physical design) and **layout data** (the output of physical design). Understanding both is essential because the layout engineer must translate one into the other while respecting technology constraints.

---

## 3.1 Circuit Data: Schematics and Netlists

### 3.1.1 Structural Description of a Circuit

A circuit's structural description captures an electrical network in terms of its **functional units** and their **electrical connections**. The key terminology:

- **Pins**: Connection points on functional units. These are the unit's interface to the outside world.
- **Nets**: Ideal electrical connections (zero impedance) linking two or more pins. Because a net has zero impedance, there are no potential differences within it -- this is why nets are synonymous with "nodes" or "potentials."
- **Ports**: External connection points of a circuit block that become pins when the block is instantiated at a higher level.
- **Instances**: Each occurrence of a device in the structural description. An instance references a device definition in the library (it is not literally copied).

#### Hierarchy

The structural description supports hierarchy through **subcircuits** (function blocks). When a subcircuit is used in a higher-level description, its ports become the pins of that higher-level instance. This hierarchy can be arbitrarily deep.

- The **top cell** is the highest level, representing the complete system circuit.
- Its ports connecting to the next system level (e.g., lead frame) are called **pads**.
- Subcircuits should be used whenever the same functionality recurs (e.g., multiple adders, registers, comparators), making the description easier to understand.

#### Device Types

**Analog IC devices** are the classical passive and active elements: resistors, capacitors, coils, diodes, transistors, thyristors, etc. A state-of-the-art mixed-signal process may offer several dozen to over a hundred different **subtypes** (e.g., implanted resistors vs. polysilicon resistors).

**Digital IC devices** are the elemental functional units for digital circuits -- logic gates and memory elements. These are pre-designed library cells, not newly developed during the design flow.

Each device instance is characterized by its **electrical parameters**: capacitance for a capacitor, channel length (L) and width (W) for a MOSFET, drive strength for logic gates (which corresponds to different transistor widths).

#### Complete Structural Description Contents

A complete structural description contains:
- A list of all devices and their properties:
  - Type (and subtype)
  - Instance designation (name)
  - Dimensions / electrical parameter settings
- A list of all nets and their assignment to device pins

For **PCBs**, the structural description lists externally sourced discrete components; their internal electrical properties do not affect the structural description.

### 3.1.2 Idealizations in Circuit Descriptions

#### Analog Circuits

Basic devices are treated as **lumped elements** -- their electrical properties are concentrated at a single point rather than physically distributed. This idealization enables Kirchhoff's laws:

- **Nodal rule (KCL)**: The sum of currents flowing into a node equals the sum flowing out.
- **Mesh rule (KVL)**: Voltages along any closed path in a network sum to zero.

These form the foundation of network theory and circuit simulation. Importantly, "lumped" does not mean "ideal" -- parasitic properties (ohmic losses in capacitors/coils) can still be modeled through equivalent circuits with ideal elements and controlled sources. Net parasitics are estimated or extracted from layout (see [[5.4 Physical Verification]]).

#### Digital Circuits

Digital devices are idealized even further. Beyond the Boolean function, the key characteristic is **propagation delay** -- the time between applying input signals and the appearance of output signals. Signal delays in nets receive special attention: first estimated during circuit design, then extracted from the layout during physical verification.

### 3.1.3 Circuit Representation: Netlist and Schematic

A structural description can be represented in two forms:

#### Netlists (Text Format)

Two types exist, distinguished by their sorting criterion:

**Pin-oriented netlist**: Sorted by functional units. Each device is listed once with its connected nets. Nets appear multiple times across device entries.

```
(NAND[1]: IN1 Net1, IN2 Net2, OUT Net3)
(NAND[2]: IN1 Net1, IN2 Net2, OUT Net4)
(NOR[1]:  IN1 Net3, IN2 Net4, OUT Net5)
```

**Net-oriented netlist**: Sorted by nets. Each net is listed once with all connected device pins. Devices appear multiple times.

```
(Net1: A, NAND[1].IN1, NAND[2].IN1)
(Net2: B, NAND[1].IN2, NAND[2].IN2)
(Net3: NAND[1].OUT, NOR[1].IN1)
```

Pin names must be unambiguously defined in the technology library for correct assignment. The syntax shown is similar to the EDIF (Electronic Design Interchange Format) standard.

#### SPICE Netlist Format

The SPICE format is pin-oriented. Each line contains:
- **Instance name** (prefixed by an identification letter)
- **Connected nets** (ordered by pin position, not named explicitly)
- **Device type**
- **Parameter settings** (W, L, M, etc.)

Identification letter conventions:
| Letter | Device Type |
|--------|-------------|
| M | MOSFET |
| C | Capacitor |
| Q | Bipolar junction transistor |
| R | Resistor |
| X | Subcircuit |

Example SPICE netlist for a bandgap circuit:
```spice
.SUBCKT bgap Ibias VDD VSS bg
QQ1 VSS VSS net05 vpnp M=1 EA=1.69
QQ0 VSS VSS net04 vpnp M=8 EA=1.69
XI0 Ibias VDD VSS net05 net01 net02 / moa
MPM1 bg net02 VDD VDD pmos W=8u L=4u M=2
RR2 net03 net05 45.05k polyhres W=2u L=255u
RR0 net01 net04 5.3k polyhres W=2u L=30u
.ENDS
```

Units use standard SI prefixes: k = kilo, u = micro, f = femto. The physical unit itself is implicit from the device type (ohm for resistors, farad for capacitors, meter for geometrical parameters like W and L).

#### Circuit Schematics (Graphical Format)

Schematics are pictorial representations where functional units appear as symbols and nets as connecting lines. They are indispensable for analog layout design because:

- Matching requirements and symmetry constraints are visually apparent
- Layout engineers must analyze the circuit in detail to select the right layout approach
- A netlist alone would make it nearly impossible to meet all analog design requirements
- Standard style rules (e.g., matched transistors arranged horizontally side by side) enable experienced layout engineers to immediately recognize critical design constraints

Subcircuits appear as symbols (e.g., a triangle for an opamp) with pins corresponding to the subcircuit's ports.

## 3.2 Layout Data: Layers and Polygons

### 3.2.1 Structure of Layout Data

Layout data are exclusively **vector images** (not raster). The reasons:

1. The vector data structure suits polygon-based layout representations very well
2. Vector data requires less memory than raster equivalents
3. Processing is faster and easier due to the structured information content
4. Shapes can be reshaped without loss of accuracy

The only disadvantage is the need to convert to raster for screen display, which modern tools handle efficiently.

#### Layers

Every shape in the layout is assigned to a unique **layer**. This layer attribute serves two purposes:
1. Enabling assignment to fabrication masks
2. Forming the basis for graphical linking operations

An important distinction exists between **drawn layers** (used in the data structure) and **fabricated layers** (actual layers on the wafer). These often correspond directly (e.g., "Nwell" drawn layer maps to the n-well fabricated layer, "Metal1" to a deposited metal). However:
- Some drawn layers have no direct fabricated counterpart (utility layers, marker layers)
- Some fabricated layers have no drawn layer (e.g., gate oxide is not modeled in layout data)

#### Shapes: Polygons

All shapes in layout data are **polygons** -- two-dimensional, continuous graphics elements bounded by straight edges. A polygon is stored as a list of successive corner coordinates, forming a closed polyline.

**General polygon**: Stored as corner coordinates C_i = (x_i, y_i). A manufacturing grid defines the smallest permissible resolution, allowing integer coordinate values and saving memory.

**Donuts** (polygons with holes): Modeled using "dual" edge sequences that run in two directions at the cut section. The superimposed edges do not form real polygon boundaries.

**Conics** (round boundaries): Cannot be precisely represented by polygons. Circles and arcs are approximated by many straight edge segments (the number is configurable, e.g., 8 edges for a circle).

**Rectangles**: The most common shape type. Since sides are almost always axis-aligned, a rectangle needs only two diagonally opposed corner coordinates -- roughly halving the data volume versus a general polygon representation.

**Paths**: Polylines with an assigned width w. Used for interconnects, providing constant cross-sectional area. Only the center-line coordinates and the width parameter are stored -- again approximately halving the data volume. Variations include "padded paths" for diagonal segments (to keep corners on-grid) and auto-extended endpoints.

**Edges**: Individual edge segments (C_i, C_{i+1}) are independently addressable in modern tools, enabling fine-grained layout editing operations.

#### Hierarchical Organization of Layout Data

The layout hierarchy mirrors the circuit's structural description:

- **Layout blocks (B)**: Correspond to function blocks / subcircuits. Each is a self-contained subset of the complete layout. Blocks can contain other blocks, cells, and net shapes.
- **Layout cells (C)**: Correspond to basic components (devices). Their shapes are assigned to FEOL layers, since devices are fabricated in the front-end-of-line.
- **Net shapes (n)**: The interconnect shapes in BEOL layers. These are "flat" data within a block -- they do not form their own hierarchy level.

The tree structure exists both conceptually and in the design environment's file organization (each block/schematic typically stored in a separate directory). Working at higher hierarchy levels simplifies physical design because the engineer can think in functional units rather than individual polygons, maintaining a "global view" of circuit topology.

### 3.2.2 How to Read a Layout View

Reading a layout means recognizing devices and their electrical connections from a 2D top-down view, and mentally constructing the 3D physical structure. The process, demonstrated on a CMOS inverter:

**Step 1 -- Identify active areas**: Find the "Active" layer, which defines regions without field oxide (STI). The STI mask is produced by negating this layer.

**Step 2 -- Find polysilicon crossings**: Wherever "Active" and "Poly" layers cross, there is a field-effect transistor channel. This is the most effective way to identify transistors, since FETs are by far the most common devices.

**Step 3 -- Distinguish NMOS from PMOS**: In a p-substrate process, PMOS transistors sit inside an "Nwell" drawn layer. Everything outside Nwell is NMOS territory (either in bare p-substrate for single-well, or in an explicit Pwell for twin-well processes). The Pwell may be derived by negating Nwell and thus may not appear as a separate drawn layer.

**Step 4 -- Identify doping**: The n+ and p+ implant layers (labeled "NSD" and "PSD" in the example) define source/drain regions. Their type follows logically from the transistor type.

**Step 5 -- Trace BEOL connections**: Contacts and vias appear as small, uniform squares. Metal features must always cover contacts/vias and form the interconnects above devices. The "Cont" layer provides contact holes, and "Metal1" forms the first metal interconnect layer.

In the CMOS inverter example, the layout uses:
- PMOS: W = 1.5 um, L = 180 nm (inside Nwell)
- NMOS: W = 600 nm, L = 180 nm (outside Nwell)
- Bulk contacts for both transistors define well/substrate potentials
- Metal1 interconnects to form the inverter circuit

### 3.2.3 Graphics Operations

#### Interactive Shape Editing

Standard commands: Add, Delete, Move, Copy/Paste, Flip, Rotate.

Layout-specific commands:
- **Stretch**: Shift a subset of edges or corners
- **Notch**: Cut out, truncate, or attach rectangles/complex polygons
- **Merge**: Combine overlapping shapes into one
- **Split**: Divide polygons along intersecting lines

#### Logical Linking of Layers (Boolean Operations)

Boolean operators "logically link" shapes across different layers. They are critical for DRC and layout post-processing (mask data generation):

| Operator | Result |
|----------|--------|
| **OR** | Geometrical union of two layers |
| **AND** | Geometrical intersection of two layers |
| **XOR** | Union minus the intersection |
| **ANDNOT** | "Geometrical difference" -- everything in the second layer is punched out of the first |

These operations write results into a new layer.

#### Select Operations

Select commands identify (but do not create) shapes meeting spatial criteria between two layers:

| Operator | Selects shapes in layer A that... |
|----------|-----------------------------------|
| **INCLUDE** | Overlap in any way with shapes in layer B |
| **OUTSIDE** | Do not overlap with shapes in layer B |
| **INSIDE** | Are fully covered by shapes in layer B |
| **ENCLOSE** | Fully cover shapes in layer B |
| **CUT** | Partially (but not fully) overlap with shapes in layer B |

These are especially useful for DRC, where specific layer subsets must be identified for checking.

#### Sizing Operators

The sizing operator shifts all edges of a polygon perpendicular to their alignment by a value s:
- **Oversizing** (positive s): Polygon grows
- **Undersizing** (negative s): Polygon shrinks

Important properties and pitfalls:

**Uneven growth**: Corners shift by v * s where v > 1. For right angles, v = sqrt(2). For acute angles, v can be much larger. This is a generic defect -- ideally corners would trace circular arcs. Some tools offer **beveling** (adding extra edges at corners) to approximate the arc.

**Rounding errors**: When edges are inclined, sized corners may not land on the manufacturing grid. Integer rounding can alter angles relative to the coordinate system, potentially causing DRC violations.

**Irreversibility**: Performing undersize then oversize (or vice versa) with the same absolute value does NOT always return the original shape:
- Small polygons and narrow ribs disappear during undersizing and cannot be recovered
- Small holes in polygons disappear during oversizing and cannot be recovered
- Rounding errors accumulate and cause permanent shape changes

**Positive use of irreversibility**: The disappearance of small features during sizing can be exploited to "clean up" layouts -- eliminating small artifacts created by sequences of sizing and Boolean operations in DRC or layout post-processing.

## Connections to the Bigger Picture

Sections 3.1 and 3.2 establish the fundamental data representations that bookend the physical design process: circuit data as input, layout data as output. The structural description concepts (hierarchy, nets, instances, pins) carry directly through to physical design tools and are the vocabulary used in placement, routing, and verification. Understanding layout data structure -- layers, polygons, and their manipulation through Boolean and sizing operations -- is prerequisite for everything that follows: [[3.3 Mask Data]] (layout post-processing to generate fabrication-ready data), [[3.4 Geometrical Design Rules]] (the constraints that govern valid layouts, checked using exactly these Boolean and select operations), and [[3.5 Libraries]] (where pre-designed cells and their abstractions are stored). The ability to "read" a layout view, mentally mapping 2D polygons to 3D silicon structures, is the core skill that connects the fabrication process knowledge from [[2.9 CMOS Standard Process]] to the practical work of layout design.
